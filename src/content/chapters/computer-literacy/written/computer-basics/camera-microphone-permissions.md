카메라·마이크 권한은 **장치 전체 접근, 앱 접근, 데스크톱 앱 접근, 웹사이트 권한**을 나누어 확인하며 Windows의 한 토글이 모든 프로그램·사이트를 개별 통제한다고 보면 안 됨

## Windows의 장치 접근과 앱 접근

현재 Windows 11에서는 카메라·마이크에 대해 다음처럼 여러 단계의 접근 조건이 존재함

- 장치의 카메라·마이크 접근
- 앱이 카메라·마이크에 접근할 수 있는지
- 지원되는 Microsoft Store 앱의 개별 접근
- 데스크톱 앱 접근

따라서 카메라 자체 접근이 꺼져 있으면 일반 앱의 사용에도 영향을 줄 수 있고, 장치 접근이 켜져 있어도 앱에 필요한 권한이 추가로 필요할 수 있음

## 데스크톱 앱은 개별 토글과 다름

인터넷에서 설치한 프로그램·브라우저 같은 데스크톱 앱은 Microsoft Store 앱처럼 **각 프로그램을 항상 개별 토글로 제어할 수 있는 구조가 아님**

현재 Windows에서는 `데스크톱 앱이 카메라/마이크에 액세스하도록 허용` 같은 묶음 설정으로 제어하는 범위가 있음

일부 데스크톱 앱은 Windows의 개인정보 설정만으로 접근을 완전히 차단할 수 없는 경우도 있으므로

**앱 목록에 안 보임 = 절대 접근 불가**

라고 판단하지 않음

## 웹사이트는 브라우저 권한이 별도로 필요

Windows에서 브라우저가 카메라·마이크를 사용할 수 있게 되어 있어도 웹사이트가 바로 사용할 수 있는 것은 아님

예를 들어 Microsoft Edge에서는 사이트가 카메라·마이크 사용을 요청할 때 해당 **웹사이트의 권한도 별도로 허용**해야 함

따라서 대표 상황

`브라우저의 카메라 사용을 Windows에서 허용함 → 모든 웹사이트가 바로 카메라 사용`

은 틀린 판단임

## Windows Hello 예외

Windows Hello 얼굴 로그인을 사용하는 경우에는 앱의 카메라 접근 허용 설정과 별개로 로그인 과정에서 카메라를 사용할 수 있는 예외가 있음

따라서

**앱 카메라 접근 OFF = Windows Hello도 반드시 카메라 사용 불가**

로 일반화하지 않음

## 판단 순서

1. 장치 카메라·마이크 접근 확인
2. 앱 접근 허용 확인
3. Store 앱인지 데스크톱 앱인지 확인
4. 브라우저라면 웹사이트 권한까지 확인
5. Windows Hello 같은 예외 여부 확인

## 학습 예시

Windows에서 브라우저의 카메라 접근을 허용했는데 화상회의 사이트가 카메라를 쓰지 못한다면 **해당 웹사이트의 카메라 권한도 확인**

실제 기출이 아닌 권한 점검 예시

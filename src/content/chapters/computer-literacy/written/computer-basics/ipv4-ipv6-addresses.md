IPv4와 IPv6는 **주소 길이·표기 방식·전송 대상 유형**을 비교하고, IPv6의 `128비트·콜론·16진수·선행 0 생략` 단서를 정확히 읽으면 됨

## IPv4

대표적인 IPv4 주소 표현

`192.0.2.10`

핵심

- 32비트 주소
- 8비트씩 4부분
- 보통 10진수로 표시
- 마침표 `.`로 구분

과거의 A~E 클래스 분류는 IPv4의 전통적인 classful addressing과 관련된 개념임

IPv6를 A~E 클래스로 구분하지 않음

## IPv6

RFC 4291 기준 IPv6 주소는 **128비트**임

일반적인 텍스트 표현은

- 16비트씩 8개 블록
- 각 블록은 16진수
- 콜론 `:`으로 구분

임

따라서

`세미콜론(;)으로 구분`

은 틀림

## 선행 0 생략

각 16비트 블록의 앞쪽 0은 생략 가능함

예

`0db8` → `db8`

현재 표준의 권장 표기인 RFC 5952에서는 선행 0을 생략하도록 규정함

연속된 0 블록은 `::`로 압축할 수도 있으나 한 주소에서 `::`는 한 번만 사용함

## IPv6의 전송 대상 유형

IPv6 주소 유형

- 유니캐스트
- 애니캐스트
- 멀티캐스트

IPv6에는 IPv4의 일반 브로드캐스트 주소 방식이 없고 그 기능은 멀티캐스트가 담당함

## IPv6를 만든 주요 이유

IPv4 주소 공간 부족 문제를 해결하기 위해 훨씬 큰 128비트 주소 공간을 사용함

따라서 `IPv4 주소 부족 문제 해결`은 연결 기출의 명확한 정답 근거임

## IPv4와 IPv6의 호환성 표현 주의

2015년 기출의 ④는

`IPv6는 IPv4와의 호환성이 뛰어나고 ... 보안문제를 해결할 수 있다`

라는 표현을 맞는 선택지로 취급함

하지만 현재 표준 관점에서 IPv4와 IPv6는 **서로 다른 프로토콜이며 그대로 직접 호환되는 구조가 아님**

공존·전환을 위해

- dual stack
- tunneling
- translation

같은 전환 기술을 사용할 수 있음

따라서 과거 시험 문구를 근거로

**IPv6 장치는 아무 설정 없이 IPv4와 직접 완전 호환**

이라고 외우지 않음

## IPv6가 보안 문제를 자동 해결하는가

아님

IPv6 환경에도 별도의 보안 위협과 전환 과정의 보안 문제가 존재함

따라서

**IPv6 사용 = 보안 문제 자동 해결**

로 일반화하지 않음

2015년 문항의 저장 정답 ①은 그대로 유지하되 ④의 표현은 **당시 시험 교육 문맥**으로만 취급함

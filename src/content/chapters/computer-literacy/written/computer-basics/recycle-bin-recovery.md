## 로컬 드라이브와 휴지통

과거 기출에서는 로컬 하드 디스크 드라이브에서 삭제한 파일을 휴지통에 임시 보관하고 복원할 수 있는 구조로 출제됨

휴지통 아이콘은 하나처럼 보이지만 삭제된 항목은 원래 드라이브와 연결된 휴지통 저장 영역에서 관리됨

따라서 연결 기출에서는

`하드 디스크 드라이브마다 휴지통을 둘 수 있다`

는 설명을 맞는 선택지로 채점함

## USB·네트워크 드라이브 삭제

연결된 2020 기출에서는

- USB 메모리에서 Delete로 삭제
- 네트워크 드라이브에서 삭제

한 파일은 일반 로컬 휴지통 복원 대상으로 보지 않음

따라서

**삭제 위치가 로컬 드라이브인지 외부·네트워크 위치인지**

를 먼저 확인함

## Shift + Delete

현재 Windows에서도

**Shift + Delete → 휴지통을 거치지 않고 영구 삭제**

로 안내됨

따라서 복원 가능 여부 문제에서는 Shift 키 조합을 반드시 확인함

## 휴지통 최대 크기

휴지통에 설정된 용량 조건에 따라 삭제된 항목이 휴지통에 들어가지 않을 수 있음

연결 기출의

`지정된 휴지통 용량을 초과하면 새로 삭제된 모든 파일·폴더가 보관되지 않는다`

라는 문장은 너무 단정적이므로 틀린 선택지로 처리됨

시험에서는 **파일 크기·휴지통 설정에 따라 결과가 달라질 수 있음**을 기억함

## 휴지통 안에서 할 수 있는 작업

휴지통에 있는 파일은 복원·영구 삭제 등의 관리 대상으로 다룸

연결 기출에서는

- 휴지통 안의 파일 이름을 자유롭게 변경
- 휴지통 안에서 원본 파일을 직접 실행

하는 기능으로 설명한 선택지를 틀린 것으로 봄

## 복원 가능한 대표 기출 상황

`바탕 화면의 파일을 휴지통으로 드래그해 삭제`

→ 로컬 파일을 휴지통에 보관한 경우이므로 복원 가능

반면

- USB 파일 Delete
- 네트워크 드라이브 파일 삭제
- 휴지통 최대 크기 0MB 설정 후 삭제

는 연결 기출에서 복원 가능 사례가 아님

휴지통의 파일을 비우면 저장 공간 확보 가능 · RAM 용량이 늘어나는 것은 아님

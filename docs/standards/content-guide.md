## 1. 반드시 지킬 8가지

1. **결론부터 작성:** 첫 화면에서 글의 대상과 얻을 답을 알 수 있게 함. 배경 설명으로 시작하지 않음
2. **독자 기준으로 선별:** 읽은 뒤 문제를 풀거나 자격·선임·업무 조건을 판단하는 데 필요한 정보만 남김
3. **불필요한 안내 삭제:** 추임새, 자기소개, ‘알아보겠습니다’식 도입, 반복 요약, 의미 없는 연결문을 지움
4. **검증 가능한 사실만:** 실제 기출·선택지·공식 자료·시점별 기준을 확인. 추정값과 AI 생성 설명을 근거로 사용하지 않음
5. **결론을 바꾸는 조건 보존:** 단위·시행일·기준 연도·예외·적용 대상·버전은 생략하지 않음
6. **하나의 정보는 적합한 형식으로 한 번:** 본문·표·그림·배지에 같은 설명을 되풀이하지 않음
7. **문장보다 판단이 중요:** 짧아도 모호하면 다시 씀. 충분한 조건이 없으면 과도하게 줄이지 않음
8. **식별자와 공개 연결 유지:** 기존 URL, slug, subject_id, question_id, 연결 기출·정답을 근거 없이 변경하지 않음

## 2. 무엇을 남기고 무엇을 지울 것인가

작성·검수 중 **문장, 소제목, 표, 그림마다** 아래 질문을 적용함.

> 이 정보를 없애면 독자가 **어느 문제를 잘못 판단하거나, 어떤 조건을 놓치는가?**

| 판정 | 처리 기준 | 예시 |
| --- | --- | --- |
| **유지** | 용어 정의, 문제 단서, 정답·오답 판단, 수치·조건·실제 행동에 필요 | ‘압입통풍은 FD 송풍기로 공기를 연소실 쪽에 공급’ |
| **축약** | 근거가 있으나 한 문장으로 충분, 서술이 길거나 같은 설명 반복 | 3문단의 개념 설명 → 정확한 정의 1문단 |
| **통합** | 표·그림·본문에서 같은 정보를 여러 번 설명 | 그림의 기기 위치는 그림에, 판별 기준은 본문에 한 번 |
| **삭제** | 독자 판단에 기여하지 않는 추임새·장식·형식적 요약 | ‘오늘은 이 개념을 자세히 알아보겠습니다’ |
| **보류** | 사실·법령·정답 근거가 부족하거나 적용 시점이 불명확 | 출처 없는 ‘매년 출제’, 근거 없는 선임 가능 주장 |

**삭제하지 말아야 하는 것:** 정답을 바꾸는 전제, 법적 예외·시행일, 안전에 필요한 경고, 명확한 오답 구별, 단계형 문제의 필수 순서. 지워서 오해가 생기면 더 짧게 다시 설명함.

### 2-1. 추임새·불필요한 안내의 구체적 판정

| 삭제·개선 대상 | 피할 문장 | 권장 처리 |
| --- | --- | --- |
| 형식적 도입 | ‘이번 시간에는 보일러 구조를 알아보겠습니다’ | 삭제하고 ‘보일러 구조’ 제목 다음 바로 핵심 설명 |
| 말 걸기·감탄 | ‘자, 이제 하나씩 살펴볼까요?’, ‘생각보다 간단하죠?’ | 삭제 |
| 목적 없는 중요성 강조 | ‘이 내용은 꼭 기억해야 합니다’, ‘매우 중요합니다’ | 중요성의 **근거가 되는 조건** 또는 판단 규칙으로 교체 |
| 독자에게 가치를 주지 않는 안내 | ‘아래 표를 참고해 주세요’, ‘그림을 보면 알 수 있습니다’ | 표/그림 제목이 기능을 설명하면 삭제. 필요한 해석 단서만 남김 |
| 중복된 연결 | ‘앞에서 설명한 내용을 다시 정리하면’ | 실제 새 판단이 없으면 삭제 |
| 관행적 마무리 | ‘이상으로 알아보았습니다’, ‘시험 준비에 도움이 되길 바랍니다’ | 삭제. 다음 기출·관련 챕터 링크가 있으면 기능으로 연결 |
| 근거 없는 예측 | ‘반드시 나오는 문제’, ‘합격의 지름길’ | 확인 가능한 범위·출처가 없으면 삭제 |
| 독자 탓·의미 없는 지시 | ‘잘 이해하셨나요?’, ‘꼭 외워야 합니다’ | 필요한 암기 항목·조건을 구체적으로 제시하거나 삭제 |

‘예를 들어’, ‘주의’, ‘참고’라는 말 자체를 금지하지는 않음. **실제 계산·구별·안전 판단에 필요할 때만** 사용. 웹 UI에서 이미 명확한 조작 설명은 본문으로 되풀이하지 않음.

### 2-2. 정보 밀도와 문장 기준

- 한 문장에 독립된 판단을 여러 개 억지로 합치지 않음. 조건마다 줄을 나눔
- ‘A·B’로 **그리고/또는**의 의미를 숨기지 않음. 동시 조건은 ‘및’, 선택 조건은 ‘또는’으로 명시
- 제목은 사용자가 찾는 용어·조건으로 작성. ‘대표 판단 단서’ 등 추상적 소제목 지양
- 본문 길이·문단 개수·표 개수를 목표로 잡지 않음. 독자 질문에 답했다면 종료
- 원문 인용·기출·공식·수치·단위는 압축을 이유로 변경하지 않음

## 3. 콘텐츠 종류별 필수 구성

**형식은 출발점이며 모든 글에 같은 섹션을 강제하지 않음.**

| 종류 | 독자가 가장 먼저 볼 내용 | 충분한 설명의 기준 |
| --- | --- | --- |
| 기출 연결 챕터 | 한 줄 개념 및 정답 판단에 필요한 단서 | 모든 주 기출에서 문제 단서 → 본문 적용 → 정답·주요 오답 판단 가능 |
| 계산형 | 공식, 단위, 주어진 값, 대입 순서 | 계산값 검산 가능. 답을 바꾸는 단위·가정 표기 |
| 설정형·화면형 | 대상 화면/셀·메뉴, 설정할 값 | 사용자가 입력값과 결과값을 혼동하지 않음 |
| 비교·구별형 | 공통 비교 기준과 가장 중요한 차이 | 선택지 구별에 필요한 차이만 남김 |
| 시설관리 자격·선임 정보 *(향후 유형)* | ‘누가, 어떤 조건에서 가능한가’에 대한 결론 | 법정 요건·취업 우대·실무 관행을 분리하고 기준일 표시 |
| 시설관리 채용·실무 정보 *(향후 유형)* | 확인 가능한 사실과 대상 독자의 판단 | 채용공고·기관·기준일을 제시하고 공고별 예외 표시 |

시설관리 콘텐츠는 **향후 집필 표준 제안**이며, 해당 서비스가 현재 main에 구현됐음을 뜻하지 않음.

### 3-1. 자격증 챕터 집필 순서

1. 주 기출 원문·선택지·정답·그림 확인. 없으면 ‘미제공’ 또는 ‘미확인’ 표기
2. 문제별로 어떤 단서가 정답·오답을 나누는지 기록
3. 여러 문제에 공통으로 필요한 **최소 개념** 추출
4. 한 줄 핵심 → 적용 예시 → 필요한 오답 구별 → 연결 기출 순서로 초안 작성
5. 계산·설정·비교에 필요한 그림/표 선택. 독자 판단을 돕지 않으면 추가하지 않음
6. 각 문항에 다시 적용해 **선택지별 판단 근거** 확인
7. 추임새·중복·과도한 예외를 제거한 뒤 조건 누락 여부 재검토

주 기출이 없는 기초 챕터는 후속 문제 이해에 필요한 이유를 기록하면 유지할 수 있음. 연결 문제 수가 적다고 자동 삭제하지 않음. 인접 챕터의 설명 범위와 기출 배정은 임의로 바꾸지 않음.

### 3-2. 시설관리 정보 콘텐츠 집필 순서

1. 독자의 질문을 한 문장으로 정함: 예) ‘이 자격으로 어느 시설의 어떤 선임이 가능한가?’
2. 결론을 조건부로 표시: 가능/불가/추가 조건 필요/확인 불가
3. 법적 선임 요건, 경력·교육 요건, 채용 공고상 우대 요건을 구분
4. 공식 근거, 적용 대상·설비 용량·시행 시점 등 **판단을 바꾸는 조건**만 정리
5. 이해에 필요한 비교표, 예외와 확인 방법 제시
6. 근거가 확실하지 않은 시설 사례나 일반화 표현 삭제

**법령과 공고는 별개:** ‘채용 우대 자격’이 곧 ‘법정 선임 가능’이라는 뜻이 아님. 서로 다른 제도의 기준을 합쳐 단정하지 않음.

## 4. 표·그림·링크 사용 기준

- **표:** 2개 이상의 대상을 같은 기준으로 비교하거나 여러 조건을 한눈에 확인할 때 사용
- **목록:** 순서·요건을 분리해야 읽기 쉬울 때 사용. 서로 다른 요건은 표 셀 안에서도 줄바꿈
- **그림:** 구조·위치·연결·흐름·화면 대응을 설명할 때. 장식용이면 넣지 않음
- **캡션:** 그림 대상·상태를 짧게 설명. 이미지 내부에 같은 제목·문장 반복 금지
- **링크:** ‘관련 기출’ 또는 ‘관련 챕터’ 등 목적을 표시. 단순 페이지 수 증가를 위한 링크 배치 금지
- **모바일:** 390px에서 필수 정보 판독 가능해야 함. 320px·PC 확인 필요. 가로 스크롤이 있는 표는 내용이 잘리지 않고 조작 가능한지 점검
- **학습 이미지:** 도식의 정확성이 장식보다 우선. 이미지 원본/파생본과 alt·확대는 별도 정본 적용

## 5. 출처·정확성·표현의 경계

| 출처·상태 | 작성 기준 |
| --- | --- |
| 기출 원본/PDF | 문제·선택지·정답·그림의 우선 근거. JSON과 충돌하면 원본 확인 |
| 공식 출제기준 | 대상 자격·시험 종류·적용 시점 기록. 범위 포함만으로 빈출 주장 금지 |
| 법령·고시·기관 안내 | 현행 시행일과 과거 기출 당시 기준 구분. 바뀔 수 있는 수치는 확인 시점 표기 |
| 제조사·기술 자료 | 장치 구조·배관 경로 등을 보조 검증. 도식 생성 결과 자체를 증거로 쓰지 않음 |
| 채용 공고 | 기관·공고일·지역·고용형태 등 범위를 밝혀 사례를 일반화하지 않음 |
| AI 작성 내용 | 초안일 뿐. 실제 원본 확인·검산·테스트 수행 여부와 구분 |
| 확인 불가 | 임의로 채우지 말고 미확인·추가 검토 대상으로 분리 |

‘빈출·최빈출·매년 출제’는 확인한 모집단과 집계 방식이 있을 때만 사용. **사이트에 수록된 문항 수와 전체 출제 횟수는 다름.**

## 6. 집필·편집 담당자 체크리스트

### 작성 시작 전
- [ ] 독자의 질문과 이 글을 읽고 할 수 있어야 할 판단을 한 줄로 적었는가
- [ ] 주 근거·문항·적용 시점·인접 챕터 범위를 확인했는가
- [ ] 미제공·미확인 자료를 분리했는가

### 초안 완료 후
- [ ] 결론이 첫 화면에 있는가. 본문을 읽어야만 제목의 뜻을 알 수 있지는 않은가
- [ ] 추임새, 의례적 인사, 말 걸기, 형식적인 도입·마무리를 삭제했는가
- [ ] ‘중요’, ‘참고’, ‘확인’ 안내를 구체적인 조건·판단으로 바꿨는가
- [ ] 각 문장·표·그림의 독자 효용을 설명할 수 있는가
- [ ] 조건·숫자·단위·원문·오답 판단이 압축 과정에서 사라지지 않았는가
- [ ] 같은 내용을 두 군데 이상 반복하지 않는가
- [ ] 모바일에서 제목·본문·표·그림·기출 연결이 읽히는가

### 검수 기록
- [ ] 확인한 원본과 실제로 수행한 검증을 기록했는가
- [ ] 기출 적용 검토는 문항별로 단서·정답·오답 근거까지 확인했는가
- [ ] 제작/Build/배포/Production 상태를 각각 구분했는가

## 8. 토스피드 비교 기반 콘텐츠 구성 (v1.2)

### 8-1. 가져올 것과 그대로 옮기지 않을 것

토스피드의 금융 정보 아티클에서는 제목·게시일·작성자·목차성 소제목·자격/조건·예외를 구분해 안내하는 사례를 확인할 수 있음. 카테고리 화면에는 추천 아티클과 주제별 목록이 별도로 있음.

**GetPassLab의 적용 결정:** 독자가 찾는 답에 빨리 접근하도록, **검색 질문과 연결되는 제목 → 결론 → 판단 조건 → 필요한 예외**로 구성하되 출처와 기준일을 분명히 함. 토스피드의 인터뷰·에세이식 장문 서사나 감성 문체를 기술자격 학습 본문에 그대로 적용하지 않음.

| 콘텐츠 유형 | 첫 화면에서 알려야 할 것 | 본문에 포함할 것 | 생략할 것 |
| --- | --- | --- | --- |
| 시설관리 제도/법령 정보 *(향후)* | 무엇이 가능한지와 적용 대상 | 공식 근거, 시행일, 자격·설비 규모·예외, 확인 방법 | 도입 인사, 개인 경험을 보편적 선임 기준으로 일반화하는 서술 |
| 시설관리 취업·현장 정보 *(향후)* | 대상 직무/기관 및 핵심 조건 | 공고일, 고용형태, 필수 요건/우대사항, 표·사례 | ‘무조건 유리’, ‘꼭 가야 할 곳’ 등 근거 없는 추천 |
| 자격증 개념 챕터 *(현행)* | 시험에서 무엇을 구별해야 하는지 | 단서, 개념, 계산/그림, 오답 근거, 연결 기출 | 토스피드형 스토리 도입·에세이·과도한 주제 추천 |
| 자격증 목록 *(현행)* | 선택 가능한 자격과 과목 | 공개된 실제 챕터 수·학습 범위·연결 문제 | 존재하지 않는 콘텐츠를 ‘모두 제공’으로 홍보 |

### 8-2. 독자 중심 편집을 세 단계로 확인

토스의 공식 라이팅 시스템은 **문장 안 불필요한 단어 제거 → 화면 안 빈 문장 제거 → 여러 화면에서 핵심 메시지에 집중**을 별도로 설명함. 이를 GetPassLab의 집필 QA에 맞게 다음 세 단계로 변환.

1. **문장:** '이번에는', '매우', '꼭', '함께 알아보겠습니다'처럼 빼도 판단이 달라지지 않는 단어·추임새 삭제
2. **하나의 절·화면:** 제목·설명·표·이미지 캡션에 동일한 개념을 중복했는지 확인. 그림에 직접 필요한 기술 라벨과 공식 조건은 삭제하지 않음
3. **페이지 사이:** 목록 카드·챕터·연결 기출·관련 글에 같은 소개를 되풀이하지 않음. 목록은 **내용을 선택할 정보**, 상세는 **판단과 적용에 필요한 근거**를 담당

**실제 검수 질문:** '이 단어/문장/페이지 설명을 없애면 독자가 어느 판단을 잘못하는가?' 답할 수 없다면 삭제·축약. 단, 법적 자격 요건과 수치·예외는 간결성을 이유로 숨기지 않음.

### 8-3. 시설관리 아티클 권장 템플릿 — 향후 집필 기준

```text
H1: 독자가 검색하는 질문 또는 정확한 주제명
상단: 결론 1~2문장(적용 대상/조건 포함)
정보: 기준일, 검증된 기관·공식 근거, 변경 가능 여부
H2: 누가 해당되는가 — 필수 요건과 예외
H2: 실제 판단·선임·채용에서 어떻게 적용되는가 — 비교표/사례
H2: 혼동하기 쉬운 기준 — 우대사항 vs 법정 의무, 과거 vs 현행 등
마무리: 공식 확인 경로 / 필요한 관련 자료
```

- 모든 글에 위 H2를 강제하지 않음. 질문·정보량에 맞게 조합
- **저자/읽기 시간/업데이트일 등 메타는 실제 확인할 수 있을 때만 표시**
- 기준일이 오래됐으면 '현재'라고 단정하지 않고 적용 시점을 재확인
- 새 법령·선임 가능 범위를 추정해 추가하지 않음. 출처가 없는 곳은 편집 메모로 이동

### 8-4. 자격증에는 기존 문제 중심 구조 유지

- 토스피드의 추천 콘텐츠 방식은 **홈의 학습 주제 추천**에 참고 가능하나, 빈도·우선순위를 추정해서는 안 됨
- 챕터는 [전체 챕터 작성 정본](../../CHAPTER_WRITING_GUIDE.md)의 `한 줄 개념 → 예시 → 오답 구별 → 연결 기출`을 우선
- 학습 도식·문제 팝업·기출 출처 및 관련 문제는 기사형 아티클에 맞추려고 재배치·삭제하지 않음
- 챕터와 시설관리 아티클을 같은 제목 길이·같은 단락 수·같은 읽기 시간으로 맞추지 않음

### 8-5. 다음 편집 작업의 추가 완료 기준

- [ ] 첫 화면의 제목·첫 문장만으로 누가 무엇을 판단할 수 있는지 알 수 있음
- [ ] 문장·절·페이지 사이 중복을 각각 확인했음
- [ ] 시설관리 콘텐츠의 실제 근거·기준일·법적 의무/공고 우대가 구분됐음
- [ ] 자격증은 기존 연결 문제마다 정답·주요 오답 판단 가능성을 유지함
- [ ] 복잡한 주제라도 중요한 조건을 삭제해 글만 짧아지지 않았음

## 9. 토스피드 기사 유형 재검증과 집필 보완 (v1.3)

**근거 문서:** [토스피드 비교 재검증 기록](../audits/2026-10-29-tossfeed-reference-revalidation.md)

### 확인 사실과 적용 범위

- **정보형 아티클 실제 사례:** 제목·게시일·필진·읽기시간·소제목 목록 아래에 가입 대상, 조건, 수령액, 신청, 예외를 분리한 구조가 있음. 시설관리의 선임/법령/채용 조건 설명에 **구성 원칙만** 참고
- **스토리형 아티클 실제 사례:** 긴 이야기와 시리즈·이미지·공유·댓글이 함께 있음. 토스피드 전체를 '짧고 결론부터 쓰는 글'로 일반화할 수 없음
- **카테고리 목록:** 추천 아티클·주제 분류·날짜·페이지 구분이 있음. 자격증의 문제 수와 출제 빈도 대신 기사 조회 수·인기 순위를 추정하지 않음

### 독자 목적별 구분 — 신규 집필 시 의사결정

| 독자가 필요한 것 | 선택할 구조 | 넣지 말아야 할 것 |
| --- | --- | --- |
| 문제를 풀 수 있는 개념 | 핵심 조건 → 이해/적용 → 오답 기준 → 연결 기출 | 일상 서사·기사형 도입·과장된 성공 약속 |
| 법정 선임 가능 여부 | 결론(적용 범위) → 자격/경력/시설 조건 → 예외·기준일 → 공식 확인처 | 법령과 채용 우대의 혼동, 임의의 예외 |
| 채용 공고의 지원 여부 | 채용 대상·기간 → 필수 요건·우대 → 급여/형태(근거 있는 경우) → 확인 경로 | 기관 전체 평균을 공고 급여로 단정 |
| 시설 현장 실무 이해 | 목적·안전조건 → 구성·절차 → 예외·오류 신호 → 확인할 원문 | 출처 없는 관행 일반화·위험한 생략 |

### 반복 콘텐츠의 책임 분리

- **목록 카드:** 선택할 이유만 제공. 해당 글의 실질 요건·출처는 상세로
- **상세 본문:** 주제의 결론·근거·조건·예외 제공. 목록의 추상적 홍보 문구를 반복하지 않음
- **관련 글:** 질문이 이어질 때만 연결. SEO 목적으로 의미 없는 관련 링크 추가 금지
- **주의 절:** 실제 독자의 판단을 바꾸는 조건을 설명할 때만 사용. 토스피드에 '꼭 확인하세요'가 있다는 이유로 모든 글에 추가하지 않음

**완료 기준:** 현재 글의 본문과 연결된 원본/법령/기출에서 조건·수치·근거를 다시 확인할 수 있어야 함. 정보형 글의 단락 수·메타 항목을 외부 사이트와 맞추는 것이 목표가 아님.

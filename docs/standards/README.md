# GetPassLab 운영 가이드 — 시작하기

- 버전: **v1.1 / 2026-10-29**
- 목적: 운영자가 알아야 할 **결정 기준을 앞에**, 실제 작업에 필요한 **세부 적용·검수 기준을 뒤에**, 변경 이유는 **각 문서 부록**에 배치
- 적용 범위: 현재 GetPassLab `main`의 코드·기존 학습 콘텐츠와 향후 서비스 확장 시의 작업 기준
- 상태: **PR 검토용 운영 문서**. 기능 변경·배포 완료를 뜻하지 않음

## 가장 먼저 숙지할 6가지

1. **독자의 질문에 바로 답한다.** 목적 없는 서론·추임새·중복 안내를 삭제
2. **내용이 사실인지 확인한다.** 기출 원문, 법령 적용 시점, 수치·단위·선임 요건은 출처와 함께 검증
3. **필요한 내용은 충분히 쓴다.** 요약하려다 정답·선임·안전 판단을 바꾸는 조건을 삭제하지 않음
4. **디자인은 기존 시스템을 재사용한다.** 토큰·컴포넌트·기술 도식 정본을 먼저 확인
5. **사용자 동작이 명확해야 한다.** 버튼·상태·닫기·채점·모바일 탐색의 의미를 일관되게
6. **확인한 결과만 완료로 기록한다.** 집필·수정·테스트·빌드·배포·Production을 구분

## 어떤 문서를 읽어야 하는가

| 할 작업 | 먼저 읽을 문서 | 알아야 할 부분 |
| --- | --- | --- |
| 자격증 챕터 집필·수정 | [콘텐츠](content-guide.md) → [전체 챕터 정본](../../CHAPTER_WRITING_GUIDE.md) | 독자 효용·추임새 삭제·기출 판단·정확성 |
| 시설관리 정보 글 작성 *(향후)* | [콘텐츠](content-guide.md) → [카피라이팅](copywriting-guide.md) | 결론·적용 조건·법정 선임/채용 우대 구별 |
| 제목·설명·배지·버튼 문구 수정 | [카피라이팅](copywriting-guide.md) | 문구 공식·과장 금지·행동 일치 |
| 색상·글꼴·카드·레이아웃 변경 | [디자인](site-design-guide.md) → 실제 CSS | 토큰·위계·컴포넌트 재사용 |
| 학습 이미지 신규·수정 | [학습 이미지 정본](learning-image-design-system-v1.md) → [디자인](site-design-guide.md) | 검증 근거·구조 정확성·캡션 역할 |
| 챕터 탐색·팝업·모의고사 개선 | [UX/UI](ux-ui-guide.md) → [카피라이팅](copywriting-guide.md) | 단계·선택·채점·닫기·모바일 QA |
| GitHub·배포·회귀 검수 | [AGENTS.md](../../AGENTS.md) + 해당 작업의 가이드 | 기존 보호 대상·배포 승인·증거 |

**모든 문서를 매번 처음부터 읽을 필요 없음.** 해당 작업의 가이드에서 1장(필수 규칙)과 적용·완료 기준을 확인. 필요한 경우 중간의 예시·세부 규격을 참조. 과거 결정 경위가 필요할 때만 부록 확인.

## 가이드 간 역할·우선순위

| 영역 | 정본·근거 | 이 문서에서 하지 않는 것 |
| --- | --- | --- |
| 프로젝트 실행·배포 | `AGENTS.md` | 배포 승인 규칙을 별도로 변경하지 않음 |
| 기출·자격증 집필 | `CHAPTER_WRITING_GUIDE.md` | 기출 원문·문항 ID·기존 챕터 범위 변경하지 않음 |
| 학습 이미지 기술 도식 | `learning-image-design-system-v1.md` (본문 버전 v1.3) | 이미지 색상·기호를 새로 임의 정의하지 않음 |
| 사이트 스타일·구현 | 실제 `src/styles/global.css` 및 컴포넌트 | 문서 수치만으로 Production 구현을 주장하지 않음 |
| 공통 편집·UX 결정 | 이 디렉터리의 네 가지 가이드 | 다른 정본과 중복하여 새 규칙을 만들지 않음 |

문서와 코드가 다르면 **현재 구현 상태는 코드로**, 새로 적용할 기준은 **해당 영역의 정본과 승인된 설계로** 판단. 충돌은 조정 후 단일 문서에 기록하고 다른 문서는 링크로 참조.

## 다음 작업 요청 시 최소 기록

```text
작업 목적 / 대상 페이지:
독자 또는 사용자의 해결할 문제:
적용한 가이드와 기준:
변경/유지 대상:
확인한 자료·버전·근거:
수행한 검증 / 미수행 검증:
변경 이력에 남길 결정 이유:
```

**시설의 모든 것 / 자격증의 모든 것** 서비스 분리 및 토스피드 참고 스타일은 별도 추진 과제. 코드 반영과 Production 확인 전에는 현행 서비스 구현으로 기록하지 않음.

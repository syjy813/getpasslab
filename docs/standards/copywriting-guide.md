# GetPassLab 카피라이팅 가이드

> **후속 상태:** v1.3 작성 당시 미실행 기록은 역사적 상태다. [2026-10-29 Cloud 후속 QA](../audits/2026-10-29-tossfeed-cloud-browser-qa.md)에서 기본 1363×936의 실측·조작을 수행했다. 지정 PC·모바일 크기는 계속 미확인이다. 최신 결과는 후속 보고서와 본 문서 끝의 보완을 참조한다.

- 버전: **v1.3 / 2026-10-29**
- 적용: 제목, 홈·목록 소개, 설명, 버튼·메뉴, 상태·배지, 기출·모의고사 안내, 오류 메시지, 이미지 캡션
- 기준: **정확한 대상 + 독자가 얻는 정보 + 필요한 조건**. 확인되지 않은 성과·빈도를 약속하지 않음
- 구분: 무엇을 다룰지는 [콘텐츠 가이드](content-guide.md), 문구를 어떻게 전달할지는 이 문서

## 1. 반드시 지킬 8가지

1. **대상과 행동을 분명히:** ‘대표 단서’보다 ‘자격 요건’, ‘자세히 보기’보다 ‘기출 풀기’
2. **결론을 먼저:** 중요한 조건이나 숫자를 뒤에 숨기지 않음
3. **추임새·형식적 문장 삭제:** ‘지금부터 알아보겠습니다’, ‘잘 이해하셨나요?’ 같은 말 걸기 제외
4. **강조 대신 사실:** ‘꼭 알아야 하는 핵심’보다 ‘선임 가능 조건’처럼 확인할 사실을 제목으로 사용
5. **검증 없는 약속 금지:** 합격 보장, 100%, 최빈출, 완벽 정리, 무조건, 국내 최고 등 근거 없는 표현 금지
6. **UI 문구는 실제 동작과 일치:** ‘답안 제출’은 실제로 답안을 제출할 때만 사용
7. **중복 금지:** 제목·설명·이미지·툴팁에 똑같은 안내를 나누어 반복하지 않음
8. **문체는 화면 목적에 맞춤:** 챕터 학습 문체와 서비스 알림의 존댓말을 기계적으로 통일하지 않음

## 2. 문구를 만드는 공식

| 위치 | 작성 방법 | 좋은 예시 |
| --- | --- | --- |
| 페이지 제목 | 대상 + 구체적인 학습·판단 주제 | ‘보일러 통풍 방식과 송풍기 위치’ |
| 비교 제목 | 비교 대상 + 차이의 기준 | ‘가스기능사와 가스산업기사의 선임 범위’ |
| 목록 설명 | 무엇을 볼 수 있는지 한 문장 | ‘공개된 챕터와 연결 기출을 과목별로 확인’ |
| 학습 챕터 첫 문장 | 한 줄 개념·공식·구별 기준 | ‘압입통풍은 송풍기로 연소용 공기를 공급하는 방식’ |
| 카드 제목 | 대상 이름 | ‘에너지관리기능사’ |
| 카드 보조 문구 | 제공하는 정보만, 확인되지 않은 성과 제외 | ‘보일러 구조, 배관, 제어의 핵심 개념과 연결 문제’ |
| 버튼 | 행동 + 대상 / 짧은 명확한 동사 | ‘기출 풀기’, ‘답안 제출’, ‘이미지 확대’ |
| 상태 | 현재 상태를 명사·수치로 표시 | ‘미응답’, ‘정답’, ‘오답’, ‘기출 연결’ |
| 오류 | 무슨 상태인지 + 사용자가 할 수 있는 조치 | ‘선택한 답안이 없습니다. 문항을 선택해 주세요.’ |
| 이미지 캡션 | 장치·상태·위치·관계 | ‘압입통풍의 송풍기 위치’ |

**예시는 새 문구 작성을 위한 예시**이며 현재 운영 화면의 문구라고 뜻하지 않음. 기능을 먼저 확인하고 버튼 문구를 결정함.

## 3. 불필요한 문구 제거 기준

> 삭제해도 독자의 이해·행동·판단에 손실이 없다면 삭제. 반드시 필요한 안내는 더 구체적으로 씀.

| 피할 표현 | 이유 | 권장 처리 |
| --- | --- | --- |
| ‘이번 챕터에서는 ~ 알아보겠습니다’ | 제목과 중복되는 형식적 도입 | 삭제하고 개념·조건부터 제시 |
| ‘자, 이제 다음을 살펴볼까요?’ | 사용자 행동을 돕지 않음 | 삭제 |
| ‘매우 중요한 내용이니 꼭 기억하세요’ | 이유 없는 중요성 강조 | 실제 시험 조건·비교 기준으로 대체 |
| ‘아래 그림을 참고해 주세요’ | 그림/캡션만으로 충분한 경우 중복 | 삭제. 해석의 핵심 한 줄만 필요 시 남김 |
| ‘한번 더 정리하자면’ | 동일한 설명 반복 | 새 판단이 없으면 요약 섹션 삭제 |
| ‘기출에 매우 자주 나옵니다’ | 집계 범위 없는 출제 빈도 암시 | 집계 근거를 제시하거나 삭제 |
| ‘이것만 알면 합격’, ‘완벽 대비’ | 검증되지 않은 결과 약속 | 사용자가 실제 할 수 있는 행동·정보로 교체 |
| ‘학습을 성공적으로 완료했습니다!’ | 단순 화면 종료에 불필요한 감탄 | 사실 상태만 ‘학습 완료’ 등으로 표시 |

문장 ‘~입니다/합니다’를 없애는 것이 목표가 아님. **의미 없는 말과 검증되지 않은 주장**을 없애는 것이 목표.

## 4. 표현·문체 규칙

### 4-1. 학습 본문
- 기본은 기존 [전체 챕터 작성 가이드](../../CHAPTER_WRITING_GUIDE.md)의 명사형·`~함`·`~임`·문장 끝 마침표 생략
- 단순한 용어 정의와 판별 기준을 짧게 쓰되, 이유·조건·예외가 없어서 의미가 달라지지 않도록 함
- ‘이 장치는 ~입니다’보다 ‘용도: ~’, ‘조건: ~’처럼 명확할 때 축약 가능. 모든 문장을 명사형으로 억지 전환하지 않음
- 수식·원문 기출·선택지·정답·표준 용어는 자연스러운 문구로 바꾸겠다는 이유로 수정하지 않음

### 4-2. 일반 정보 글
- 독자가 검색한 질문에 대한 **결론 → 적용 조건 → 비교·예외 → 확인 방법** 순서
- 법정 의무·기관 정책·채용 우대 등 서로 다른 기준을 같은 말로 묶지 않음
- ‘가능하다’는 판단은 누가, 어떤 시설, 어떤 시점에서 가능한지 구체화
- 홍보성 감탄·과도한 질문형 제목·근거 없는 유리한 수식어 사용하지 않음

### 4-3. UI·안내·오류
- 자연스러운 존댓말이나 기능명 사용. ‘정답을 확인할 수 있도록 해드리겠습니다’처럼 장황한 접객 문구 금지
- 성공/실패를 판정하지 않았으면 성공 표현 금지
- ‘확인’처럼 모호한 버튼은 문맥이 불분명할 때 ‘닫기’, ‘계속 풀기’, ‘답안 제출’ 등으로 변경
- 위험·삭제·문항 이탈처럼 사용자 결정에 영향을 주는 경우에는 **결과를 짧게 명시**하고 취소할 수 있게 함

### 4-4. 제목·메타·검색 문구
- 화면 H1, 브라우저 title, 메타 설명, 카드 제목은 **서로 역할이 다름**. 같은 긴 문장을 그대로 복사하지 않음
- 해당 페이지가 실제 제공하는 내용을 설명. 아직 없는 기능·전 범위 공개·모든 기출 제공 주장 금지
- ‘최신’은 관련 기준일이 표시될 때만. 공식 자료의 변동 가능성이 크면 날짜와 조건을 남김
- 검색어 반복보다 이용자의 질문과 본문 일치가 우선

## 5. 기호·줄바꿈·표현 통일

| 상황 | 원칙 | 예시 |
| --- | --- | --- |
| 동시 조건 | ‘및’, ‘와/과’ 또는 목록으로 명시 | ‘선임 및 시설 유지관리’ *(둘 다 필요할 때)* |
| 선택 조건 | ‘또는’ 명시 | ‘자격증 또는 인정 경력’ *(실제 규정이 그렇게 정한 때만)* |
| 문장 나열 | 독립 문장은 마침표/줄바꿈 | ‘A 수행. B 기록’ |
| 한 셀의 복수 요건 | 항목별 줄바꿈·목록 | ‘학력 요건’ 다음 줄 ‘경력 요건’ |
| 비교 대상 | 같은 항목·순서 유지 | ‘필요 자격 / 경력 / 시설 범위’ |
| 약어 | 첫 노출에서 뜻이 필요하면 설명 | ‘FD 송풍기(압입용)’ 등 맥락에 맞게 |
| 범위 | 기준·단위를 함께 표기 | ‘320px·390px 화면에서 확인’ |
| 단순 분류 | 가운뎃점 허용 | ‘컴퓨터일반 · 스프레드시트 일반’ |

가운뎃점(`·`) 자체를 일괄 금지하거나 일괄 변경하지 않음. **접속 의미를 숨기는 독립 문장 연결**에 사용하지 않음.

## 6. 버튼·배지·상태 카피 점검

- **버튼:** 누른 후 일어나는 행동이 텍스트와 일치하는지 실제 확인. ‘시작’/‘풀기’/‘채점’/‘닫기’ 구별
- **모달:** 본문 제목은 질문·행동 목적. 닫기 아이콘은 접근 가능한 이름이 있어야 함
- **선택 상태:** 선택, 미응답, 정답, 오답, 해설 공개의 용어를 일관되게 사용
- **출제 빈도 배지:** 모집단·집계 범위를 밝힐 수 있는 경우만 ‘빈출·최빈출’ 사용
- **요약·주의 상자:** 독자의 판단을 바꾸는 정보만. 같은 내용을 본문·상자에 반복하지 않음
- **광고·프로모션:** 광고임을 명확히 하고 학습 버튼처럼 오해될 문구를 사용하지 않음

## 7. 공개 전 체크리스트

- [ ] 제목만 보고 대상과 얻을 정보를 예상할 수 있는가
- [ ] 첫 문장이 관행적 소개가 아닌 실제 결론·기준인가
- [ ] 모든 문장을 ‘독자의 판단·행동에 필요한가’로 검토했는가
- [ ] 근거 없는 ‘중요·최고·완벽·반드시·무조건·빈출’ 표현이 없는가
- [ ] 정답·법령·숫자·단위·시험 시점에 필요한 조건이 유지됐는가
- [ ] 제목·본문·표·그림·배지의 중복 문구가 없는가
- [ ] AND/OR 조건과 셀 내 줄바꿈이 의미대로 적용됐는가
- [ ] CTA·오류·상태 문구가 실제 동작 결과와 일치하는가
- [ ] 390px에서 제목·버튼·표 라벨이 읽히는가

## 8. 토스 공식 라이팅과 GetPassLab 적용 기준 (v1.2)

### 8-1. 참고 원칙과 GetPassLab 전용 해석

토스 공식 글쓰기 자료에는 **다음 화면 예측**, **문장·화면·화면 사이의 무의미한 표현 제거**, **쉬운 단어**, **강요하지 않는 안내** 원칙이 있음. 이를 동일 문구로 복제하지 않고 GetPassLab에 맞는 편집 판단으로 변환.

| 참고한 원칙 | GetPassLab 문구 규칙 | 적용 제외/주의 |
| --- | --- | --- |
| 다음 화면 예측 가능 | '기출 풀기'는 문제 화면, '챕터 보기'는 읽기 화면으로 이동 | 클릭 뒤 다른 흐름이 나오는 문구 금지 |
| 문장 내 불필요한 단어 삭제 | '이번에는', '매우', '이제', '쉽게', '함께' 등 의미 없는 단어 제거 | 기술적 조건·부정 표현·단위는 삭제 금지 |
| 화면 안 중복 문장 삭제 | 제목·한 줄 설명·배지·이미지 캡션에서 같은 메시지 반복 금지 | 접근성용 alt·aria-label은 역할이 달라 유지 가능 |
| 화면 간 핵심 메시지 집중 | 목록에서는 선택 이유, 상세에서는 실제 내용과 조건만 제공 | 목록 카드 전체를 본문 요약처럼 길게 쓰지 않음 |
| 일상어 사용 | 사용자에게 익숙한 표현을 쓰고 약어는 필요 시 풀이 | 기출 원문·법정 용어·공식의 정확성은 우선 |
| 강요보다 사실 안내 | 선택 가능한 행동·결과·취소 가능 여부를 알려줌 | 불안 조성·합격 보장·사용자의 상황 단정 금지 |

**가이드 문체:** 토스피드 기사/토스 제품 문구의 반말·구어체·감성적 표현까지 동일하게 사용하지 않음. GetPassLab에서는 학습 본문은 [챕터 정본](../../CHAPTER_WRITING_GUIDE.md)의 간결한 형식을 유지하고, 서비스 안내는 자연스러운 존댓말로 씀.

### 8-2. 문장 → 화면 → 화면 간 교정 사례 (새로 작성한 GetPassLab 예시)

| 범위 | 개선 전 예시 | 개선 후 예시 | 이유 |
| --- | --- | --- | --- |
| 문장 안 | '지금부터 산업안전기사의 중요한 기출 개념을 함께 살펴보겠습니다' | '산업안전기사 핵심 개념' | 불필요한 추임새 제거. 실제 출제 빈도 주장은 하지 않음 |
| 화면 안 | 제목 '압입통풍' + 설명 '압입통풍을 알아보세요' | 제목 '압입통풍' + 설명 'FD 송풍기로 연소용 공기를 공급하는 방식' | 설명에 새로운 판단 정보 제공 |
| 화면 사이 | 목록·상세·문제 팝업에 '기출을 쉽게 학습할 수 있어요' 반복 | 목록 '관련 기출 3문항' *(실제로 3문항일 때)* → 상세는 개념·근거 → 문제 팝업은 문항·선택지 | 각 화면이 서로 다른 정보 제공 |
| 버튼 | '학습을 시작해보세요' | '기출 풀기' *(실제 문제를 여는 버튼)* | 누른 직후 동작 예상 가능 |
| 안내 | '정답을 확인하기 전에 꼭 한번 생각해보세요' | '정답 보기' | 강요하지 않고 동작 이름 사용 |
| 정보 기사 | '놓치면 손해 보는 초급 선임 조건' | '기계설비유지관리자 초급 인정 조건' | 독자가 검색한 요건을 정확히 표시 |

예시의 항목·문항 수는 실제 페이지 데이터가 아닌 **카피 작성 예**임. 실제 사용 시 코드·출처 확인 후 적용.

### 8-3. GetPassLab의 보이스와 톤

- **보이스(항상):** 정확하고 명확함, 짧지만 충분함, 과장하지 않음, 독자가 스스로 판단할 수 있게 함
- **학습 본문 톤:** 중립적 정의·조건·공식, 명사형·'~함/~임', 설명이 필요할 때만 긴 문장
- **시설관리 정보 톤:** 검색 질문에 결론부터 답하며 적용 대상·법적 근거·변경 가능성을 구별하는 설명체
- **서비스 UI 톤:** 짧고 자연스러운 안내, 명령형 남발 금지, 실패/미응답에서 비난하지 않음
- **광고·추천 톤:** 외부 노출을 늘리려고 '최고', '필수', '확정', '무조건' 등의 표현을 추가하지 않음

### 8-4. 실제 UI 개편 시 카피 완성 조건

1. 각 버튼의 **목표 화면·결과**를 적고 문구와 일치시킴
2. 제목·카드·요약·캡션에 중복된 메시지가 없는지 **문장/화면/화면 간** 확인
3. 서비스별 명칭 '시설의 모든 것 / 자격증의 모든 것'을 GNB·페이지 타이틀·위치 표시에서 일관되게 사용
4. 독자의 시간·성취·합격 가능성·출제 빈도를 근거 없이 약속하지 않음
5. 변경 뒤 모바일 폭에서 명칭·버튼의 잘림과 오해를 확인하고 기존 공개 URL을 보호

## 9. 토스 라이팅 원문과 적용 범위 재검증 (v1.3)

**검증 근거:** [토스의 8가지 라이팅 원칙](https://toss.tech/article/8-writing-principles-of-toss) (2022-11-15), [토스 마케팅 문구 6가지 원칙](https://toss.tech/article/Marketing_Writing) (2026-01-30), [재검증 기록](../audits/2026-10-29-tossfeed-reference-revalidation.md)

### 공식 문서에 있는 원칙과 GetPassLab 자체 규칙을 구분

| 토스 원문 원칙 | 의미 확인 | GetPassLab 적용 |
| --- | --- | --- |
| Predictable hint | 다음 화면에서 무엇이 일어날지 예측 가능 | '챕터 보기', '기출 풀기', '답안 제출'의 동작과 이동처 정확히 일치 |
| Weed cutting | 문장 안 의미 없는 단어 제거 | 추임새·과도한 수식어 삭제. 정답 조건·부정어·단위는 보존 |
| Remove empty sentences | **한 화면** 안 의미 없는 반복 문장 제거 | 타이틀·카드 설명·도식 캡션의 불필요한 반복 삭제 |
| Focus on key message | 화면 사이에 필요한 핵심 메시지에 집중 | 목록은 선택 정보, 상세는 판단 근거, 문제 화면은 실제 문항/상태 |
| Easy to speak / Universal words | 이해하기 쉬운 말·용어 사용 | 쉬운 설명을 우선하되 법령명·기출 원문·자격명은 정확히 유지 |
| Suggest over force | 강요·공포 조성 자제 | '이것 안 보면 불합격' 같은 불안 자극 문구 금지 |
| Find hidden emotion | 문구를 접하는 사용자의 감정 고려 | 채점·미응답 메시지에서 비난하지 않음. 과도한 감정 문구는 넣지 않음 |

### 적용하지 않을 것

- 토스피드의 **스토리형 에세이 문체**를 자격증 챕터의 기본 문체로 전환하지 않음
- 토스의 마케팅 A/B 테스트 결과를 GetPassLab의 클릭률·합격률 향상 근거로 사용하지 않음
- 기사형 '3분', '필진' 등 메타는 실제 값이 있을 때만 노출
- 문구를 줄이는 것이 목표가 아니라 **의미 없는 말을 제거하면서 정확한 메시지를 유지**하는 것이 목표

### 실무 교정 예시 (GetPassLab 자체 작성)

| 사용처 | 이전 초안 예시 | 수정 예시 | 판정 기준 |
| --- | --- | --- | --- |
| 홈 카드 | '모든 기출을 완벽하게 학습하세요' | '에너지관리기능사 필기 챕터 보기' | 수록 범위 과장 제거 |
| 정보형 제목 | '놓치면 후회하는 법정선임 필수정보' | '기계설비유지관리자 초급 인정 조건' | 불안 유도 제거·실제 질문에 대응 |
| 모달 버튼 | '계속 진행하기' | '답안 제출' *(실제 제출이라면)* | 다음 행동 예측 |
| 표 설명 | '아래 표에서 상세 내용을 참고할 수 있습니다' | 삭제 또는 실제 차이 1문장 | 제목·표와 중복 제거 |

**참고:** 공식 글쓰기 문서는 '어떤 문장을 어떻게 쓸 것인가'의 원칙이며 토스피드의 카드 크기·색상·모바일 동작을 입증하는 자료가 아님.

## 부록 B. 현행 화면의 후속 검토 후보

- 현행 main 소스의 홈·푸터에는 ‘합격을 위한’, ‘핵심만 빠르게’ 등 문구가 있음. 즉시 금지 대상으로 단정하지 말고 실제 정보·화면 목적과 일치하는지 문맥별 검토

## 2026-10-29 Cloud Browser 후속 보완 — v1.3

근거: [Cloud QA F02·F03](../audits/2026-10-29-tossfeed-cloud-browser-qa.md). 토스 공식 라이팅 원칙과 기존 자체 규칙을 유지한다.

- 이미지에 가로 넘침이 있을 때만 좌우 이동을 안내한다. 세로 넘침만 있으면 가로로 밀라고 하지 않고, 넘침 없으면 지시를 생략한다. 크기 전환 후 실제 상태로 재판정한다.
- “확대”라고 부르면 표시 크기·판독성이 향상되는지 확인한다. 원본 크기로 보여주는 기능이라면 “원본 크기 보기” 등 정확한 명칭을 검토한다. 이번에 Production 문구를 변경한 것은 아니다.
- 서비스 선택은 “시설의 모든 것 / 자격증의 모든 것”, 하위 기능은 “자격증 선택 / 챕터 목차” 등으로 역할을 나눈다.
- 정답 확인 레이어·즉시 풀이·소방 제출/채점 창은 결과가 다르므로 동일 문구로 강제 통일하지 않는다.
- 홈 소개 축약은 다음 행동을 드러내는 후보이며 클릭률·학습 성취 개선이 검증됐다고 쓰지 않는다.

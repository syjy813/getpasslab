## 1. 콘텐츠 운영 원칙

### 1.1 목표와 포지셔닝

**"직접 조사한 채용공고·제도·현장 업무를 연결해 시설관리 취업과 장기 커리어를 실제로 판단할 수 있게 한다."**

- 독자의 주요 질문은 **어디에 취업할 수 있는가 → 어떤 자격이 필요한가 → 실제 선임이 가능한가 → 어떤 근무·급여 조건인가 → 경력을 어떻게 쌓는가**다.
- 독자에게 필요한 것은 자격증 목록이 아니라 **사업장 단위의 비교와 선택 기준**이다.
- 특정 분야를 준비하는 사람의 관점에서 **에너지관리·공조냉동·가스·위험물·소방 등 자격의 실무 활용**을 설명한다.
- 취업정보, 직무현장, 법정선임, 경력증빙, 기계설비유지관리자 등급을 하나의 경로로 연결한다.
- 상업적으로 매력적인 과장, 허위 경력·방문 경험, AI 재요약형 대량 글은 만들지 않는다.

### 1.2 다섯 가지 구분(항상 사용)

| 분류 | 의미 | 예시로 쓸 문장 |
|---|---|---|
| 법적 선임 요건 | 법령이 특정 대상/규모에 요구하는 자격 | "해당 냉동시설의 법령상 선임기준을 확인해야 한다" |
| 채용 필수 요건 | 특정 공고에서 필수로 적은 요건 | "2026년 ○차 ○○사업소 공고는 ○○ 선임 가능자를 필수로 명시했다" |
| 채용 우대 요건 | 가점·우대조건 | "해당 공고는 관련 자격 보유자를 우대했다" |
| 실무 활용 | 설비 운전/정비/관리에서 유용 | "공조냉동 지식은 냉동기·공조설비 이해에 연결된다" |
| 장기 경력 가치 | 인정경력·직책·상위 자격과 연결 | "해당 실무경력을 증빙하면 향후 경력심사에 활용될 수 있다" |

**규칙:** '자격증이 있다'와 '특정 시설에 법정선임할 수 있다'는 다르다. '채용 필수'와 '취업에 도움이 된다'도 구별한다.

### 1.3 핵심 커리어 관점

1. 지원할 기관보다 먼저 실제 사업장과 관리 설비를 본다.
2. 현장에서 직접 수행하는 기계설비 업무를 기준으로 첫 일자리를 비교한다.
3. 기능사·산업기사·기사 취득과 동시에 업무·근무기간·선임이력을 증빙한다.
4. 에너지관리·공조냉동 분야를 중심으로 실제 지원 공고의 추가 선임요건을 확인한다.
5. 장기적으로 기계설비유지관리자 책임/보조 및 등급 상승 가능성을 검토한다.

> 단, 기능사 우선 취업, 기사 우선 취득, 공공자회사 이직 같은 추천은 **현재 경력·응시요건·지역·공고 필수조건**에 따라 달라져야 한다.


### 1.4 서비스 정체성 — 편집형 정보 미디어 우선

**초기 포지셔닝:** "시설관리 취업·법정선임·실무 정보를 공식 근거와 실제 사례로 정리하는, 읽기 쉬운 전문 정보 미디어"

- **운영자 발행을 우선:** 최초 오픈은 빈 게시판·자유게시판보다 검증된 아티클, 공고 아카이브, 실무 가이드에 집중한다.
- **커뮤니티 같은 친근함은 문체와 정보 설계에서 구현:** 실제 이용자 후기·댓글·활동량이 존재하는 것처럼 보이게 하지 않는다.
- **위키형 아카이브는 문서 구성 방식:** 개념·설비·제도·질문을 체계적으로 연결하며, 협업 편집 기능이 반드시 필요하다는 뜻은 아니다.
- **참여 기능은 추후 검토:** 질문 수요, 답변 검증·수정·신고·운영 역량이 확보된 뒤 Q&A나 게시판의 실익을 평가한다.
- **자격증 학습과 역할 분리:** 이 영역은 취업·선임·실무 활용, '자격증의 모든 것'은 시험 이론·기출·문제풀이를 담당한다.

### 1.5 초기 차별화 포맷 — 두 가지 주력 + 연결 콘텐츠

1. **법·제도 변화 '3줄 핵심'**: 무엇이 바뀌었는지 / 누구에게 적용되는지 / 무엇을 확인·준비할지. 단, 3줄은 **진입 요약**이지 법령 해석 전체를 대신하지 않는다. 기준일·시행일·적용 대상·예외·공식 출처를 본문에 따로 제공한다.
2. **구조화된 실무 위키·Q&A 아카이브**: '기계실에서 펌프는 무슨 역할일까?', '기능사 자격만으로 선임이 가능한가?'처럼 **질문 하나에 핵심 답 하나**를 제공하고 개념, 판단 기준, 사례, 출처, 관련 글로 연결한다.
3. **실제 공고 분석·커리어 가이드로 차별화**: 기관명에만 의존하지 않고 사업소, 고용형태, 필수·우대·선임, 급여·교대, 경력 기준을 대조한다.

**발행 판단:** 짧은 글이라는 이유만으로 별도 URL을 만들지 않는다. 독립 검색 의도와 검증 가능한 근거, 기존 문서와 구별되는 판단 가치가 있을 때만 발행한다.

### 1.6 스타일 참조 범위

- 토스피드에서 참고하는 것은 **쉽게 읽히는 편집적 위계, 자연스러운 제목, 짧은 문단, 핵심 정보 우선의 독서 흐름**이다.
- 브랜드 로고·화면·카피·컴포넌트를 동일하게 복제하지 않는다. GetPassLab의 포레스트 그린 테마와 기존 Astro 구조, 접근성·성능·SEO를 우선한다.
- 디자인 자체보다 **한 페이지에서 독자가 무엇을 이해하고 판단할 수 있는가**를 콘텐츠 품질 기준으로 삼는다.

## 3. 기존 10편 핵심 내용 — 이관용 요약

이 절의 모든 숫자·기준은 **당시 원문이 분석한 공고 및 제도**이다. 운영상 데이터를 재사용할 때 `기준 연도·공고 차수·사업소·근무형태·기준일`을 함께 보존한다.

- 시설 영역은 **기사·기능사 공부법 자체**보다 자격의 **채용·법적 활용·실무·경력**을 다룬다.
- 학습 영역은 시험요건·과목별 이론·기출·모의고사를 다룬다.

### 4.1 시작 페이지 구성

1. **핵심 주제 진입:** 첫 취업 / 채용공고 분석 / 법정선임 / 기계설비유지관리자 / 현장 실무.
2. **먼저 읽기 3편:** 첫 취업, 공공기관 시설관리 비교, 법정선임 5대 개관.
3. **기관별 카드:** 한전FMS, 우체국시설관리단, 코레일테크, 캠코FMC (발행 기준 연도 표시).
4. **빠른 선택:** 기능사로 시작 / 법정선임 준비 / 중장년 이직 / 경력직 상향.
5. **학습 콘텐츠 연결:** 예) 에너지관리기능사 학습 ↔ 검사대상기기관리자의 실무 활용.


### 4.2 홈 화면의 에디토리얼 위계(안)

1. **첫 화면:** "시설관리, 어디서부터 시작해야 할까?"와 한 문장 서비스 소개. 핵심 진입 경로 **첫 취업 / 채용공고 / 법정선임 / 현장 실무**를 우선 배치한다.
2. **처음 읽을 글:** 직무 개관, 첫 취업, 법정선임 개관 등 시작점을 주는 글 3편 내외.
3. **핵심 아카이브:** 기관별 채용공고 비교 카드와 ‘2026년 공고 사례’처럼 연도가 표시된 제목/설명.
4. **짧게 읽기:** 공식 개정 확인을 마친 법·제도 변화 '3줄 요약'. 개정 소식이 없으면 억지로 채우지 않는다.
5. **실무 위키:** 보일러·냉동기·펌프·공조기·BMS 등 설비 질문형 카드.
6. **연결 학습:** 시설 실무에서 이어지는 자격증 학습 페이지. 사이트 내 다른 영역으로 이동함을 분명히 알린다.

**운영 원칙:** 실제 등록 콘텐츠가 없는 섹션은 노출하지 않는다. 카드 수를 채우기 위해 품질이 낮은 글을 생산하지 않는다. 홈의 섹션 순서·카드 수·최종 카피는 구현 후 PC·모바일 QA에서 조정한다.

### 4.3 분류와 탐색 기준

- 최상위 4개 묶음: **취업·커리어 / 채용공고 분석 / 법정선임·자격 활용 / 시설관리 실무**.
- '3줄 요약', '실무 위키', '기관 분석'은 **콘텐츠 형식/시리즈**다. 처음부터 별도의 상위 카테고리와 중복 URL을 만들지 않는다.
- 동일 주제의 글은 **개관 → 자세한 판단 기준 → 실제 사례 → 관련 자격증 학습** 순서로 연결한다.
- 예상 독자 질문과 태그는 탐색 보조 요소이며, 태그별 빈 페이지·기계적 유사 글 생성을 피한다.
- IA와 제안 URL은 **검토안**이다. 기존 공개 URL·slug·식별자 변경은 별도 승인과 영향 검토가 필요하다.

## 5. 실제로 사용했던 글쓰기 스타일과 개선된 집필 규칙

### 5.1 편집 톤

- **첫 화면에 답부터:** `H1 → 핵심 요약 → 도입부` 순서를 기본으로 한다. 핵심 요약에서 검색 질문의 답을 먼저 전달하며, 도입부는 요약을 반복하지 않고 상황·문제의식으로 자연스럽게 이어간다.
- **실제 공고·제도 우선:** 일반론보다 기관명, 사업소, 공고 차수, 직급, 자격조건, 급여 등 확인 가능한 근거를 보여준다.
- **짧고 명확한 문단:** 모바일 기준 한 문단에 한 개의 주장만 둔다.
- **핵심 비교표 + 해석:** 표를 넣은 뒤 "표를 읽으면 무엇이 달라지는지" 설명한다.
- **과장 배제:** 모든 시설직에 적용된다고 주장하거나, 단일 사례를 전체 시장 통계로 확대하지 않는다.
- **다음 행동 제시:** 독자가 어떤 공고를 확인하고 어떤 자격·경력을 준비할지 마무리에서 결정하게 한다.

### 5.2 제목·소제목 규칙

- `H1`: 페이지당 1회, 검색하는 사람이 실제 궁금해하는 질문 또는 기관·자격 키워드 중심. 사이트 레이아웃이 페이지 제목을 `H1`으로 출력한다면 Markdown 본문에 중복 `H1`을 만들지 않는다.
- `H2`: 대분류(예: 실제 채용공고에서는 무엇을 요구할까? / 법정선임 조건 / 근무조건 / 준비 방향).
- `H3`: 해당 `H2`에 종속되는 독립적인 세부 질문·설비·자격 또는 사업소 분석. 제목을 크기만 작게 보이게 하려고 `H3`를 사용하지 않는다. `H4`는 정말 필요한 경우에만 사용한다.
- **계층을 건너뛰지 않는다:** `H1 → H2 → H3` 순서로 구조를 만든다. `이어 읽기`가 본문 전체의 독립 섹션이면 `H2`를 사용한다.
- **폰트 크기와 제목 계층은 별개다:** Markdown에서 의미를 표시하고, 실제 크기·굵기·간격은 공통 CSS/디자인 토큰으로 관리한다(5.11 참조).
- 제목 패턴: `[채용공고 분석] 기관명 시설관리｜핵심 주제 총정리`, `기계설비유지관리자 등급 총정리｜초급·중급·고급·특급 기준` 등.
- 맥락 없는 '무조건', '필독', '역대급', '100% 합격·취업' 등 과장 제목은 지양. 기존 '40~60대 필독' 글은 이전 시 검색 질문형 제목 개선 검토.

### 5.3 본문 기본 흐름

**공통 시작:** `H1 → 핵심 요약(1~3개의 핵심 문장/항목) → 대표 이미지 → 도입부 → H2 본문`. 화면에 제목·핵심 요약이 먼저 보이도록 하고, 도입부에서 요약을 같은 말로 반복하지 않는다. 법령·채용 정보는 요약에도 기준일·대상 범위를 빠뜨리지 않는다.

**정보형:** 핵심 요약 → 생활 장면 또는 독자의 질문 → 제도/직무 설명 → 필요한 비교·사례 → 다음 판단/관련 글.

**채용공고 분석형:** 핵심 요약 → 어떤 공고를 비교했는가 → 공고 원자료·표본 → 사업소/직급별 요건 → 반복되는 자격·선임 패턴 → 급여·교대·정년 → 입문자/경력자 선택 → 업데이트 안내.

**법령형:** 핵심 요약(대상·기준일 포함) → 적용 대상과 개념 → 법적 근거 → 자격별/설비 규모별 기준 → 예외·겸직·특례 → 사례 → 독자가 확인할 행정 절차.

**초보자 가이드형:** 핵심 요약 → 상황·궁금증 → 비교 기준(최대 3~5개) → 실패하기 쉬운 조건 → 실제 면접·공고 체크리스트 → 관련 글/다음 행동.

- **결론 재진술은 필수가 아니다.** 이미 상단 요약과 본문에서 충분히 답했다면 형식적인 마지막 요약 대신 독자가 다음에 확인할 자료로 마무리한다.

### 5.4 데이터 표 작성 요령

- 채용 표 필수 컬럼: **기관 / 사업소 / 공고일·차수 / 고용형태 / 직위·직급 / 필수자격 / 우대자격 / 법정선임 / 경력 / 근무형태 / 급여 / 정년 / 공고 출처**.
- PC에서는 자세한 표를 쓰더라도 모바일은 주요 4~6열만 보여주고 상세 조건을 카드 또는 접이식 정보로 분리한다.
- 복합요건 `A + B + C`는 **동시충족(AND)** 여부를 명시하고, `A 또는 B`는 대체조건(OR)임을 표기한다.
- 사업소 요구사항과 법적 선임가능 자격표는 한 칸에서 섞지 않는다.
- 평균보수, 기본급, 수당 포함 월 지급액, 12개월 단순환산, 실제 연봉을 구분한다.
- `급여 약 400만원`만 쓰지 않고 `2026년 ○차 ○사업소, 교대·월 지급액, 세전, 포함수당은 공고 확인`처럼 표기한다.
- 공고 표본이 일부면 "대표 공고 사례이며 전수조사가 아님"을 표 밑에 둔다.

### 5.7 편집형 미디어 카피라이팅 규칙(v1.1, v1.2 보완)

- 첫 화면에 **제목(H1) → 핵심 요약(1~3개) → 도입부 → 본문(H2부터)** 흐름을 사용한다. 불필요한 인사·장황한 배경부터 시작하지 않는다.
- **짧고 자연스럽게:** 모바일에서 문단 하나는 한 주장만, 전문용어는 처음 등장할 때 짧게 풀이한다. 지나친 명사 나열·어색한 어미·중복 결론을 줄인다.
- **번호형 요약은 선택적:** 비교 선택지나 실행 순서가 2~5개일 때 사용. 모든 글을 강제로 숫자 목록으로 만들지 않는다.
- **볼드 강조는 '읽어야 하는 결론'에 집중:** 핵심 개념·판단 기준·필수/우대·AND/OR·적용 대상·기준일·급여 단위·중요 예외 등에 사용한다. 기본값은 `H2`당 강조 문장 **1~2개 이내를 목표**로 하며, 필요하면 더 적게 쓴다. 단순 장식, 위트·비유 자체, 한 문단 전체를 기계적으로 볼드 처리하지 않는다.
- **강조는 정보와 분리하지 않는다:** '불가'·'예외'·'해당 공고만' 같은 제한조건을 빼고 유리한 부분만 굵게 만들지 않는다.
- **표 하나 + 표 아래 해석:** 단순 수치 열거를 피하고 “이 표를 보고 어떤 결정을 해야 하는가”를 1~2문장으로 설명한다.
- **에디터의 해석과 사실을 분리:** “2026년 해당 공고에는 …”와 “이런 경력 경로를 고려할 만하다”를 같은 확정 사실로 쓰지 않는다.
- **이모지와 감탄은 최소화:** 정보 밀도가 높은 전문 아티클에는 관습적인 장식 대신 제목·라벨·여백으로 위계를 만든다.
- **의미 단위 줄바꿈:** 문장마다 줄을 바꾸지 않는다. 화제 전환, 사례→해석, 독자 질문→답변에서 문단을 나누되 기존 5.11의 본문 행간·문단 간격을 우선 유지한다.
- **일상 문장 교정:** 맞춤법에 맞는 표현이라도 맥락상 과장되거나 어색하면 더 자연스러운 말로 교체한다. 예를 들어 ‘존재감조차 없던 설비’는 ‘평소에는 신경 쓰지 않던 설비’처럼 다듬을 수 있다(‘존재감조차’ 자체는 올바른 띄어쓰기임).
- **공개 본문과 내부 편집 메모 분리:** ‘자료 및 편집 기준’ 같은 내부 작업용 제목, 임시 URL·작업 상태·검수 요청사항을 공개 본문에 자동 노출하지 않는다. 단, 법령·채용·급여 등 근거가 필요한 정보의 **실제 독자용 출처 링크·확인일·적용 범위는 삭제하지 않는다**. 문맥에 자연스럽게 넣거나 출처 주석·연결 링크를 제공한다.

**짧은 예시**

> **제목:** 시설관리 교대근무, 급여가 높으면 더 좋은 조건일까?  
> **첫 문단:** 교대근무는 야간·연장수당 때문에 월 지급액이 높아 보일 수 있습니다. 그러나 근무시간, 휴게시간, 실제 야간 비중을 함께 확인해야 조건을 비교할 수 있습니다.  
> **다음 내용:** 근무표 비교 → 수당 포함 여부 → 면접에서 확인할 질문

### 5.8 콘텐츠 유형별 템플릿(고정 소제목 강제 아님)

| 콘텐츠 형식 | 맨 앞에서 해결할 질문 | 권장 본문 흐름 | 필수 검증·표시 |
|---|---|---|---|
| 법·제도 변화 '3줄 핵심' | 무엇이, 누구에게, 언제부터 바뀌나? | 3줄 요약 → 변경 전/후 → 적용 대상·예외 → 준비할 일 | 법령·조항·시행일·확인일·원문 링크 |

- 위키 문서에 실측 사진·현장 경험이 없는 경우 **실제 경험담처럼 쓰지 않는다**. 학습용 도식은 재구성임을 표시한다.
- 기존 글과 동일 검색 의도라면 새 글보다 **기존 글 업데이트/내부 섹션 보강**을 우선한다.

### 5.10 에디토리얼 UI·모바일 UX 원칙

- **본문 중심:** 장식적 카드보다 타이포그래피, 문단 간격, 명확한 소제목, 읽기 흐름을 우선한다. 카드형 표현은 홈·목록·선택·요약 구간에 집중한다.
- **색의 역할 분리:** 포레스트 그린은 브랜드·주요 액션, 중성색은 본문·구분선, 주의 정보는 별도 라벨·문구로 식별한다. 색만으로 위험·정답·상태를 표현하지 않는다.
- **읽기 좋은 문단 폭:** PC에서 한 줄이 지나치게 길어지지 않도록 콘텐츠 폭을 제한하고, 모바일은 본문을 우선해 좌우 여백과 줄간격을 확보한다.
- **표는 상황에 맞게:** 모바일에서 표의 의미를 잃는다면 핵심 4~6개 항목으로 압축하거나 카드로 바꾼다. 불가피한 가로 스크롤에는 스크롤 가능함을 표시한다.
- **카드 정보 계층:** 카테고리/시리즈 → 제목 → 핵심 한 문장 → 날짜/출처. 긴 제목은 의미 없이 잘라 핵심 조건을 숨기지 않는다.
- **조작 가능성:** 링크·버튼은 시각적으로 구분하고 눌렀을 때 실제 이동한다. 키보드 포커스, 터치 영역, 이미지 대체 텍스트를 검수한다.
- **근거 접근성:** 법령·공고의 원문 및 기준일을 독자가 쉽게 찾도록 한다. 과거 채용공고에는 '사례 분석'을 표시하고 현재 모집으로 오인시키지 않는다.
- **성능과 SEO:** 정적 Astro 구조 재사용, 이미지 최적화, 제목 계층·메타데이터·내부 링크를 우선하며 필요 없는 클라이언트 스크립트·애니메이션을 피한다.
- **실측 QA:** 최소 모바일 약 390px과 PC 약 1440px에서 본문, 표, 목차, 카드, 관련 글, 광고와 콘텐츠의 간격을 확인한다. 이 규칙은 **검증 목표**이며 본 문서 작성만으로 QA 완료가 아니다.


### 5.11 콘텐츠 타이포그래피 가이드 (v1.2 추가)

아래 수치는 **시설의 모든 것 신규 콘텐츠에 대한 권장 디자인 목표값**이다. 실제 GetPassLab CSS·전역 토큰·기존 반응형 규칙을 확인한 후 확정하며, 지금 문서 작성만으로 사이트에 적용된 것으로 표현하지 않는다. CSS가 한 번에 제어하도록 **Markdown 본문에 인라인 `font-size`, 임의 HTML 제목 태그, 페이지별 개별 CSS를 넣지 않는다.**

| `H1` 페이지 제목 | 32px | 27px | 700 | 1.25~1.35 |
| `H2` 대분류 제목 | 24px | 22px | 700 | 1.3~1.4 |
| `H3` 세부 제목 | 20px | 18px | 600 | 1.4~1.5 |

- **본문 16px 우선:** 모바일 본문은 기본 16px을 유지한다. 표·캡션은 작은 크기를 허용하더라도 확대 없이 핵심 정보가 읽히는지 확인한다.

- **폰트 일관성:** 기존 사이트의 한글 폰트와 디자인 토큰을 우선 사용한다. 새로운 웹폰트 도입은 별도 성능 검토 없이는 진행하지 않는다.
- **템플릿 조정:** 레이아웃이 제목을 렌더링하면 본문 Markdown에 두 번째 `H1`을 추가하지 않는다. 핵심 요약은 시각적 카드나 인용 블록으로 보이더라도 `H2`로 오인될 정도의 제목 크기를 적용하지 않는다.
- **검증:** 실제 구현 시 390px/1440px 화면에서 제목 줄바꿈, 본문 밀도, 표 너비, 요약 카드, 캡션 대비, 시스템 글꼴 확대 및 가로 스크롤 여부를 확인한다. 본 문서 수치는 **QA 완료 판정이 아니다**.

### 5.12 작가형 문체·비유·강조 운영 원칙 (v1.2 추가)

**목표:** 기술 정보의 정확성은 유지하면서, 'AI가 목차대로 정리한 설명문'보다 **사람이 독자에게 이야기를 들려주는 전문 에디토리얼 글**처럼 읽히게 한다. 가벼운 위트는 허용하되 공고·법령·안전 정보의 권위와 근거를 약화하지 않는다.

1. **장면에서 시작하되 답은 먼저 제공:** `H1` 다음 `핵심 요약`으로 결론을 보여준 뒤, 도입부에 일상적 상황·독자의 질문·작은 반전을 사용한다. 예를 들어 건물의 설비를 설명할 때 '평소에는 조용한데 멈추면 모두가 알아차리는 일' 같은 생활 장면을 활용한다.
2. **비유는 이해에 도움이 될 때만:** 낯선 설비·자격제도에 익숙한 장면을 연결한다. 하나의 핵심 개념에 비유 하나면 충분하며, 모든 문단을 비유·농담으로 시작하지 않는다. 비유 다음에는 실제 기술적 의미를 정확한 용어로 다시 적는다.
3. **위트는 자연스럽게:** 질문형 문장, 짧은 반전, 담백한 관찰을 활용한다. 억지 유행어, 인위적 감탄, 과도한 의인화, 감성 문장 남발을 피한다.
4. **문장 리듬을 조절:** 짧은 문장과 설명이 필요한 긴 문장을 섞는다. 매 문단을 '따라서', '중요하다', '확인해야 한다'로 끝내거나, 'A는 B다 → 사례 → 핵심 요약'을 반복하지 않는다.
5. **볼드는 핵심 주장에만:** 독자가 굵은 부분만 훑어도 결론·조건·차이를 파악할 수 있도록 한다. 한 섹션에 대략 1~2개를 출발점으로 삼되 실제 정보 밀도에 따라 조절한다. 비유를 돋보이게 하려고 **기술적 제한조건만 빠진 문장**을 강조하지 않는다.
6. **말투는 읽기 쉽게, 근거는 엄격하게:** 일상 설명은 자연스러운 서술체를 쓰되, 법령·급여·채용 조건은 시점과 적용 범위를 정확히 적는다. 실제 현장 경험이 없다면 경험한 것처럼 '제가 가봤더니'라고 쓰지 않는다. 가상 상황은 독자가 오인하지 않도록 예시임을 명시한다.
7. **불필요한 복습·훈계 삭제:** 상단 요약을 말만 바꿔 마지막에 반복하지 않는다. 별도 글에서 깊이 다룰 주제는 핵심 차이만 설명하고 관련 글로 연결한다.

**편집 예시(가상 사례):**

- 딱딱한 표현: `시설관리 업무는 건물의 설비에 대한 운전·점검·유지보수·기록을 수행한다.`
- 개선한 표현: `건물은 아무 말 없이 잘 돌아가는 듯 보인다. 하지만 냉방이 멈추는 순간, 누가 이 설비를 돌보고 있었는지 알게 된다. 시설관리는 그런 일이 생기기 전부터 설비의 상태를 살피는 일이다.`
- **정확성 보완:** `여기서 말하는 '살핀다'는 운전 상태 확인·정기 점검·필요 시 정비 조치와 기록을 포함한다.`

**피해야 할 사례:** 비유를 법정선임의 실제 자격 범위처럼 오해하게 하거나, 안전상 위험한 조작을 '쉽게 따라 할 수 있다'고 묘사하는 문장.

### 5.13 시설 영역 이미지 디자인 시스템 (v1.3 추가)

**결정:** 2026-10-30에 승인된 첫 글 「시설관리란? 건물이 멀쩡한 데는 다 이유가 있다」의 **이미지 5장**을 '시설의 모든 것' **시각 스타일 기준 세트**로 채택한다. 승인 이미지는 원본을 유지한다. 단, 스타일 승인과 기술적 정확성·배포 QA 완료는 별개다.

#### 5.13.1 제작 방향 및 스타일 토큰(권장)

- **캔버스:** 따뜻한 오프화이트/아이보리 배경, 짙은 포레스트 그린 포인트, 차콜 본문, 연한 그린 정보 카드. 특정 HEX는 저장소의 기존 디자인 토큰 확인 후 확정한다.
- **조형:** 부드러운 라운드 카드, 얕은 그림자, 단정한 일러스트·설비 도식, 충분한 여백, 읽기 쉬운 한글 제목. 실제 기업·기관의 로고와 화면을 유사하게 위조하지 않는다.
- **브랜드 시그니처:** 필요할 때만 작은 `시설의 모든 것` 표기. 매 이미지마다 동일 인물·건물을 반복하지 않는다. 이미지 내부의 장식·캐릭터가 정보보다 눈에 띄지 않게 한다.
- **원칙:** 이미지가 본문의 판단을 보조해야 하며, 글자만 반복하는 홍보 포스터로 만들지 않는다. 일러스트는 사실적인 장비 도면이나 현장 사진으로 오인되게 제작하지 않는다.

#### 5.13.2 이미지 용도와 규격

| 구분 | 권장 비율 | 기준 픽셀 | 사용 원칙 |
|---|---|---|---|
| 본문 설명 이미지·인포그래픽 | **4:3 (확정 기본)** | 원본 1448×1086, 새 제작 기준 약 1440×1080 | 본문 전체 폭에 반응형으로 배치하고 원본 종횡비 유지 |
| 시설 영역 대표 이미지 | **4:3을 우선 사용** | 본문 이미지와 같은 원본 활용 가능 | 실제 목록 카드 비율을 확인하고 크롭·텍스트 안전영역 검증. 16:9는 목록 UI상 필요할 때만 별도 제안 |
| OG/SNS 공유 이미지 | 약 **1.91:1** | 약 1200×630 | 필요할 때 별도 파생 제작. 본문 4:3 원본을 무조건 잘라 사용하지 않음 |
| 기존 티스토리 블로그 썸네일 | **1:1 유지 가능** | 해당 블로그 규칙 준수 | GetPassLab 시설 영역의 4:3과 혼동하지 않음 |

- **새 이미지가 글당 무조건 5장인 것은 아님:** 대체로 대표 1장 + 판단에 도움 되는 세부 2~4장을 출발점으로 하되 짧은 글은 더 적게 사용한다. 중복·장식 이미지는 제외한다.
- **문서 내 위치:** `H1 → 핵심 요약 → 대표 이미지 → 도입부`를 기본으로 하고, 직무·근무시설·자격 구별·체크리스트 같은 구간은 해당 설명 가까이에 배치한다. 이미지 삽입을 위해 H2/H3 계층을 바꾸지 않는다.
- **보존:** 최종 PNG 원본과 웹용 WebP 파생을 분리 보관한다. WebP 파생은 화면 표시 최적화를 위한 것이며 승인된 이미지 내용·비율을 변경하지 않는다. 이미지당 용량은 합리적으로 줄이고 실제 LCP·CLS 영향은 구현 시 확인한다.
- **문구와 글꼴:** 이미지의 큰 제목은 줄이고 본문에서 이미 H2로 제시하는 같은 문구를 과하게 반복하지 않는다. 한국어 오탈자·단위·숫자·기관명·법률 용어는 제작 후 원고와 대조한다.

#### 5.13.3 콘텐츠별 이미지 유형 선택

1. **대표 이미지:** 주제를 소개하는 일러스트, 단일 핵심 메시지.
2. **개념·직무 비교:** 기계·전기·소방·영선 등 서로 다른 항목을 동등한 카드로 표현.
3. **장소·근무환경 비교:** 오피스·아파트·병원 등 시설 유형별 차이를 보여줌.
4. **법령·자격·선임 설명:** 조건, 예외, 자격의 실제 효력을 비교하되 최신 법령과 대상 범위를 별도 검증.
5. **실무·구조도:** 기기 구성·유체 흐름·순서 등 관계를 정확하게 묘사. 기술적 사실성이 불확실하면 초안으로 보류하고 실무·공식 매뉴얼 검증 후 공개.
6. **절차·체크리스트:** 사용자가 확인하거나 수행할 질문을 요약. 실제 의무점검표로 오인되지 않도록 표기.

**중요한 시각적 의미 규칙:** `필수자격 / 우대자격 / 법정선임`은 **순차 단계가 아니라 별도의 개념**이다. 비교 항목 사이에는 원칙적으로 화살표를 사용하지 않는다. 첫 1번 콘텐츠의 **승인된 기존 이미지에는 화살표가 남아 있으므로**, 본문과 캡션에서 '순서가 아니다'를 명시한다. 이는 해당 이미지의 가독성 보완책이며 신규 이미지에 같은 구조를 재사용하라는 뜻이 아니다.

#### 5.13.4 반응형·접근성·SEO

- **본문 이미지:** `width:100%`, `height:auto`에 준하는 반응형 표시. 원본 비율을 유지하며 가로 스크롤·잘림 금지. 기존 Astro 이미지 파이프라인 사용 여부 확인.
- **390px 모바일:** 4~5개 카드의 작은 글씨가 실제 화면에서 읽히는지 확인. 읽히지 않으면 모바일용 2열/세로형 분리 이미지나 이미지 밖의 HTML 텍스트 제공을 우선 검토한다.
- **캡션:** 그림을 읽을 이유가 있는 경우 한 줄로 의미·적용 범위·`학습용 재구성` 여부를 안내한다. 같은 문구를 그림 안과 밖에 과도하게 반복하지 않는다.
- **alt:** `이미지` 같은 무의미한 표현 금지. 시각화하는 항목과 핵심 관계를 간결하게 설명. 본문 전체를 alt로 복사하지 않는다.
- **성능:** 원본 1448×1086 PNG는 마스터로 보관하고, 공개 시 WebP 등 최적화 형식·적절한 압축·실제 렌더 크기·로딩 속성·CLS 예약 공간을 점검한다. 화면 첫 대표 이미지는 LCP 후보이므로 지연 로딩 여부를 별도 판단한다.
- **저작권/출처:** 타사 원본 그래픽이나 로고를 그대로 가져오지 않는다. AI 재구성 이미지는 오해 소지가 있는 부분을 검수하고, 특정 현장 실측 도면처럼 소개하지 않는다.

#### 5.13.5 이미지 파일 관리 및 발행 검수

- 파일명: `01-facility-management-hero.webp` 등 **영문 kebab-case + 주제/역할**을 권장. 중복되지 않게 article ID나 slug와 연결한다. 본문에는 경로와 alt를 함께 작성.
- 원고 메타데이터: `heroImage`, `imageCredits/description` 등 기존 Astro frontmatter 스키마가 허용하는 필드만 실제 반영한다. 여기 적힌 파일명·예시 스키마는 프로젝트 확인 전까지 제안이다.
- 승인 후 변경: 사용자가 승인한 원본 5장은 바꾸지 않는다. 문구나 법령에 오류가 발견되면 **검증 결과를 우선 보고**하고 필요한 경우 사용자에게 이미지 재제작 승인을 구한다.
- QA: (1) 문장·표·이미지 서로 일치 (2) 기술 구조·조건·순서 검증 (3) 이미지 한글 오탈자 (4) 모바일 390px (5) PC 1440px (6) alt/caption (7) 이미지 용량·LCP/CLS (8) 경로/링크 (9) SNS 공유 미리보기 검토.
- **정확성 게이트:** 이미지 제작 완료 ≠ 원고 검증 완료 ≠ 사이트 적용 완료 ≠ 실서버 QA 완료. 각 단계는 실제 확인했을 때만 완료 표시.
- **승인된 이미지와 시안을 구별:** 1번 콘텐츠에서 승인된 5장은 레퍼런스이며, 2~5번 콘텐츠의 추가 이미지와 검토 패키지는 개별 승인 전까지 시안이다. 모든 신규 이미지가 자동으로 게시 승인된 것은 아니다.
- **시안 선별:** 글 주제와 다른 그림(예: ‘취업 비교’ 글에 ‘보일러 원리’ 이미지), 이미지 한 장에 본문 전체를 압축한 과밀 도식, 근거 없는 장단점 순위·수치·급여·휴무·정년을 포함한 그림은 채택하지 않는다. 재제작하거나 본문 표/카드로 옮긴다.
- **독립적으로 의미 검수:** 이미지가 본문과 다른 직무 구분·안전 절차·법적 자격 단계·고용형태의 우열을 암시하지 않는지 확인한다. 비교 항목 간 화살표는 **실제 순서·인과·전환이 입증되는 경우에만** 사용한다.
- **작은 글씨를 이미지에 가두지 않음:** 모바일 390px에서 여러 열의 텍스트가 읽히지 않으면 카드 수를 줄이거나 HTML 비교표를 병행한다. 이미지가 없어도 독자가 핵심 결론을 얻을 수 있어야 한다.

### 5.14 1~5번 콘텐츠 교정에서 확정된 공통 제작 워크플로 (v1.4 추가)

**적용 범위:** GetPassLab `시설의 모든 것` 신규·개정 기사 전반. 자격증 기출 원문·학습 챕터에는 기존 정본 가이드를 유지한다.

1. **원고 취지 확인:** 이 글이 답할 질문 1개, 독자에게 남길 판단 기준, 기존 글과의 중복을 확인한다. 구체적 근거가 필요한 내용은 공식 원문과 기준일을 기록한다.
2. **첫 화면 구성:** `H1(1개) → 핵심 요약(1~3개) → 대표 이미지 → 독자 상황에서 출발하는 도입부`를 기본으로 한다. 실제 템플릿에서 H1을 렌더링한다면 본문에 중복 생성하지 않는다.
3. **문체·교정:** 설명만 나열하기보다 독자의 상황 → 질문 → 정확한 설명 → 실제 판단의 흐름을 쓴다. 위트·비유는 의미를 분명히 하는 경우에만, 전문용어는 현실의 개념으로 다시 풀어 준다. 말투·맞춤법·중복어·과장·말줄임·문장 리듬을 검수한다.
4. **본문 시각 위계:** `H2`는 독립된 큰 질문, `H3`는 그 안의 상세 설명. 핵심 볼드는 필요한 섹션에 1~2문장 정도만, 중요한 제한조건을 함께 담는다. 비교표 아래에는 해석을 붙인다.
5. **줄바꿈·여백:** 문장별 강제 `<br>` 대신 의미가 바뀌는 위치에서 문단을 구분한다. PC/모바일 본문 행간과 H2/H3 여백은 5.11 목표값·현행 CSS와 대조하며 임의로 중복 적용하지 않는다.
6. **이미지 기획:** 대표 1장 + 주제 이해에 필요한 설명 이미지 2~4장을 권장 출발점으로 삼는다(장수 할당 목표가 아님). 각 이미지는 한 메시지만 맡고 실제 위치·대체텍스트·캡션·모바일 표시 방법을 미리 정한다.
7. **이미지 생성·채택:** 승인 스타일(4:3, 포레스트 그린/아이보리)로 초안을 만들되, 생성 결과를 주제·근거·한글·도식·수치·과밀도 관점에서 별도 검수한다. 오류 시 제외·교체한다. 최종 승인되지 않은 이미지를 게시하지 않는다.
8. **발행용·편집용 분리:** 공개 원고에는 독자가 이해·검증할 수 있는 사실·출처·기준일만 남기고, `EDITOR_NOTES`, 자체 판정, 미검증 수치, 내부 ‘자료 및 편집 기준’ 제목은 별도 메모로 관리한다.
9. **최종 패키지:** 개별 Markdown, 원본 PNG, 웹용 WebP, 이미지별 alt/캡션, HTML 미리보기, 편집·팩트체크 메모, 원고 상태표를 준비한다. 생성 파일·실행 테스트·브라우저 QA·배포 상태를 각각 분리해 보고한다.

**1~5번 콘텐츠 적용 기록(2026-10-31):** 1번 교정 및 승인된 이미지 5장, 2번 첫 취업 원고·이미지 검토, 3번 고용구조 비교 검토, 4번 근무·휴게·수당 구분 검토, 5번 공공부문 공고·보수 통계 비교 검토를 통해 위 공통 규칙을 정리했다. 2~5번 원고와 이미지의 **최종 발행 승인·Git 반영을 의미하지 않는다.**

### 5.15 GitHub 정본·문서 적용 범위 (v1.4 추가)

- **정본 하나:** GitHub 내 `시설의 모든 것` 콘텐츠 통합 가이드를 하나의 문서로 관리한다. `AGENTS.md`에서는 이 가이드로 연결하고, 사용자별 패키지 ZIP이나 복제본 여러 개를 정본으로 병행 유지하지 않는다.
- **프로젝트 공통 규칙 보호:** 기존 `docs/standards/learning-image-design-system-v1.md`는 자격증 학습 이미지의 정본으로 유지한다. `시설의 모든 것`의 **에디토리얼 이미지**는 본 5.13을 따른다. 두 영역이 교차하는 교육·설비 도식은 관련 기술 정확성·안전 규칙도 함께 적용한다.
- **명확한 경계:** 이미지 4:3·시설 영역 타이포그래피 목표값을 자격증 전체 페이지에 무조건 적용하지 않는다. 기존 Astro 템플릿·디자인 토큰을 확인한 뒤 시설 영역 범위에서만 통합한다.
- **문서 우선 반영:** 가이드 등록 및 `AGENTS.md` 참조 연결은 문서 작업이다. CSS 수치 확정·UI 수정·원고 일괄 재작성·이미지 재생성·공개 URL 변경·사이트 배포는 **별도 검토 또는 승인 대상**이다.
- **Git 절차:** 최신 `main`, `AGENTS.md`, `AI_HANDOVER.md`를 확인하고 별도 브랜치와 PR에서 변경한다. `main` 병합·push가 자동 배포로 이어질 수 있으므로 명시 승인 전 병합하지 않는다.

### 6.4 짧은 법 개정 콘텐츠의 사실검증 게이트

'이번에 바뀐 기준' 같은 문구를 쓰기 전에 **① 현재 시행 중인지 ② 공포·시행일이 각각 언제인지 ③ 적용 시설과 종사자 범위 ④ 경과조치·예외 ⑤ 소관기관 원문**을 확인한다.

- 검증 전: `검토 중 / 기준 미확인`으로만 관리하고 법령 확정 정보처럼 공개하지 않는다.
- 검증 후: 한 줄 결론과 출처 확인일을 함께 공개한다. 법령이 바뀌면 요약 카드뿐 아니라 상세 글과 내부 링크도 갱신한다.
- 법적 판단의 불확실성이 큰 경우: '3줄 핵심' 단독 발행을 미루고 원문 설명을 확보한다.

## 7. SEO·중복 콘텐츠·마이그레이션 원칙

1. 기존 10편은 URL과 주제가 확인된 **기존 발행 자산**으로 취급한다. 신규 글로 무작정 다시 복제하지 않는다.
2. GetPassLab에서 **최신 기준 재검증 + 모바일 가독성 개선 + 새로운 비교 기준**을 추가해 이전한다.
3. 티스토리와 GetPassLab 양쪽에서 동일한 본문을 장기간 별도 URL로 병행 공개하면 검색엔진 중복 문서 판단 가능성이 생긴다. 이전 시 원본 링크/이전 안내 및 가능한 경우 대표 URL(canonical/리다이렉트)을 검토한다.
4. 제목·메타설명은 새 페이지의 실제 내용과 검색의도에 맞춘다. 이미 다룬 동일 검색의도의 글을 키워드만 바꿔 여러 개 만들지 않는다.
5. `발행일(원본)`과 `업데이트일(현행 검증)`을 별도 표기한다. 내용에 2026년 채용사례가 남으면 제목·표·주석에도 그 기준연도를 표시한다.
6. 내부링크는 **기초 설명 → 기관 사례 → 법정선임 상세 → 경력 단계 → 자격증 학습**의 순서로 연결한다.
7. 본문 안에 `관련 글`을 문맥상 1~3개만 넣고 무관한 키워드 링크를 남발하지 않는다.

## 10. 운영용 요약 — GetPassLab 콘텐츠 작성자의 기본 프롬프트

> 너는 GetPassLab '시설의 모든 것'의 편집자다. 시설관리 취업·자격증 실무 활용·법정선임·채용공고·근무조건·경력성장을 다룬다. 검색자가 실제로 판단할 수 있게 정부·법령·기관 공고의 원자료를 우선 조사하고, 사업소·공고 차수·연도·필수/우대·선임·경력·급여·교대·정년을 구분하라. 원자료에 없는 사항은 추정하지 말고 확인 불가로 표시하라. 서두에 핵심 결론을 제시하며 H1 1개, H2 대분류, H3 세부 분류, 비교표와 표 아래 해석, 대상 독자별 준비 순서, 출처 및 확인일을 포함하라. 실제 경험이 없는 일을 경험담처럼 쓰지 말고, 자격증 보유=무조건 선임 가능이라고 단정하지 마라. 기존 발행 글과 검색의도가 중복되면 통합 또는 업데이트를 우선한다. GetPassLab '자격증의 모든 것'에서는 시험이론과 기출을 다루므로 이 영역은 취업·현장·선임 활용에 집중한다.
> 
> 추가 편집 원칙(v1.1): 초기 사이트는 **운영자 발행 중심의 편집형 정보 미디어**로 운영한다. 토스피드의 읽기 쉬운 위계를 참고하되 표현·자산·UI를 복제하지 않는다. 글은 검색자의 질문에 1~3문장으로 바로 답하고 짧은 문단·절제된 강조·필요한 비교표를 사용한다. 법령 변경은 **무엇이 바뀜 / 누구에게 적용 / 무엇을 확인**의 3줄 요약을 도입하되 시행일·예외·원문 근거를 본문에 반드시 담는다. 실무 위키는 **질문 → 한 줄 답 → 역할·판단 기준 → 주의 → 관련 문서**로 작성한다. 기사·채용·선임의 시점을 구분하고, 빈 커뮤니티·가짜 후기·근거 없는 출제/채용 확률·무의미한 다량 게시를 피한다. 모바일·PC QA는 실제 수행한 경우에만 완료로 기록한다.
>
> **추가 개정 원칙(v1.2):** 모든 아티클은 `H1 → 핵심 요약 → 대표 이미지 → 도입부 → H2 본문` 순서를 우선한다. `H1/H2/H3/본문`의 의미·스타일을 구분하고 PC/모바일 권장 크기는 5.11의 표를 따른다(실제 사이트 CSS 검증 전까지 목표값). 중요한 판단 문장은 섹션당 1~2개 정도를 선별해 볼드 처리하고, 법령·급여 조건의 예외·기준일도 함께 표시한다. 위트·일상 비유·서술 리듬으로 읽기 쉽게 쓰되 과장·거짓 체험담·기계적인 반복 요약을 피한다.
>
> **이미지 제작 원칙(v1.3):** 신규 시설 콘텐츠의 대표/본문 이미지에는 4:3 비율을 기본 적용하고, 포레스트 그린·오프화이트·라운드 카드 중심의 일관된 편집형 시각 언어를 사용한다. 글당 이미지 수는 고정하지 않는다. 이미지의 제목·도식·조건·화살표는 본문과 사실관계를 검증하고, 모바일 가독성과 alt·캡션·웹 이미지 최적화를 점검한다. 기존 티스토리 1:1과는 구분하며 실제 GetPassLab 목록 카드 비율 및 CSS는 구현 전에 확인한다.
>
> **검수·공통 운영 원칙(v1.4):** 문장마다 줄을 끊지 않고 의미 단위로 문단을 나눈다. 공개 본문에는 내부용 ‘자료 및 편집 기준’ 섹션을 만들지 않되 독자가 확인해야 할 공식 출처·기준일·예외는 명확히 제공한다. 이미지가 본문과 무관하거나 수치·우열·법적 순서를 왜곡하면 폐기/재제작하며, 정보가 많은 표는 HTML 본문으로 분리한다. 1번 승인 이미지와 2~5번 미승인 시안을 구분하고, 가이드 문서·실제 CSS·배포 상태를 별도 검증한다.

## 11. 별도 문서와 관리 방법

이 인계서는 전체 전략과 10편을 요약한다. 아래 경로는 **기존 인계 패키지의 구성 기록**이며, 이 저장소의 동일 폴더에 해당 파일들이 존재한다는 뜻은 아니다. `articles/*.md`는 인계 패키지의 각 글 **개별 콘텐츠 브리프**이고 `originalUrl`, `originalPublishedAt`, `sourceCheckedAt`, `factCheckStatus`, `proposedPath` 메타데이터를 포함한다.

**최종 원칙:** **실제 공고 → 사업장 설비 → 자격·법정선임 → 경력·근무조건 → 독자의 준비/선택**. 이 연결이 기존 콘텐츠의 차별점이다.

## 1. 그림을 만들기 전 결정할 것

그림을 제작하기 전에 아래 항목을 메모하고, 첫 문장으로 **캡션부터 작성**한다.

| 항목 | 필수 여부 | 작성 예시 |
|---|---|---|
| 챕터 제목·slug | 필수 | 통풍·연도·굴뚝 / draft-flue-gas |
| 연결 문제·학습 질문 | 필수 | 압입·흡입통풍은 팬이 어디에 있는가? |
| 그림 유형 | 필수 | 흐름형 / 비교형 / 구조·단면형 / 절차형 |
| 전달할 한 가지 핵심 | 필수 | FD는 앞에서 공기를 밀고 ID는 뒤에서 가스를 당김 |
| 검증 근거 | 필수 | 원본 기출·교재·공식 기술 자료·기존 본문 중 확인한 자료 |
| 구분해야 할 흐름·부품·상태 | 필수 | 연소용 공기, 배기가스, 연소실, 송풍기 |
| 원본 에셋·수정 이력 | 필수 | 사용자 제공 PNG → 공개 SVG / 수정 내용 |
| 시기 의존 조건 | 해당 시 | 기출 당시 법령·기준과 현행 기준 구분 |

그림의 역할을 설명하기 어려우면 일러스트를 추가하지 않는다. **원본 기출과 충돌하면 기출 원본/PDF를 우선 확인**하며, 정답·수치·부품 연결 관계를 추정하여 보완하지 않는다.

## 2. 표현 레벨과 그림 유형

### 표현 레벨
- **L1 개념 도식:** 위치·연결·방향만 보여주는 단순화 그림. 통풍 방식, 계통의 개요 등
- **L2 상세 기술 도식:** 장치의 식별 가능한 실제 형상·단면·부품·작동 단계를 보존. 트랩, 팽창탱크, 펌프 등
- **원본 유지형:** 실제 기출 도판·프로그램 캡처·안전표지처럼 재그리면 정보가 달라지는 그림. 크롭·주석이 필요하면 원본과 파생본을 구분

L1을 모든 이미지의 기본 표현으로 강제하지 않는다. **무엇을 구별하는 문제인지**에 따라 L1/L2를 선택한다. 실제 표준 기호가 아닌 교육용 재구성에는 `학습용 재구성` 표기. 법정 안전표지나 특정 규격의 기호는 임의로 색상·형태를 변경하지 않는다.

### 구성 유형
1. **흐름형:** 유체·에너지의 출발/경유/도착, 단방향 화살표. 예: 4가지 통풍
2. **비교형:** 동일한 비교 축으로 2~4개 대상을 반복 배치. 예: 개방형·밀폐식 팽창탱크
3. **구조·단면형:** 절개 위치·실제 부품 연결과 내부 차이를 중시. 예: 디스크 트랩
4. **절차형:** 시작 상태 → 전환 조건 → 종료 상태. 예: 수면계 기능시험

전체 계통도가 복잡하면 먼저 개요를, 다음 그림에서 급수·연소·배기가스처럼 **부분 경로를 별도로 확대**한다. 챕터당 그림 개수의 일률적인 상한은 두지 않는다. 단, 중복된 핵심 설명은 제거한다.

## 3. 시각 토큰 (v1 기본값)

색상의 우선순위는 **유체 의미**, **장치의 중립적 형상**, **상태/경고**를 구분하는 것. 흰 배경에서 아래 짙은 의미색은 일반 텍스트용 4.5:1 및 중요 그래픽용 3:1 대비 기준을 넘기도록 선정함(계산값, 실제 렌더링·조합은 별도 QA).

| 토큰 | HEX | 역할·사용 위치 |
|---|---|---|
| `fig.bg` | `#FFFFFF` | 주 배경 |
| `fig.bg-muted` | `#F7F9FC` | 장치 구획·연한 정보 상자 |
| `fig.text` | `#25334B` | 제목·장치명·라벨 |
| `fig.text-muted` | `#526176` | 보조 설명 |
| `fig.structure` | `#526176` | 실제 장치·배관 경계선 |
| `fig.border-decorative` | `#CBD5E1` | 정보 전달에 필수가 아닌 장식용 구분선 |
| `fig.medium.air` | `#1769AA` | 외기·연소용 공기 흐름 |
| `fig.medium.flue` | `#A94E32` | 연소가스·배기가스 흐름 |
| `fig.medium.water` | `#15785C` | 일반 물·급수·보일러수 |
| `fig.medium.steam` | `#734BA6` | 증기 흐름 |
| `fig.medium.condensate` | `#126D86` | 응축수·환수 |
| `fig.medium.fuel` | `#9B5A13` | 연료 공급(필요한 그림에만) |
| `fig.effect.heat` | `#B45309` | 열의 전달·가열 영역(연료와 반드시 문자 병기) |
| `fig.state.warning` | `#855400` | 주의 표시 + 주의 아이콘 |
| `fig.state.error` | `#90234B` | 오답·위험·잘못된 연결 + × 표시 |
| `fig.state.correct` | `#236E49` | 검증된 정상·정답 + ✓ 표시 |

**유체색은 '좋고 나쁨'을 표현하지 않는다.** 부압·양압은 빨강/초록으로 판정하지 말고 `부압(-)`, `양압(+)`의 문자 또는 게이지형 상태 배지로 표시한다. 붉은 계열 배기가스와 오답의 의미를 혼동하지 않도록 반드시 직접 라벨과 별도의 × 기호를 병기한다.

공식 시험 화면·법정 안전표지·규격 색상이 등장하면 원본/해당 표준의 색상을 우선한다. 이 팔레트로 임의 덧칠하지 않는다.

## 4. 기호·선·화살표 사용 규칙

- 송풍기(FD)와 유인통풍기(ID)는 **기본 팬 기호는 동일**하게 사용하고, *유체 종류·설치 위치·명칭*으로 역할을 구분. 팬 몸체를 유체 의미색으로 과도하게 칠하지 않음
- 펌프·탱크·버너·밸브는 재사용할 수 있는 공통 모양을 정의하되, 문제의 정답이 **부품 형태**에 달려 있으면 L2 실제 구조를 유지. 특정 밸브 형상을 모두 같은 마름모로 치환하지 않음
- 유체 흐름은 색상 + **직접 라벨** + 진행 방향을 모두 표시
- 실제 연결관과 흐름 화살표를 구분. 선의 교차를 접속으로 오해하지 않도록 **접속점은 ●**, 비교차는 이격 또는 점프 처리
- 실선 화살표: 해당 매체의 이동. 점선 화살표: 보조 설명·조건/가정 등 별도 범례가 있을 때만 사용. 서로 다른 뜻에 같은 점선을 중복 부여하지 않음
- 한 화살표에 양방향 화살촉을 기본 사용하지 않음. 실제 왕복·역류 여부가 문제라면 각 방향을 따로 표기
- 원칙적으로 표시된 최종 화면 기준 핵심 흐름선 **3 CSS px 이상**, 중요 연결선 **2 CSS px 이상**을 목표. 축소 화면에서 다시 검사
- L1 도식에서는 형광 효과·큰 그림자·장식적 불꽃보다 고대비 라벨과 필요한 부품 번호를 우선. L2 실물형 단면은 구조를 알아보는 데 필요한 강재 질감·화실 표현을 허용하되, 불꽃을 실제 가스 경로·화염 접촉·관내 유체로 오해할 수 없게 함

**표시 예시:** 파란 `연소용 공기 → FD 송풍기 → 연소실` / 적갈색 `연소실 → ID 유인통풍기 → 연돌`. 펌프/보일러 등 설비 전체 흐름도에서는 배관 연결의 기술적 정확성을 별도로 교차 검증한다.

## 5. 글꼴·정보 계층

권장 글꼴 스택: `Noto Sans KR, Apple SD Gothic Neo, Malgun Gothic, sans-serif` (서비스 제공 환경에서 실제 폰트 존재 여부 확인. 폰트 파일 동봉 금지).

**본문과 이미지의 역할 분리(필수):** HTML의 `figcaption`이 카드 제목·한 줄 설명을 담당한다. 이미지는 ① 기계/부품 라벨 ② 중요한 값·상태 ③ 유체·에너지 흐름과 방향을 보여준다. 카드 바로 아래 그림 안에 동일한 제목·부제를 다시 그리지 않는다. 기출 원본처럼 이미지 안 제목을 보존해야 하는 경우에는 이유를 별도로 기록한다.

| 요소 | **최종 표시 크기** 목표 |
|---|---:|
| 카드 제목(가능하면 HTML 캡션) | 17–20 CSS px |
| 핵심 부품·유체 라벨 | 14–16 CSS px 이상 |
| 상태·보조 라벨 | 가능하면 13–14 CSS px 이상 |
| 두껍고 긴 설명문 | 그림 밖 HTML로 이동 |

- **중복 문구 QA:** `figcaption`에 이미 있는 제목(예: `압입통풍`)과 설명(예: `앞의 FD 송풍기가 공기를 밀어 넣음`)을 이미지의 보이는 텍스트로 반복하지 않는다. 다만 장치명 `FD 송풍기`처럼 그림을 이해하는 데 필요한 직접 라벨은 유지한다.
- **범례 최소화:** 공기·배기가스 등 흐름이 색상과 직접 라벨·화살표로 충분히 구분된다면 하단에 같은 이름의 범례를 반복하지 않는다. 직접 라벨만으로 뜻을 식별하기 어렵거나 다른 의미의 기호가 여럿 있으면 범례를 유지한다.
- `AIR` 등 보조 영문 표기와 긴 경로 요약 상자는 기출 판단에 필요하지 않으면 생략한다. 제목을 지운 뒤 남은 빈 여백은 도식을 재배치하고 캔버스의 높이를 다시 계산해 정리한다. **무조건 작게 자르지 말고** 부품과 경로의 시각적 식별을 우선한다.
- `학습용 재구성` 표기는 이미지 안이나 인접 본문·캡션에서 독자가 확인할 수 있게 제공하되 동일한 문구를 반복 배치하지 않는다. SVG `title`·`desc`와 HTML `alt`는 접근성 설명이며, 일반 화면의 중복 제목과는 구분한다.

SVG 내부 좌표의 글자 크기와 스마트폰에서 최종 **렌더링되는 글자 크기는 다름**. 예를 들어 `viewBox width=560`에 `font-size=16`을 지정한 그림이 실제 가로 344px로 표시되면 글자 크기는 약 **9.8 CSS px**. 그러므로 단순히 SVG 안에서 `16px`로 적었다고 모바일 기준을 통과하지 않음.

그림에는 기출 원문을 왜곡하거나 시험용 중요 조건을 빠뜨리는 축약 금지. HTML 본문·캡션·그림에 같은 긴 설명을 3번 반복하는 것도 지양.

## 6. 모바일·PC 레이아웃과 에셋 규격

- 검증 기준 화면: **390px 뷰포트**를 필수로, 실제 콘텐츠 내부 너비를 측정해 그림을 검수. 보조로 320px와 태블릿/데스크톱 확인
- 새 L1 개념 도식은 모바일 표시를 먼저 고려해 `viewBox` 너비 **360~400 단위**를 출발점으로 제안. 유형에 따라 세로 길이는 자유롭게 조정
- 기존 원본 4:3 PNG는 내용이 충분히 읽히면 그대로 사용 가능. 강제로 16:9나 SVG로 바꾸지 않음
- 넓은 개요도·L2 복잡 도식은 **한 열로 표시하거나 확대 보기** 제공. 핵심 단어는 확대 없이 식별 가능해야 함
- 기존 `learning-visuals`는 데스크톱 2열/모바일 1열이므로 그림의 크기와 각 카드의 실제 너비를 모두 점검
- **PC·모바일 에셋 결정:** 동일한 그림을 양쪽 화면에서 읽을 수 있고 기술적 내용도 같으면 **한 파일을 공통 사용**한다. PC라고 기존 가로형 파일을 무조건 유지하거나, 모바일이라고 별도 세로형을 무조건 만들지 않는다. 실제 정보량·가독성 때문에 분리가 필요할 때만 반응형 `picture/source`를 사용하고 두 버전의 의미·라벨·경로를 대조한다.
- 최초 통풍 적용에 쓰인 **390×290 SVG는 성공적으로 적용한 사례의 크기이지 공통 고정 템플릿이 아니다**. 비교 축, 부품 수, 원본 비율에 따라 크기·가로세로비를 결정하고 320px·390px의 실제 렌더 크기와 PC 카드 너비에서 재검토한다.
- 이미지 최적화는 **핵심 가독성·글자 선명도**가 우선. SVG는 기술 도식에 적합하지만 구조 정보의 왜곡을 정당화하지 않음
- 사용자 제공 원본은 별도 보관하고, 공개용 파생본이 있다면 구별 가능한 명칭을 사용
- 장식 이미지와 달리 핵심 학습 이미지는 `alt` 필수. 복잡한 계통은 본문에 텍스트로도 흐름을 설명
- 레이아웃 이동 방지를 위해 이미지의 가로/세로 크기 또는 비율 지정

## 7. 원본 활용의 결정 규칙

1. 원본의 **기술적 정확성**을 먼저 확인
2. 원본이 정확하고 모바일에서 읽히면 **그대로 사용**
3. 긴 문구·라벨·여백만 문제면 **원본을 보존한 경미 수정**
4. 구조·연결·작동 원리에 오류가 있거나 모바일에서 구조 파악이 불가하면 **재제작**. 이때 원본에서 무엇을 유지·수정·삭제했는지 기록
5. 비교군 여러 장에는 동일한 확대율·팬 위치 기준·색·화살표 규칙 적용

정확성 검수의 최우선 항목: **이동 유체, 진행 방향, 배관 접속, 부품 기능, 열/압력/온도의 변화, 단계별 개폐 상태**.

### 실물형·AI 생성 그림의 작동 경로 게이트 (v1.2)

실물처럼 보이는 단면일수록 독자는 보이는 관·색·화살표를 실제 작동 경로로 해석한다. **장치의 종류만 구별할 구조 비교 그림인지, 처음부터 끝까지 따라갈 작동 원리도인지 제작 전 정하고 캡션·alt·본문에 같은 범위를 사용**한다. 구조 비교용 그림의 생략된 가스 반전부·배출관을 독자가 완성된 경로로 오해할 수 있으면, 무엇을 생략했는지 그림 바로 옆에 명시한다.

| 검수 대상 | 공개 전 통과 기준 | 실패 시 조치 |
|---|---|---|
| 부품의 연결 | 급수·증기·연소가스가 드나드는 출입구와 밸브·펌프·드럼·헤더의 연결을 원본과 기술 근거에 대조. 보이지 않는 연결을 추측해 화살표로 메우지 않음 | 정확한 연결을 알 수 없으면 화살표를 빼고 구조 비교용으로 범위를 제한하거나 재제작 |
| 유체의 상태·색 | **관로의 실제 연결 순서대로** 물→혼합물→증기 등의 변화를 추적. 화면의 좌우·상하를 따라 색을 반복하여 유체가 식거나 상이 되돌아가는 것처럼 보이지 않게 함. 빨강·주황은 관 밖 가열 표현인지 관 안 매체인지 직접 구분 | 같은 관로에서 상태색이 되돌아가면 중립색 관과 별도 흐름 라벨로 바꾸거나 오류가 없는 그림으로 재제작 |
| 방향과 작동 단계 | 시작점→중간 부품→종점, 순환이면 복귀까지 실제 관을 따라 손가락으로 추적. 화살표의 위치·방향·접속은 원본 또는 공식 기술 자료와 대조 | 생성 모델이 반복 관·굽힘을 잘못 연결하면 기술 흐름은 검증 가능한 SVG·HTML 화살표로 분리 |
| 실물형 디테일 | 생성된 볼트·노즐·불꽃·배기구를 근거 없는 실제 설계 사양처럼 읽히게 하지 않음. 화염 효과와 가열 공간은 수관 내부의 연소가스나 직접 화염 접촉을 뜻하지 않도록 검수 | 정답 판단에 불필요한 디테일은 흐리거나 빼고, 필요한 기술적 연결은 검증된 도식으로 표현 |
| 원본 대비 식별성 | 원본·후보를 같은 표시 폭에서 나란히 보고 제목을 가린 상태에서도 장치 형태와 시험 판별 부품을 구분할 수 있는지 확인 | 구조감이나 핵심 부품을 잃었다면 원본 재사용 또는 재제작 |

AI 생성 그림은 **정답이나 실제 배관의 증거가 아님**. 출처는 기출 원본, 제조사·기술 기관 자료 등에서 확인하고, 검수 기록에는 `확인한 관계 / 그림에서 생략한 관계 / 확인하지 못한 디테일`을 분리해 적는다. 이미지의 시각적 완성도와 기술적 타당성은 각각 별도로 판정한다.

## 9. 공개 전 QA 및 상태 관리

| 단계 | 통과 기준 | 증거 |
|---|---|---|
| A. 콘텐츠 정확성 | 원본 문제 및 신뢰할 근거와 장치·화살표·수치·문구가 일치, 오류·과장 없음. 실물형 그림의 출입구·연결·순환 복귀·관로를 따른 유체 상태를 §7의 게이트로 추적 | 문제 ID, 원본 자료, 연결·색 추적 메모 |
| B. 디자인·중복 QA | 의미색과 라벨 병기, 상태색 분리, 범례·교차선 모호성 없음. **HTML figcaption의 제목·부제를 이미지 안에 다시 쓰지 않았는지**, 직접 라벨과 범례가 불필요하게 반복되지 않는지 확인 | 본문/캡션/그림 동시 비교, 원본/파생본 비교 |
| C. 반응형 QA | 320px·390px 모바일과 PC의 실제 콘텐츠 너비에서 핵심 글자·화살표 식별, 가로 넘침·과한 빈 여백·왜곡 없음. 공통 에셋 또는 picture 분기 적절성 확인 | 모바일 및 데스크톱 화면 캡처(미실행 시 명시) |
| D. 웹 QA | 이미지 파일 200 응답, alt, width/height, 경로, 기존 URL/ID 유지. PC·모바일이 **의도한 이미지 파일**을 로드하는지 확인 | Test/Build 및 브라우저 확인 |
| E. 배포 검증 | Commit/Push/Deploy와 실제 Production 렌더링은 별도로 확인 | 커밋·워크플로·공개 페이지 |

`계획` → `이미지 제작` → `콘텐츠 검증` → `브라우저 QA` → `PR` → `Merge` → `Deploy` → `Production 확인`을 혼동하지 않는다. 원본 PNG를 기준으로 다시 만든 SVG라도 원본과 구조가 동일함을 따로 검증해야 한다.

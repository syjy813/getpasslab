# GetPassLab 디자인 가이드

- 버전: **v1.1 / 2026-10-29**
- 적용: 사이트의 공통 시각 요소, 페이지 레이아웃, 카드·버튼·태그, 학습 이미지 배치
- 확인 기준: 현행 `main`의 `src/styles/global.css`, `src/pages/index.astro`, `src/components/GNB.astro`, `src/components/Footer.astro`
- 별도 정본: 학습 이미지의 실제 도식·의미색·기술 검증은 [학습 이미지 디자인 시스템](learning-image-design-system-v1.md) 적용

## 1. 반드시 지킬 7가지

1. **정보 구조가 디자인보다 우선:** 독자가 가장 먼저 봐야 할 제목·결론·행동을 높은 위계로 배치
2. **기존 토큰과 컴포넌트 재사용:** 같은 기능에 새 색상·크기·카드 양식을 만들지 않음
3. **강조 요소 최소화:** 한 화면에서 여러 배지·버튼·색상 강조가 경쟁하지 않도록 배치
4. **텍스트 판독성 유지:** 모바일에서 줄이 끊기거나 내용이 과도하게 압축되지 않도록 조정
5. **행동과 상태의 시각적 의미 구분:** 주요 버튼은 행동, 배지는 상태·분류, 경고는 주의 정보에만 사용
6. **학습 그림 정확성 유지:** 기술적으로 필요한 연결·화살표·라벨을 장식이나 통일감을 이유로 삭제·왜곡하지 않음
7. **변경 영향 범위 확인:** 공통 CSS 수정은 모든 자격증·퀴즈·모달·푸터의 회귀 가능성을 확인

### 2-1. 글자 위계

| 역할 | 모바일(기본) | 768px 이상 | 적용 위치 |
| --- | ---: | ---: | --- |
| 메인 대형 제목 | 28px | 40px | 홈 히어로 등 |
| 일반 H1 | 24px | 32px | 목록/상세 화면 제목 |
| H2 | 20px | 24px | 주요 섹션 |
| H3 | 18px | 20px | 하위 섹션·카드 |
| 기본 본문 | 15px | 16px | 읽기 텍스트 |
| 보조 캡션 | 13px | 14px | 메타·상태 설명 |

- 제목 줄높이는 1.3, 기본 본문은 1.6을 출발점으로 함
- 본문의 **실제 HTML 제목 수준(H1~H3)**과 시각 스타일 클래스를 구분. 제목 크기만 맞추기 위해 의미상 잘못된 H 레벨을 사용하지 않음
- 한 카드에서 제목·설명·메타를 모두 굵게 만들지 않음. 강조할 내용에만 Bold 사용
- 긴 한국어는 자연스럽게 줄을 나누고, 기출·법령·자격 명칭의 의미를 말줄임으로 감추지 않음

## 3. 화면 구조·여백

### 기본 읽기 순서

`페이지 제목 → 한 줄 목적/결론 → 필요한 정보·선택 항목 → 주요 행동 → 참고/관련 콘텐츠`

- **홈·목록:** 소개 문구보다 탐색할 자격증 또는 콘텐츠가 명확하게 보이도록 구성
- **챕터:** 설명, 비교·그림, 연결 기출, 관련 챕터가 읽기 흐름을 방해하지 않도록 배치
- **콘텐츠 카드:** 이름 → 무엇을 제공하는지 → 검증 가능한 메타 정보 순서
- **정보 페이지(향후):** 질문·결론 → 조건 → 예외 → 확인할 출처 순서. 실제 서비스 구현 완료로 간주하지 않음

### 간격 사용

- 기본 단위 4px. 인접 요소는 보통 8~16px, 다른 정보 묶음은 24~48px 사이의 기존 토큰 우선 검토
- **같은 묶음은 가깝게, 다른 묶음은 멀게** 배치. 카드마다 여백을 무조건 크게 만들지 않음
- 큰 여백으로 텍스트 부족을 감추거나 카드 수를 늘리는 구성 지양
- 모바일에서는 읽기 가능한 실제 콘텐츠 폭을 확인. 외곽 여백만 계산하지 말고 카드 내부 패딩까지 확인

## 4. 컴포넌트별 판단

| 요소 | 사용 기준 | 피할 구성 |
| --- | --- | --- |
| 주요 버튼 | 한 단계의 핵심 행동을 나타냄 | 카드 전체·모든 링크를 같은 강한 버튼으로 표현 |
| 보조 버튼 | 닫기, 취소, 보조 동작 | 주 행동보다 강한 색·높이 |
| 카드 | 제목·설명·메타처럼 서로 관련된 정보를 묶음 | 하나의 문장만 넣기 위해 불필요한 박스 생성 |
| 배지·태그 | 실제 분류, 상태, 확인된 빈도 | 장식용 ‘핵심’, ‘필수’ 남발, 근거 없는 최빈출 |
| 표 | 비교 축이 명확한 2개 이상 조건 정리 | 모든 개념을 표로 만들거나 같은 내용을 본문에 반복 |
| 정보·주의 박스 | 정답·안전·적용 조건을 반드시 구분해야 할 때 | 같은 정보 강조를 위해 회색·노란색 상자 중첩 |
| 그림 카드 | 위치·연결·작동 경로 등 시각적 설명이 필요한 때 | 제목·본문·그림에 같은 서술 세 번 반복 |
| 구분선 | 큰 섹션 사이를 정리할 때 | 단순 문장마다 테두리를 넣는 방식 |

### 공통 상태 표현

- 성공·정답 / 오류·오답 / 경고·미응답은 각각 의미를 갖고 표시하되 **색상만으로 전달하지 않음**
- 상태 변경 전후의 굵기·아이콘·텍스트 라벨 등도 고려. 구체적 처리 방식은 [UX/UI 가이드](ux-ui-guide.md) 참고
- 실제 시험 UI에서는 정답 여부에 따라 색상을 쓸 수 있으나, 공식 시험·법정 안전표지의 규정 색을 임의 변경하지 않음

## 5. 학습 이미지 — 현행 정본을 우선

학습 이미지에는 일반 사이트 색상과 별개의 **의미색 체계**가 있음. 예를 들어 물·증기·배기가스·정답/오답을 사이트 기본 파란색 하나로 대체하지 않음.

제작 전 결정:
1. 독자가 **무엇을 구별해야 하는지** 질문 한 문장 작성
2. L1 개념 도식 / L2 상세 기술 도식 / 원본 유지형 중 선택
3. 기출 원본·교재·공식 기술 자료와 기술적 관계 대조
4. 캡션은 HTML, 이미지 내부는 장치명·상태·화살표·필수 수치 위주
5. 320px·390px 실제 표시 폭에서 **라벨의 최종 렌더 크기** 확인. 확대가 필요하면 확대 UI 추가
6. 원본과 파생본, 모바일·PC 에셋의 차이와 검증 결과 기록

모든 이미지를 강제로 동일한 비율·SVG 규격으로 변환하지 않음. 원본이 정확하고 읽히면 재사용.

## 6. 반응형 디자인·접근성

- **검토 화면:** 320px, 390px, 768px, 1024px, 1440px. 변경 영역의 실제 화면에서 확인할 기준
- **레이아웃:** 현행 그리드는 640px·1024px 등에 따라 열 수가 달라짐. 모바일에서 열 수만 줄이지 말고 텍스트·그림 내부 폭도 확인
- **터치·키보드:** 주요 컨트롤의 목표 크기 44px, 초점 표시·대비·키보드 동작 확인
- **대비:** 일반 텍스트 4.5:1, 큰 텍스트 3:1, 중요한 UI 그래픽 3:1을 접근성 점검 기준으로 사용. 새로운 배색은 실제 조합에서 재검산
- **확대:** 그림을 눌러 확대한 후에도 제목·상태·닫기 기능이 식별돼야 함
- **광고:** 광고 영역은 콘텐츠 및 주 행동과 혼동되거나 탐색·모달을 가리지 않아야 함

## 7. 다음 작업에서 적용할 변경 절차

1. 대상 화면·역할·문제점과 **현재 스크린샷 또는 구현 파일** 확인
2. 기존 디자인 토큰·컴포넌트로 해결되는지 먼저 판단
3. 바꿀 요소(예: 제목 크기/여백/상태 표시)와 유지 요소(URL·ID·로직)를 구분
4. 필요할 때만 신규 토큰·컴포넌트 정의하고 예외·재사용 가능성 명시
5. 모바일·PC 및 공통 컴포넌트를 쓰는 다른 페이지 회귀 점검
6. 변경 파일, 브라우저 QA 조건, 미확인 사항과 배포 상태 기록

### 적용 완료 기준
- [ ] 같은 역할의 화면들이 같은 시각 규칙을 사용함
- [ ] 제목·본문·그림의 중복 설명이 없음
- [ ] 320/390px에서 중요 글자·그림을 읽을 수 있음
- [ ] 상태가 색상 외의 수단으로도 구분됨
- [ ] 기존 주요 흐름·공개 경로가 보호됨
- [ ] 실제 확인한 환경·결과와 미실행 항목을 구분함

- 버전: **v1.3 / 2026-10-29**
- 적용: 사이트의 공통 시각 요소, 페이지 레이아웃, 카드·버튼·태그, 학습 이미지 배치

- 별도 정본: 학습 이미지의 실제 도식·의미색·기술 검증은 [학습 이미지 디자인 시스템](learning-image-design-system-v1.md) 적용

## 1. 반드시 지킬 7가지

1. **정보 구조가 디자인보다 우선:** 독자가 가장 먼저 봐야 할 제목·결론·행동을 높은 위계로 배치
2. **기존 토큰과 컴포넌트 재사용:** 같은 기능에 새 색상·크기·카드 양식을 만들지 않음
3. **강조 요소 최소화:** 한 화면에서 여러 배지·버튼·색상 강조가 경쟁하지 않도록 배치
4. **텍스트 판독성 유지:** 모바일에서 줄이 끊기거나 내용이 과도하게 압축되지 않도록 조정
5. **행동과 상태의 시각적 의미 구분:** 주요 버튼은 행동, 배지는 상태·분류, 경고는 주의 정보에만 사용
6. **학습 그림 정확성 유지:** 기술적으로 필요한 연결·화살표·라벨을 장식이나 통일감을 이유로 삭제·왜곡하지 않음
7. **변경 영향 범위 확인:** 공통 CSS 수정은 모든 자격증·퀴즈·모달·푸터의 회귀 가능성을 확인

### 2-1. 글자 위계

| 역할 | 모바일(기본) | 768px 이상 | 적용 위치 |
| --- | ---: | ---: | --- |
| 메인 대형 제목 | 28px | 40px | 홈 히어로 등 |
| 일반 H1 | 24px | 32px | 목록/상세 화면 제목 |
| H2 | 20px | 24px | 주요 섹션 |
| H3 | 18px | 20px | 하위 섹션·카드 |
| 기본 본문 | 15px | 16px | 읽기 텍스트 |
| 보조 캡션 | 13px | 14px | 메타·상태 설명 |

- 제목 줄높이는 1.3, 기본 본문은 1.6을 출발점으로 함
- 본문의 **실제 HTML 제목 수준(H1~H3)**과 시각 스타일 클래스를 구분. 제목 크기만 맞추기 위해 의미상 잘못된 H 레벨을 사용하지 않음
- 한 카드에서 제목·설명·메타를 모두 굵게 만들지 않음. 강조할 내용에만 Bold 사용
- 긴 한국어는 자연스럽게 줄을 나누고, 기출·법령·자격 명칭의 의미를 말줄임으로 감추지 않음

## 3. 화면 구조·여백

### 기본 읽기 순서

`페이지 제목 → 한 줄 목적/결론 → 필요한 정보·선택 항목 → 주요 행동 → 참고/관련 콘텐츠`

- **홈·목록:** 소개 문구보다 탐색할 자격증 또는 콘텐츠가 명확하게 보이도록 구성
- **챕터:** 설명, 비교·그림, 연결 기출, 관련 챕터가 읽기 흐름을 방해하지 않도록 배치
- **콘텐츠 카드:** 이름 → 무엇을 제공하는지 → 검증 가능한 메타 정보 순서
- **정보 페이지(향후):** 질문·결론 → 조건 → 예외 → 확인할 출처 순서. 실제 서비스 구현 완료로 간주하지 않음

### 간격 사용

- 기본 단위 4px. 인접 요소는 보통 8~16px, 다른 정보 묶음은 24~48px 사이의 기존 토큰 우선 검토
- **같은 묶음은 가깝게, 다른 묶음은 멀게** 배치. 카드마다 여백을 무조건 크게 만들지 않음
- 큰 여백으로 텍스트 부족을 감추거나 카드 수를 늘리는 구성 지양
- 모바일에서는 읽기 가능한 실제 콘텐츠 폭을 확인. 외곽 여백만 계산하지 말고 카드 내부 패딩까지 확인

## 4. 컴포넌트별 판단

| 요소 | 사용 기준 | 피할 구성 |
| --- | --- | --- |
| 주요 버튼 | 한 단계의 핵심 행동을 나타냄 | 카드 전체·모든 링크를 같은 강한 버튼으로 표현 |
| 보조 버튼 | 닫기, 취소, 보조 동작 | 주 행동보다 강한 색·높이 |
| 카드 | 제목·설명·메타처럼 서로 관련된 정보를 묶음 | 하나의 문장만 넣기 위해 불필요한 박스 생성 |
| 배지·태그 | 실제 분류, 상태, 확인된 빈도 | 장식용 ‘핵심’, ‘필수’ 남발, 근거 없는 최빈출 |
| 표 | 비교 축이 명확한 2개 이상 조건 정리 | 모든 개념을 표로 만들거나 같은 내용을 본문에 반복 |
| 정보·주의 박스 | 정답·안전·적용 조건을 반드시 구분해야 할 때 | 같은 정보 강조를 위해 회색·노란색 상자 중첩 |
| 그림 카드 | 위치·연결·작동 경로 등 시각적 설명이 필요한 때 | 제목·본문·그림에 같은 서술 세 번 반복 |
| 구분선 | 큰 섹션 사이를 정리할 때 | 단순 문장마다 테두리를 넣는 방식 |

### 공통 상태 표현

- 성공·정답 / 오류·오답 / 경고·미응답은 각각 의미를 갖고 표시하되 **색상만으로 전달하지 않음**
- 상태 변경 전후의 굵기·아이콘·텍스트 라벨 등도 고려. 구체적 처리 방식은 [UX/UI 가이드](ux-ui-guide.md) 참고
- 실제 시험 UI에서는 정답 여부에 따라 색상을 쓸 수 있으나, 공식 시험·법정 안전표지의 규정 색을 임의 변경하지 않음

## 5. 학습 이미지 — 현행 정본을 우선

학습 이미지에는 일반 사이트 색상과 별개의 **의미색 체계**가 있음. 예를 들어 물·증기·배기가스·정답/오답을 사이트 기본 파란색 하나로 대체하지 않음.

제작 전 결정:
1. 독자가 **무엇을 구별해야 하는지** 질문 한 문장 작성
2. L1 개념 도식 / L2 상세 기술 도식 / 원본 유지형 중 선택
3. 기출 원본·교재·공식 기술 자료와 기술적 관계 대조
4. 캡션은 HTML, 이미지 내부는 장치명·상태·화살표·필수 수치 위주
5. 320px·390px 실제 표시 폭에서 **라벨의 최종 렌더 크기** 확인. 확대가 필요하면 확대 UI 추가
6. 원본과 파생본, 모바일·PC 에셋의 차이와 검증 결과 기록

모든 이미지를 강제로 동일한 비율·SVG 규격으로 변환하지 않음. 원본이 정확하고 읽히면 재사용.

## 6. 반응형 디자인·접근성

- **검토 화면:** 320px, 390px, 768px, 1024px, 1440px. 변경 영역의 실제 화면에서 확인할 기준
- **레이아웃:** 현행 그리드는 640px·1024px 등에 따라 열 수가 달라짐. 모바일에서 열 수만 줄이지 말고 텍스트·그림 내부 폭도 확인
- **터치·키보드:** 주요 컨트롤의 목표 크기 44px, 초점 표시·대비·키보드 동작 확인
- **대비:** 일반 텍스트 4.5:1, 큰 텍스트 3:1, 중요한 UI 그래픽 3:1을 접근성 점검 기준으로 사용. 새로운 배색은 실제 조합에서 재검산
- **확대:** 그림을 눌러 확대한 후에도 제목·상태·닫기 기능이 식별돼야 함
- **광고:** 광고 영역은 콘텐츠 및 주 행동과 혼동되거나 탐색·모달을 가리지 않아야 함

## 7. 다음 작업에서 적용할 변경 절차

1. 대상 화면·역할·문제점과 **현재 스크린샷 또는 구현 파일** 확인
2. 기존 디자인 토큰·컴포넌트로 해결되는지 먼저 판단
3. 바꿀 요소(예: 제목 크기/여백/상태 표시)와 유지 요소(URL·ID·로직)를 구분
4. 필요할 때만 신규 토큰·컴포넌트 정의하고 예외·재사용 가능성 명시
5. 모바일·PC 및 공통 컴포넌트를 쓰는 다른 페이지 회귀 점검
6. 변경 파일, 브라우저 QA 조건, 미확인 사항과 배포 상태 기록

### 적용 완료 기준
- [ ] 같은 역할의 화면들이 같은 시각 규칙을 사용함
- [ ] 제목·본문·그림의 중복 설명이 없음
- [ ] 320/390px에서 중요 글자·그림을 읽을 수 있음
- [ ] 상태가 색상 외의 수단으로도 구분됨
- [ ] 기존 주요 흐름·공개 경로가 보호됨
- [ ] 실제 확인한 환경·결과와 미실행 항목을 구분함

## 8. 토스피드 비교 기반 디자인 결정 (v1.2)

### 8-1. 관찰한 사실과 도입할 원칙의 구분

| 참고 사이트에서 확인한 정보 구조 | GetPassLab에 적용할 설계 규칙 | 도입하지 않을 것 |
| --- | --- | --- |
| 상단에 '토스피드 에디션 / 금융의 모든 것 / 토스의 모든 것 / 금융 계산기'라는 영역 구분 | 브랜드 아래에서 서비스 영역을 먼저 구분하고, 서비스마다 별도 하위 탐색 제공 | 토스피드의 메뉴명·브랜드 아이덴티티 직접 차용 |
| 금융 콘텐츠 영역에 추천 아티클과 주제 분류/목록이 별도로 있음 | 시설관리 홈은 대표 정보 글과 주제 목록을 구분. 자격증 홈은 자격증 선택과 학습 기능을 우선 | 모든 페이지를 동일한 기사 카드 그리드로 만드는 방식 |
| 아티클 페이지에 제목, 날짜, 작성자/소요 시간, 소제목별 본문이 구분됨 | 시설관리 정보 글의 제목·출처·기준일·본문 위계를 명확히 | 확인하지 않은 읽기 시간·작성자·업데이트일 생성 |
| 토스의 UX Writing 원칙은 문장·화면·화면 간 반복 제거를 설명함 | 같은 설명을 배지·카드 설명·본문·캡션에 중복 배치하지 않음 | 단순 글자 수 축소를 디자인 개선이라고 간주 |

위 항목은 **웹페이지에서 확인한 정보 구조와 공식 글쓰기 원칙**을 바탕으로 한 설계 결정임. 토스피드 CSS 값, 정확한 여백·픽셀·애니메이션을 분석하거나 동일하다고 판정한 것은 아님. 기존 GetPassLab 색상·폰트·토큰은 유지하며 변경은 별도 승인과 코드 검증 후 적용.

### 8-2. 화면 유형별 권장 구성 — 아직 구현하지 않은 제안

| 유형 | 정보 위계 | 주요 구성 요소 | 검수 포인트 |
| --- | --- | --- | --- |
| 서비스 공통 GNB | 브랜드 → 서비스 구분 → 해당 영역 탐색 | 두 서비스 선택, 현 위치, 모바일 메뉴 | 현재 영역 확인·작은 화면 넘침·기존 URL 보호 |
| 시설관리 콘텐츠 홈 | 사용자 관심 주제 → 주요 정보 → 주제별 글 목록 | 소수의 대표 콘텐츠, 주제 분류, 기사 카드 | 홍보성 문장보다 글 제목·주제·기준일 우선 |
| 시설관리 아티클 | 제목 → 한 줄 결론 → 기준일/근거 → 조건·비교·예외 | 읽기 폭을 제한한 본문, 소제목, 표, 관련 글 | 법령·선임 기준을 숨기지 않음 |
| 자격증 홈 | 자격증 선택 → 학습 범위 → 챕터/기출 | 기존 자격증 카드·과목·문제풀이 진입 | 기사형 추천 콘텐츠 때문에 학습 시작이 멀어지지 않음 |
| 자격증 챕터 | 한 줄 개념 → 예시·그림 → 연결 문제 → 관련 챕터 | 학습 본문과 기존 문제 UI | 출제 판단·정답·문항 ID 유지 |

### 8-3. 컴포넌트 수정 방향

- **GNB:** 두 서비스의 활성 상태와 해당 영역의 탐색을 시각적으로 구분. 단순 색상만이 아니라 위치·텍스트·접근성 상태로도 알림
- **홈/카드:** 카드 제목이 주 정보, 설명은 실제 제공 내용, 보조 정보는 필요할 때만. 빈 공간을 채우기 위한 배지·요약 삭제
- **아티클:** 하나의 주제에서 여러 화면에 나눠 설명하지 말고 제목·첫 문단·관련 소제목이 스캔 가능하도록 구성
- **학습 화면:** 정보 위계를 다듬더라도 기존 문제 레이어·정답 표시·하단 학습 탐색은 역할에 맞게 유지
- **이미지:** 토스피드의 사진·일러스트를 복제하지 않음. GetPassLab의 기술 도식과 이미지 정본을 우선

### 8-4. 시각 개편 전후 비교 기준

1. 실제 작업 대상의 **현재 캡처**를 390px·1440px에서 확보(가능하면 320px 보조)
2. 제목·CTA·카드 메타·섹션의 읽기 순서를 전후 비교
3. 원래 있던 문제 링크·카드 클릭·GNB·푸터가 여전히 동작하는지 확인
4. 새 색상·글꼴·여백을 도입할 때는 기존 토큰으로 불가능한 이유를 변경 기록에 남김
5. 화면 개선 여부는 **독자가 더 빨리 목적을 파악하고 행동할 수 있는지**로 검수. 외부 서비스와 시각적 유사도만으로 합격 처리하지 않음

**UI 작업 자체는 이 문서의 범위 밖임.** 아래 부록의 근거는 '참고 분석'과 '적용 결정'을 구분해 기록.

## 9. 토스피드 실제 자료 재검증 후 디자인 보완 (v1.3)

**근거 문서:** [토스피드 비교 재검증 기록](../audits/2026-10-29-tossfeed-reference-revalidation.md). 이번 검증은 공개 페이지·연결된 Chrome 탭의 텍스트/마크업과 GetPassLab 실제 CSS 확인에 한정. **PC/모바일 화면 캡처와 픽셀 실측은 아직 미실행.**

### 디자인에 반영할 것

| 화면 | 확인된 참고 사실 | GetPassLab 자체 설계 기준 | 확정 전 필요한 검증 |
| --- | --- | --- | --- |
| 공통 헤더 | 토스피드는 콘텐츠 주제/영역/도구를 상단에서 구분 | '시설의 모든 것 / 자격증의 모든 것'을 별도 **서비스 선택**으로 설계할 수 있음. 이는 GetPassLab의 결정이지 토스피드와 동일 구현은 아님 | 1440/390/320px에서 서비스명 길이·현재 위치·포커스 |
| 시설 홈 | 토스피드 메인에는 이 주의 콘텐츠, 인기 콘텐츠, 시리즈·필진 링크가 있음 | 대표 콘텐츠 영역·주제별 목록을 분리하되 데이터가 부족할 땐 억지로 채우지 않음 | 카드 제목/썸네일·메타·배지·링크 확인 |
| 시설 목록 | 금융 카테고리는 '추천 아티클'과 전체/뉴스/라이브러리/라이프/영상/인터뷰 분류·페이지 탐색을 가짐 | 시설 글의 실제 카테고리에 맞춘 분류를 사용하고 필요한 경우에만 추천·필터 도입 | 분류 필터·카드·모바일 터치 검증 |

| 자격증 학습 | 토스피드와 목적이 다름 | 카드·타이포그래피의 가독성만 제한적으로 개선. 기존 정답·기출 UI 유지 | 모든 자격증 대표 챕터 회귀 검증 |

### 디자인 숫자를 임의로 복제하지 않음

- '토스와 동일한 글꼴/회색/간격/카드 크기'는 외부 CSS 실측 없이 **채택 불가**
- GetPassLab 현재 CSS의 Pretendard·간격·명도·콘텐츠 폭이 기존 기준. 변경하려면 전후 스크린샷과 읽기·탐색 개선 근거를 첨부
- 새 카드에서 이미지 비율은 실제 콘텐츠 형식과 썸네일 존재 여부로 결정. 모든 카드의 동일 비율이나 썸네일 강제 금지
- 시각적 유사성보다 **독자 선택 가능성·실제 정보량·가독성**으로 평가

### 시각 QA 통과 전에는 확정하지 않을 항목

1. 토스피드와 GetPassLab 각각 PC 1440px, 모바일 390/320px 동일 조건 화면을 캡처
2. 실제 GNB 높이, 콘텐츠 폭, 카드 열 수·간격, 타이포그래피 계층, 이미지 비율·텍스트 넘침을 직접 비교
3. 보이는 메뉴와 숨김/중복 마크업을 구분. DOM에 버튼이 존재한다는 이유로 시각적·상호작용 QA PASS 처리 금지
4. '참고할 디자인 원리'와 '실제로 적용할 CSS 변경값'을 따로 승인·기록

## 2026-10-29 Cloud Browser 후속 보완 — v1.3

근거: [Cloud QA §4·§5](../audits/2026-10-29-tossfeed-cloud-browser-qa.md), [구현 제안](../audits/2026-10-29-tossfeed-ui-implementation-proposal.md). 코드 토큰 표는 유지한다.

1. nav 64px와 border 포함 header 65px은 다른 측정 대상이다. 일반문단·절차·표·캡션의 실제 스타일을 따로 확인한다. 소방 절차 일부는 14px, 일반 본문은 16px로 관찰됐으므로 하나의 body 토큰으로 모든 본문 크기를 대표하지 않는다.
2. 토스 정보형 일반문단 700px, GetPassLab article 880px·일반문단 800px을 확인했다. 시설정보 읽기 열을 따로 설계하고 학습 표·공식·도식을 기사 폭에 일괄 축소하지 않는다.
3. 카드 최초 로드·필터·뒤로가기·재진입·재로드와 긴 제목·이미지 없음 상태를 함께 검사한다. 텍스트의 bounding width와 실제 카드 클릭 영역의 폭을 구분한다. 토스의 일시적 비균등 폭을 채택할 규칙으로 해석하지 않는다.
4. viewer 열림/닫힘과 실제 확대 효용은 별도 검사다. 에너지 본문430px→viewer390px 사례와 소방의 큰 그림 viewer를 구분한다.
5. 비슷한 회색·폰트색은 동일 UX라는 증거가 아니다. 기존 토큰·학습 의미색·원본·alt·비율을 보존한다.

측정은 기본 Cloud 1363×936의 관찰이다. 지정 폭 QA 전 공통 토큰 수치를 확정하지 않는다. 상세 후보 수치는 구현 제안의 **GetPassLab 자체 설계 후보**로 유지한다.

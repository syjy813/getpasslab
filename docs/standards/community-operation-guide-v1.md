## 1. 목적·적용 범위·문서 관계

커뮤니티 기획·운영·기능 도입·유지·변경을 사용자 가치와 운영 효율에 비추어 판단하는 정본이다. 이론의 수나 기능 수보다 **독자가 근거를 이해하고 실제 취업·선임·현장 판단에 활용하는가**를 우선한다.

현재의 운영자 발행형 정보 미디어와 향후 검토할 회원 참여형 커뮤니티를 구분한다. 아래 회원·기여·모더레이션 기준은 해당 기능을 승인받은 뒤 운영 설계를 구체화할 때 사용한다. 이 문서 자체는 회원가입·댓글·게시판·랭킹·정책 적용을 승인하지 않는다.

## 2. 운영 목표와 근거 판독법

### 2.1 단계별 운영 목표

| 단계 | 우선 가치 | 성공의 근거 | 다음 단계 검토 조건 |
|---|---|---|---|
| 현재: 운영자 발행 | 정확한 설명, 조건 비교, 필요한 글 탐색 | 독자 과업 관찰·오류 수정·출처 최신성·주제별 탐색 데이터 | 기존 글 보완으로 해결하기 어려운 반복 질문·정보 공백 확인 |
| 선택적 참여 접수 검토 | 정정·질문·현장 맥락을 받아 검증된 지식으로 환류 | 처리 가능한 접수량, 유효 질문·정정, 실제 반영 결과 | 담당자·검증·회신·보관 범위와 비용 정의, 별도 실행 승인 |
| 회원 참여형 검토 | 지속 가능한 상호 도움과 지식 축적 | 유효 기여·해결·재참여, 피해·처리 부담을 함께 관찰 | 신고·수정·이의 처리·스팸 대응·운영 여력 확보, 별도 승인 |

단계는 필수 성장 코스가 아니다. 참여형 전환의 순편익이 작으면 편집형 미디어를 유지한다. 자격증 학습 영역의 기출·학습 성과와 시설 영역의 취업·현장 판단 성과도 섞지 않는다.

### 2.2 근거와 판단의 표시

- **[이론]** 개념·메커니즘·예측. 특정 UI의 효과 증명이 아님.
- **[연구 결과]** 연구 대상·설계·관찰 결과. 실험의 인과 범위와 관찰연구의 연관성을 구별한다.
- **[GPL 추론]** GetPassLab에 맞춘 해석·권고. 현지 효과는 미검증이다.
- **[실험 후보]** 비교·측정 후 채택 여부를 정할 가설. 적용 승인이나 일정이 아니다.
- **[현지 데이터]** 대상·기간·정의·수집 누락을 확인한 GetPassLab 측정. 논문의 수치와 별도 관리한다.

원칙 분류는 다음과 같다. **A라는 이유로 개별 기능의 효과가 검증됐다고 쓰지 않는다.**

| 분류 | 판단 기준 |
|---|---|
| A. 핵심 운영 원칙 | 연구·이론과 기존 프로젝트 기준이 일관되고 현재 운영 판단에 적용 가치가 높음. 구체적인 구현 효과는 별도 검증 |
| B. 조건부 운영 원칙 | 회원 구조·상호작용·운영 용량 등 선행 조건에 따라 적용. 현재 미구현 기능의 도입 근거로 단독 사용 금지 |
| C. 실험 후보 | 카피·노출·요청·정렬 등 실제 개입의 효과·비용을 현지 데이터로 확인해야 함 |

이번 검토는 아래 6개 관점에 맞춘 목적 중심 문헌 검토이며 체계적 문헌고찰·메타분석이 아니다. 원저·학술지·저자/대학 공개본·주요 연구기관 자료를 우선하고 연구방법·결과·한계를 확인했다. 한국 시설관리 독자를 대상으로 한 직접 효과 연구를 확보한 것으로 주장하지 않는다. 고전 연구의 시기·플랫폼 차이와 성공 사례 선택 편향을 고려한다.

## 5. 콘텐츠·참여·신뢰·관리 기준

### 5.1 콘텐츠와 지식 재사용

- 시설 가이드의 출처 우선순위·공식 수치 검증·집필·이미지·SEO 규칙을 재사용한다. 연구용 참고문헌을 공개 원고에 기계적으로 붙이지 않는다.
- 용어 글은 현장에서 쓰는 뜻·오해·적용 범위·상세 기준으로 연결한다. 비공식 약칭과 법정 자격·선임 상태를 혼동시키지 않는다. 신규 글·URL 생성은 별도 요청 범위에서 판단한다.
- 시설 이야기의 후기·절망/희망 사례는 표본·시기·설비·인력·고용 맥락에 따라 달라진다. 독립 사례 수, 재인용, 확인 불가 자료를 구분한다. 운영자의 직접 경험이나 회원 증언으로 꾸미지 않는다.
- 반복 질문은 기존 문서 보완·내부 연결로 해결 가능한지 먼저 본다. 상호작용이 필요한 사유를 확인하기 전에 게시판을 기본 해법으로 삼지 않는다.
- 출처 목록을 숨기는 기존 시리즈 예외를 이번 문서로 변경하지 않는다. 추후 편집 시 독자가 판단에 필요한 근거를 찾을 수 있는지는 시설 가이드와 함께 검수한다.

### 5.2 참여 기능을 검토할 때

접수 목적(정정/질문/경험 공유), 공개 범위, 검증·응답 담당, 처리 가능한 물량, 철회·수정 범위를 먼저 정한다. 실명·직장명 공개를 참여의 기본 조건으로 삼지 말고 필요한 맥락을 최소 항목으로 정한다. 개인정보·법적 쟁점은 실제 설계 시 최신 공식 기준을 별도로 검토하며 이 문서를 법률 근거로 쓰지 않는다.

‘유효 기여’는 **질문이면 답할 수 있는 맥락, 정정이면 확인할 수 있는 주장·근거, 사례면 범위를 식별할 수 있는 정보**가 있는 접수로 정의한다. 형식 충족은 정확성 검증 완료와 다르다. 단순 글 수·좋아요·자격증 개수를 유효성으로 대체하지 않는다.

### 5.3 신뢰와 권위

공식 확인 사실 / 특정 시점·사업장의 경험 / 편집 해석 / 미확인을 구분한다. 고경력자·다수 의견·인기글도 개별 주장 검증을 대체할 수 없다. 채용·선임·안전 관련 이견은 인기투표로 확정하지 않고 소관 원문을 대조한다. AI가 작성한 요약·답변도 같은 검증 책임을 적용한다.

### 5.4 관리 체계의 사전 설계

현재는 발행·정정 책임의 문서 판단 기준으로 사용한다. 아래는 **참여형 기능 승인 후 구체화할 설계 항목**이며 이번에 공개 정책이나 실제 제재로 적용하지 않는다.

| 처리 유형 | 사전 설계할 기준 | 운영 기록·관찰 |

| 사실 오류·오래된 정보 | 검증 담당·원문·영향 범위, 정정 내용·시점과 관련 글 갱신 | 접수~판정~수정 시간, 재발 여부 |

## 6. 기능 도입·유지·변경 의사결정

### 6.1 판단 순서

1. **문제 확인:** 누구의 어떤 과업이 막혔는지와 실제 관찰·질문·데이터를 제시한다. 사용자 제안은 검토할 입력이며 최적 해법으로 자동 인정하지 않는다.
2. **현재 단계·대안:** 기존 글·탐색·편집 과정 보완, 기능 변경, 현상 유지의 편익과 비용을 비교한다. 명시된 사용자 지시를 임의로 다른 구현으로 바꾸지는 않는다.
3. **근거 분리:** 논문 결과, GPL 관찰, 해석, 반례·불확실성을 나누고 A/B/C를 표시한다.
4. **운영 가능성:** 개발비 외에 콘텐츠 검증·회신·신고·유지보수·데이터 품질 비용과 담당을 확인한다.
5. **검증 설계:** 주요 지표·보호 지표·대상·기간·중단 기준·되돌리는 방법을 정한다. 관측 불가능하면 먼저 관찰 계획을 만든다.
6. **승인 경계:** 기존 AGENTS의 IA·URL·데이터·유료 서비스·Production 경계를 유지한다. 기존 승인과 범위가 같은지 확인하며 불필요한 재승인 절차는 추가하지 않는다.
7. **판단 기록:** 유지/소규모 실험/수정/보류/중단 중 하나로 결론 내리고 근거·미확인을 기록한다. 유지 역시 비용과 사용 가치를 재평가할 수 있다.

기능은 ‘도입되었으니 성공’으로 끝내지 않는다. 주요 지표가 늘어도 오류·피해·운영비가 더 커지면 수정·보류·중단을 검토한다. 독자 가치가 확인된 경우 참여량이 작다는 이유만으로 폐기하지 않는다.

### 7.3 측정·판정 원칙

- 비율에는 분자·분모·기간·제외 기준과 가능하면 불확실성 범위를 함께 남긴다. 사건 0건과 수집 실패·미구현·관측기간 미완료를 구분한다.
- 사전 기준선 없이 ‘개선’이라고 쓰지 않는다. 주제·유입·발행시점·모바일 비중 변화와 동시 개편을 확인한다. 개인 식별이 불가능한 데이터에서 사람 단위 코호트를 추정 생성하지 않는다.
- 작은 표본에서는 건수·인터뷰·실패 사례로 다음 판단을 좁힌다. 차이 없음과 효과 없음은 다르며, 유의한 결과가 나올 때까지 기간을 늘려 결론을 고르지 않는다.
- 지표의 수집 가능성과 부담을 먼저 확인한다. 추적·회원 식별·외부 유료 도구 도입은 이 가이드로 승인되지 않는다. 근거 없는 목표치·보편적 ‘90-9-1’ 참여율·필수 회원 수를 운영 법칙으로 쓰지 않는다.

## 9. 적용 주의사항·갱신 기준

1. 운영 이론은 의사결정의 렌즈다. 댓글·보상·친목·등급·조회수 정렬을 반드시 넣으라는 요구가 아니다.
2. 연구의 효과 크기·참여자 수·초보자 정의는 해당 연구의 조건이다. GPL 목표값이나 현지 성과로 옮기지 않는다.
3. 법령·채용·설비 안전의 판단 근거는 소관 공식 자료다. 사회과학 연구가 이를 대체하지 않는다.
4. 기존 정상 기능·원고·이미지·카테고리·공개 URL·식별자·출처 예외를 보호한다. 현재 승인된 IA 변경과 향후 제안, 구현·배포 상태를 구별한다.
5. 기능·운영 정책·회원 데이터·유료 서비스·Production은 해당 사용자 승인 범위에서만 진행한다. 후속 main 반영도 기존 사용자 승인 범위를 확인한다.
6. 서비스 단계·현행 IA 변경, #278 병합, 참여 접수 운영 시작, 새로운 반증 연구, 실제 지표의 반복적 악화가 있으면 관련 절을 재검토한다. #282 병합은 §1.1에 반영했다. 단순 문서 날짜 갱신은 재검증이 아니다.
7. 새 연구를 추가할 때 원문 접근 범위·연구 설계·대상·결과·반례·GPL 적용을 기록한다. 정본에 결과를 통합하고 별도 연구 요약집·PDF·지식베이스를 중복 생성하지 않는다.

### 9.1 프로젝트 총 지침에 추가할 최소 문구

프로젝트 설정의 총 지침은 Git 파일이 아니므로 이번 PR에서 직접 수정하지 않는다. v2.2의 §6 ‘구현 및 검증 원칙’ 말미에 다음 문단을 추가할 수 있다.

> 사용자 제안은 최적의 해결책으로 자동 인정하지 않고 목적·근거·대안·비용을 검토한다. 커뮤니티 기획·운영·기능 작업은 Git의 `docs/standards/community-operation-guide-v1.md` 관련 절을 참고하며, 이론적 근거·GetPassLab 실측 데이터·적용 추론·실험 가설을 구분한다. 기능의 도입·유지·변경은 사용자 가치와 운영 효율을 기준으로 판단하고, 기존 승인 범위와 보호 규칙을 따른다.

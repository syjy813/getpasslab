# GetPassLab UX/UI 가이드

> **후속 상태:** v1.3 작성 당시 미실행 기록은 역사적 상태다. [2026-10-29 Cloud 후속 QA](../audits/2026-10-29-tossfeed-cloud-browser-qa.md)에서 기본 1363×936의 실측·조작을 수행했다. 지정 PC·모바일 크기는 계속 미확인이다. 최신 결과는 후속 보고서와 본 문서 끝의 보완을 참조한다.

- 버전: **v1.3 / 2026-10-29**
- 적용: 홈·목록·챕터·문제풀이·모의고사·정보 콘텐츠의 탐색과 상호작용
- 확인 기준: 현행 `main`의 `GNB.astro`, `BaseLayout.astro`, `ReadableChapter.astro`, `global.css` 및 기존 운영 기록
- 구분: 아래의 **현재 코드에서 확인한 동작**과 **앞으로 지킬 설계·검수 기준**은 다름. 전체 Production 브라우저 QA를 마친 것으로 해석하지 않음

## 1. 반드시 지킬 8가지

1. **사용자 목표가 첫 화면에 보여야 함:** 공부할 자격증, 읽을 챕터, 풀 문제 또는 필요한 정보가 무엇인지 명확히 표시
2. **한 번의 행동에 한 가지 의미:** 시작·선택·제출·닫기·다음으로 이동을 혼동하지 않음
3. **학습 흐름을 끊지 않음:** 챕터 → 기출 → 해설 → 다음 챕터 이동을 불필요한 설명·확인창·광고가 가로막지 않음
4. **상태는 명확하게 표시:** 미응답·선택·정답·오답·해설 공개·비활성 상태를 각각 구분
5. **같은 동작은 같은 패턴:** 기출 팝업·모의고사 등 목적이 비슷한 곳의 닫기·선택지·채점·해설 UI를 일관되게 유지
6. **모바일에서 모든 필수 행동 가능:** 하단 메뉴·표·그림·모달이 겹치거나 잘리지 않게 함
7. **사용자 결정 보호:** 응답 초기화·문제 이탈·제출처럼 되돌리기 어려운 행동에 적절한 안내와 취소 제공
8. **기존 데이터·검색 경로 보호:** URL·slug·question_id·선택/채점 상태·SEO 메타데이터 영향 점검

## 2. 화면별 사용 목적

| 화면 | 사용자가 하려는 일 | 핵심 요소 | 피할 설계 |
| --- | --- | --- | --- |
| 홈 | 공부할 자격증/서비스 선택 | 서비스 선택, 자격증 카드, 간단한 학습 방식 | 큰 홍보 문구에 실제 탐색이 묻힘 |
| 자격증·과목 목록 | 원하는 챕터 찾기 | 과목·주제·공개 챕터·기출 여부 | 너무 많은 동일 배지, 조건 없는 추천 |
| 학습 챕터 | 짧게 이해하고 바로 적용 | 핵심 개념, 비교·그림, 연결 기출, 관련 챕터 | 설명과 관계없는 안내/장식/중복 요약 |
| 기출 팝업 | 문제 확인 및 해설 | 문항/선택지, 정답 공개, 명확한 닫기 | 본문 뒤 답이 가려짐, 버튼 상태 불명확 |
| 모의고사 | 문제 선택·제출·채점·오답 확인 | 진행 상황, 미응답, 제출·채점, 해설 | 답안이 유실되거나 선택과 채점 상태가 혼동됨 |
| 시설관리 정보(향후) | 자격·선임·취업 조건 판단 | 결론, 적용 범위, 비교표, 근거·기준일 | 일반적 단정, 확인 불가 조건 숨김 |

시설관리 정보 서비스·서비스 전환 토글은 **별도 설계 과제**. 현재 main의 구현으로 확정하지 않음.

## 3. 현재 코드에서 확인된 패턴

| 영역 | 현행 소스에서 확인한 내용 | 작업 시 확인할 점 |
| --- | --- | --- |
| GNB | 로고와 자격증·과목 드롭다운. 챕터에서는 목차 드롭다운으로 전환 | 열림/닫힘, 현재 위치, 화면 밖 넘침 |
| GNB 키보드 | Escape 닫기와 닫은 뒤 summary 포커스, 외부 클릭 닫기 | 포커스가 예상 위치로 복귀하는지 |
| 챕터 목차 | 현재 항목 중앙 정렬 스크롤·`aria-current` 사용 | 긴 제목·말줄임 뒤 실제 이동 가능 여부 |
| 챕터 레이아웃 | 1024px 이상 측면 탐색, 작은 화면에서 하단 이전/다음 링크 | 하단 safe-area, 본문 가림, 마지막 챕터 |
| 본문 | 제목 섹션 구분, 표·그림·기출 이력·관련 챕터 스타일 | 모바일 계층, 표 셀 가독성 |
| 기출 표시 | 일부 문제 UI에 `dialog` 레이어, 선택지/정답 공개 표시 | 상태·닫기·스크롤·키보드 |
| 학습 이미지 | 확대 dialog, 닫기 버튼, 스크롤·포커스 스타일 | 확대 후 글자 판독, 포커스 이동 |
| 터치 목표 | 공통 목표 44px, 하단 챕터 링크 최소 48px | 실제 히트 영역이 그 크기인지 |
| 광고 | 기존 광고 컴포넌트·광고 배치 존재 | 학습 흐름·터치 영역·스크롤 방해 여부 |

소스 확인은 기능의 **정의 여부**만 보여 줌. 동작이 모든 브라우저에서 정상임을 증명하지 않으므로 실제 QA는 별도 수행.

## 4. 탐색과 정보 구조

### 홈·서비스 선택
- 홈에서 사용자가 **어디로 갈지** 알 수 있어야 함. 정보 소개 문장은 선택지를 가리지 않을 정도로 간단히
- 서비스가 둘 이상이라면 현재 영역과 다른 영역을 구분. 전환 뒤에도 사용자에게 현재 위치가 명확하도록 설계
- 선택 대상의 실제 공개 범위(공개 챕터·기출·정보 유무)를 숨기지 않음

### 자격증·챕터
- 자격증 → 과목 → 챕터 → 연결 기출의 계층을 유지
- 현재 위치 표시, 이전/다음 이동, 관련 챕터는 역할이 다름. 같은 UI로 혼합하지 않음
- 긴 챕터 제목은 탐색에서 말줄임 처리할 수 있으나 **항목을 열었을 때 전체 제목이 확인 가능**해야 함
- 연결된 기출이 없으면 있는 것처럼 표시하지 않음. 기능이 없는 버튼은 숨김 또는 명확한 비활성 처리

### 뒤로가기·외부 이동
- 닫기는 팝업 닫기, 뒤로가기는 이전 화면 이동. 둘을 대체 사용하지 않음
- 공개 URL 및 기존 링크를 변경해야 할 때는 SEO·내부 링크·리디렉션 영향 검토 및 별도 승인
- 작업 성공·저장·제출을 사용자 화면에서 확인할 수 있게 해야 함

## 5. 문제풀이·모의고사 상호작용

### 답안 선택·제출·채점
1. **시작 전:** 문항 수·범위·제한 시간 등이 실제 기능과 일치할 때만 표시
2. **풀이 중:** 어떤 선택지가 선택됐는지 텍스트/모양/색상으로 명확히 표시. 답안 변경 가능 여부는 기능과 일치
3. **미응답:** 선택하지 않은 문제를 별도 상태로 표현. 기본 체크박스가 있는 것처럼 보이지 않게 함
4. **제출 시:** 미응답 문항 처리 기준, 제출 후 되돌릴 수 있는지 여부를 정확히 안내
5. **채점 후:** 정답·오답·미응답 구분, 선택 답과 정답의 차이, 해설 접근을 확인
6. **재도전·닫기:** 남은 선택 내용과 초기화 여부를 실제 구현에 맞게 안내

**정답/오답 색만 표시하지 않음.** 상태 텍스트·선택지 강조도 필요. 이전 과목에서 통일된 UI라도 문항 형태·기능이 다르면 동일 컴포넌트 강제가 아닌 차이의 이유를 기록.

### 팝업·모달
- 닫기 버튼의 위치·터치 영역·접근 가능한 이름을 통일. 실제 닫기 동작 확인
- 열릴 때 포커스가 접근 가능한 위치로 이동하고, 닫은 후 원래 조작 맥락으로 돌아갈 수 있어야 함
- Escape·닫기 버튼·배경 스크롤·본문 스크롤 동작을 확인
- 모달 내부 문제·해설이 긴 경우 상단·하단 버튼을 가리지 않도록 스크롤 검수
- 팝업 닫기를 위해 별도의 불필요한 확인창을 반복 표시하지 않음. **답안 유실 가능 시에만** 확인이 필요

## 6. 콘텐츠·레이아웃 상호작용

- **본문:** 한 화면에서 제목→핵심→예시/도식→연결 기출 순으로 이어짐. 정보가 없는 안내문은 [콘텐츠 가이드](content-guide.md)에 따라 삭제
- **비교표:** 모바일에서 가로 스크롤이 불가피하면 가로 스크롤 영역임이 인지되고 셀이 잘리지 않도록 확인. 표 내용 자체의 줄바꿈도 검토
- **학습 이미지:** 기본 크기에서 핵심 관계를 이해해야 함. 확대는 자세한 라벨 확인용으로 제공
- **오류·확인:** 작업 상태와 다음 행동을 한 문장으로 안내. 조작을 막는 빈 안내 모달 지양
- **광고:** CTA·문항 선택지를 가리거나 버튼과 오인되지 않도록 표시. 광고 코드 존재·노출·수익을 동일 상태로 취급하지 않음

## 7. 반응형·접근성 검수 기준

| 뷰포트 | 집중 확인 |
| --- | --- |
| 320px | 메뉴 넘침, 긴 텍스트, 모달 닫기, 이미지 라벨 |
| 390px | 일반 모바일 기준: 카드 폭, 표 줄바꿈, 하단 탐색, 기출 팝업 |
| 768px | 모바일/태블릿 전환 시 레이아웃·글자 크기 |
| 1024px | 측면 챕터 목차 전환·본문 폭 |
| 1440px | 넓은 화면에서 컨테이너·여백·표·그림 가독성 |

- **터치:** 44px 목표, 주변 컨트롤과 오터치 위험 확인
- **키보드:** Tab/Shift+Tab, Enter/Space, Escape, 닫은 뒤 포커스 복귀 검수
- **보조기술:** 링크·버튼의 목적, 이미지 alt, 상태 텍스트, 현재 페이지 표시 등 의미 전달 확인
- **색·대비:** 색 이외의 식별 수단 유지. 시각 대비는 [디자인 가이드](site-design-guide.md) 기준 참고
- **레이아웃:** 가로 넘침, 누락된 이미지, 광고로 인한 이동, 화면 아래 고정 요소와 내용의 충돌 확인

## 8. 다음 작업의 실제 QA 시나리오

| 작업 유형 | 필수 시나리오 | 실패 기준 |
| --- | --- | --- |
| GNB 변경 | 메뉴 열기→다른 자격증 이동→뒤로가기→Escape/외부 클릭 닫기 | 메뉴가 닫히지 않음, 다른 링크로 이동, 초점 손실 |
| 챕터 변경 | 목록→챕터→연결 문제→닫기→관련 챕터 이동 | 원문/문제 불일치, 링크 깨짐, 읽기 위치 상실 |
| 문제 UI 변경 | 선택→변경→답 공개→닫기→재열기 | 선택/정답 상태 불명확, 닫기 불능 |
| 모의고사 변경 | 시작→일부 응답→미응답 확인→제출→채점→해설 | 답 유실, 채점/미응답 표시 오류 |
| 표·그림 변경 | 320/390px→확대→뒤로가기→PC 확인 | 텍스트 판독 불가, 가로 잘림, 복귀 불가 |
| 공통 CSS 변경 | 네 자격증의 목록·대표 챕터·팝업·푸터 확인 | 특정 과목만 레이아웃 손상 |

### 검수 결과 보고
- **변경 범위:** 파일, 컴포넌트, 대상 페이지
- **보호 대상:** 기존 URL, ID, 연결 기출·정답, 주요 UI 동작
- **확인:** 코드 검토 / 테스트 / 빌드 / 브라우저 폭별 QA / CI / 배포 / Production **각각**
- **미확인:** 수행하지 않은 시나리오, 재현되지 않은 문제, 추가 확인이 필요한 브라우저·기기
- **완료 기준:** 의도한 동작을 직접 확인하고 회귀 위험을 기록한 때. PR 생성만으로 완료 아님

| 아티클 제목·날짜·저자·읽기 시간·소제목 등이 구분된 정보형 글 사례 | 자격증 챕터는 학습 본문·기출·관련 챕터 중심 | 시설 상세는 **정보 아티클형**, 자격증 상세는 **문제 풀이형**으로 분리 |
| 공식 UX Writing 원칙에서 다음 화면 예상·문장/화면 간 중복 제거 강조 | 자격증/챕터 메뉴와 문제 레이어에 개별 버튼·안내 적용 | 메뉴 이름·CTA·선택/제출/닫기의 역할을 단순하고 일관되게 정리 |

위 표의 토스피드 항목은 **공개 페이지의 정보 구조**만 확인한 결과. 픽셀 단위 화면 배치·CSS·동작 전체를 확인하거나 토스피드와 동일한 UX로 검증했다고 주장하지 않음.

### 9-2. 두 서비스 GNB의 신규 설계안 — 현재 미구현

```text
GetPassLab
 ├─ 시설의 모든 것 [서비스 선택]
 │   ├─ 시설관리 취업
 │   ├─ 실무·설비
 │   └─ 법정선임·자격 정보
 └─ 자격증의 모든 것 [서비스 선택]
     ├─ 자격증 선택
     ├─ 과목/챕터
     └─ 기출·모의고사 [실제로 제공되는 범위]
```

위 하위 메뉴 명칭은 **정보구조 후보**이며 실제 URL·콘텐츠 수·카테고리 확정이 아님. 향후 구현 전 등록된 콘텐츠와 공개 경로부터 확인해야 함.

**전환 규칙**
- 로고는 서비스 공통 홈으로 연결할지, 현재 서비스 홈으로 연결할지 **실제 라우팅 설계에서 한 가지로 확정**. 동작이 모호한 로고 금지
- 상단 서비스 선택 뒤 해당 서비스의 주제/과목 탐색만 노출. 다른 서비스의 전체 챕터 목록을 같은 패널에 섞지 않음
- 현재 서비스와 현재 페이지를 텍스트·`aria-current` 등으로 표시. 모바일에서 서비스 선택과 챕터 목차가 겹치지 않게 설계
- 기존 챕터는 공개 URL과 SEO canonical을 유지. URL 변경·리디렉션이 꼭 필요하면 별도 승인
- 미래 서비스로 이동하는 메뉴는 실제 공개 페이지가 생기기 전까지 동작하는 것처럼 노출하지 않음

### 9-3. 화면별 적용 분리

| 화면 | 토스피드에서 참고할 UX | 유지해야 할 GetPassLab 기능 |
| --- | --- | --- |
| 서비스 공통·시설 홈 | 상위 서비스 탐색, 대표 콘텐츠와 주제 분류, 목록의 분리 | 기존 자격증 진입 경로, 검색 엔진용 메타 |
| 시설 정보 목록 | 명확한 주제 탭, 제목과 실제 메타 정보, 하나의 주 클릭 영역 | 공개된 글만 노출, 필요 없는 클릭 유도 배지 금지 |
| 시설 정보 상세 | 제목·결론·기준일·목차성 소제목, 읽기와 연결 콘텐츠 구분 | 공식 근거·법정 조건·수치 정확성 |
| 자격증 홈/과목 목록 | 제목·선택지의 정보 위계와 카드 밀도 개선 | 자격증·과목·챕터 목록·실제 기출 연결 |

| 문제풀이·모의고사 | **토스피드의 기사 레이아웃은 적용하지 않음** | 기존 선택·응답·정답·채점·해설과 과목별 UI 일관성 |

### 9-4. 실제 UX/UI 변경의 단계와 승인 경계

**이 문서는 작업 순서와 완료 기준을 정하는 단계이며, 사이트 코드를 변경하지 않음.**

| 순서 | 대상 | 변경할 부분 | 반드시 보호·검증할 부분 | 완료 기준 |
| --- | --- | --- | --- | --- |
| 1 | GNB·서비스 전환 | 두 서비스 선택·하위 메뉴·모바일 전환 | 기존 자격증/과목/챕터 URL, 현재 목차, Escape·포커스·기존 링크 | 양 서비스의 현재 위치·전환이 분명하고 모바일/PC 이동 정상 |
| 2 | 홈·카테고리·카드 | 대표 글·주제 분류·카드 정보량·메타 위치 | 실제 존재하는 콘텐츠만 노출, 홈 CTA 및 검색 메타 | 시작 행동이 명확하며 중복 소개가 줄고 각 카드 링크 정상 |
| 3 | 시설관리 상세 글 | 정보형 아티클 레이아웃·관련 콘텐츠·근거 표시 | 법령·기준일·URL·내부 링크 정확성 | 결론·조건·예외를 찾을 수 있고 320/390/1440px 읽기 정상 |
| 4 *(선택)* | 자격증 목록·챕터의 시각 정돈 | 글자 위계·간격·표·이미지 캡션 등 제한적 수정 | 기존 정답·기출·하단 탐색·팝업·모의고사 | 실제 기존 과목의 대표 화면에서 회귀 QA 통과 |

**제외:** 시험 문제 팝업과 모의고사의 구조 변경, 공개 URL·데이터 ID 재설계, 학습 정답 로직 변경, 토스피드 원본 이미지·아이콘·문구 복제. 추가 변경이 필요하면 범위 및 별도 승인 확인.

### 9-5. 1단계 GNB 개편 전 필수 QA 시나리오

1. **PC 1440px:** 각 서비스 진입 → 메뉴 항목 선택 → 다른 서비스 전환 → 뒤로가기. 활성 영역 표시 확인
2. **모바일 390px·320px:** 메뉴 열기·닫기, Escape, 바깥 클릭, 긴 메뉴명 줄바꿈·넘침, 하단 탐색 가림 여부
3. **기존 챕터:** 산업안전기사·에너지관리기능사·컴활 2급·소방안전관리자 2급 각각 목록 → 챕터 → 기출 → 목차 → 이전/다음 탐색
4. **접근성:** 키보드 Tab/Enter/Space/Escape, 현재 페이지 의미 표시, 메뉴 포커스 이동·복귀
5. **SEO·배포:** 기존 URL·canonical·사이트맵·내부 링크 보존. 테스트/빌드/CI/배포/Production 상태를 별도 확인

**성공 판단:** '토스와 비슷해 보인다'가 아니라 **사용자가 두 서비스와 원하는 콘텐츠를 혼동 없이 선택하고 기존 학습을 계속할 수 있는지**로 판정.

## 10. 토스피드 브라우저 재검증 및 1단계 UX 완료 조건 (v1.3)

**근거:** [토스피드 참고 재검증 기록](../audits/2026-10-29-tossfeed-reference-revalidation.md). 현재 Chat에서 연결된 Chrome의 **열린 탭과 내용은 읽었으나 직접 클릭·스크롤·뷰포트 변경은 불가**. 다음의 시각·반응형 확인은 **미실행**.

### 기존 v1.2의 해석 보정

- 토스피드 상단 '토스피드 에디션 / 금융의 모든 것 / 토스의 모든 것 / 금융 계산기'는 **하나의 콘텐츠 플랫폼 안의 주제·도구 메뉴**. 이것을 GetPassLab의 두 서비스 전환이 이미 검증된 사례라고 해석하지 않음
- 토스피드 메인은 '이 주의 콘텐츠', '지금 많이 보는 콘텐츠', 시리즈·필진 탐색도 제공. 시설관리 콘텐츠의 탐색 후보에 반영하되, 충분한 글·집계가 없는 항목은 노출하지 않음
- 금융 정보형 아티클과 이야기형 아티클의 읽기 경험이 다름. 두 서비스 전환·학습 화면에 같은 기사 레이아웃을 강제하지 않음

### 1단계 GNB의 테스트 가능한 설계 규칙

| 항목 | 예정 UX 규칙 | 실패 기준 |
| --- | --- | --- |
| 서비스 선택 | **시설의 모든 것 / 자격증의 모든 것** 중 현재 영역 명확히 표시 | 페이지를 열어도 현재 영역을 모름 |
| 하위 탐색 | 각 영역에서 그 영역의 실제 공개 카테고리·자격/과목만 표시 | 아직 없는 서비스/문항/목록에 연결 |
| 로고·홈 | 로고 클릭 결과와 서비스 전환의 목적을 한 번에 이해 | 로고 클릭이 임의 서비스로 예측 불가능하게 이동 |
| 챕터 목차 | 기존 과목/챕터 목차 및 `aria-current` 보호 | GNB 개편 뒤 챕터 링크·현재 상태 소실 |
| 키보드 | Tab·Enter/Space·Escape, 닫은 후 포커스 복귀 | 보이지 않는 메뉴에 포커스, Escape 후 포커스 손실 |
| 모바일 | 320/390px에서 텍스트·메뉴가 화면 밖으로 잘리지 않고 터치 가능 | 옆으로 밀리거나 메뉴가 버튼·광고를 가림 |
| 데이터·SEO | 기존 URL·slug·문항 ID·canonical 보호 | 기존 학습 경로 404, 정답 데이터·SEO 경로 변형 |

### 실제 PC/모바일 재현 확인 체크리스트 — 아직 수행하지 않음

1. **토스피드:** PC 1440px, 모바일 390px 및 320px에서 메인·금융 카테고리·정보형 아티클을 **브라우저 직접 조작**하여 스크린샷과 UI 상태 수집
2. **GetPassLab:** 동일한 화면 폭에서 메인·자격증 카드·과목·챕터·기출 팝업 실제 렌더링을 확인
3. GNB 메뉴 클릭, 항목 전환, 검색/테마 버튼의 **존재**와 **작동**을 구분해 기록. 토스피드의 검색·테마까지 GetPassLab에 도입할지는 별도 결정
4. 제목·그리드·카드의 크기/간격은 스크린샷/개발자 도구 실측 뒤에만 값 확정
5. 새 GNB를 구현한 다음에 네 자격증 대표 링크와 기존 문제풀이를 회귀 검증
6. 변경 완료는 코드→Test→Build→브라우저 QA→Merge→Deploy→Production 확인을 각각 증거로 판단

**이번 작업의 완료 판정:** 토스피드 참고 가이드의 근거 재검증과 UX 변경 **기준 정리 완료**. 실제 브라우저 반응형 검증과 UI 변경은 **미완료**. 가이드에 '실측 완료'를 기록하지 않음.

- **그림 완료 기준:** 열기/닫기와 실제 판독성을 분리한다. 확대 시 그림이 작아지지 않는지, 넘침이 있는 축으로 이동되는지, 닫으면 원래 버튼으로 초점이 돌아오는지 확인한다.
- **카드 상태 검사:** 최초 로드·필터·뒤로가기·재로드를 포함한다. 토스에서 관찰한 현상을 GetPassLab Production의 결함으로 옮겨 기록하지 않는다.

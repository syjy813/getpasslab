## 2. PC 별도 창과 이전 Cloud 결과를 분리

PC popup은 `Input.dispatchMouseEvent`에서 시작·창 닫기 모두 타임아웃이었다. 일반 Tab 입력 후 DOM 초점은 BODY에 머물렀고, 캡처도 `Page.captureScreenshot` 타임아웃이었다. 창을 브라우저 API로 정리했으므로 사이트의 ‘창 닫기’ 성공으로 세지 않는다. 원래 창 크기로도 재시도했으므로390 override만의 문제라고 확정할 근거가 없다. 같은 연결의 일반 탭은 이 문서의 기출·이미지·메뉴 조작이 정상 실행됐다.

반면 [기존 Cloud QA §5의 G12~G14](2026-10-29-tossfeed-cloud-browser-qa.md)는 같은 FSM2-035 새 창에서 **시작→1문항 응답→제출·채점→창 닫기·원래 링크 초점**을 실제 확인했다. 이 자료는 재사용한다.

| 근거 환경 | 검증된 범위 | 남는 한계 |
| --- | --- | --- |
| Cloud Browser | native 새 창 시작·답안·채점·창 닫기·부모 링크 초점 PASS | 팝업의 정확한 viewport 당시 미측정. 사용자 PC Chrome 결과가 아님 |
| 연결된 PC Chrome,390 일반 탭 | 같은 popup URL의 시작·답안 유지·제출 취소·채점 PASS | 별도 창 제어 성공으로 확대 불가 |
| 연결된 PC Chrome, 원래 창 크기 | 부모1920×919→새 창1180×843 열림 확인 | 시작·사이트 닫기·캡처는 자동 제어 제약. 미확인 유지 |

이 때문에 ‘기출 새 창 기능을 어느 환경에서도 한 번도 검증하지 못함’과 ‘사용자 PC의 native 창 입력이 미확인’은 다르다.

## 4. 결과물·보호 기능·다음 단계

- 핵심 기준은 기존 [구현 제안](2026-10-29-tossfeed-ui-implementation-proposal.md)의 GNB→홈/목록→시설 상세→학습 읽기 제한 개선 순서를 유지한다.
- 실제 수정할 후속 결함은320 광고 폭/문서 overflow·목차와 하단바 간격,desktop 에너지 viewer 효용,넘침 조건부 안내다. 토스의 Escape·초점 결함은 참고 패턴에서 제외한다.
- Astro 정적 구조, 공개 URL/canonical/SEO, 자격증·챕터·문항 ID·정답·기출 연결, 문제풀이·모의고사 구조, 이미지 확대·모바일 탐색·광고 영역을 보호한다.
- 이번 추가 캡처는 기출 레이어의 정답 확인 버튼 키보드 초점390×844,1개다. 이전32+6 세트에 추가해 **기준32+조작7=39개**다. [전체 ZIP](https://chatgpt.com/library?file_id=libfile_9ef7c097654481918136dcc158952699&account_id=personal)을 갱신한다. native 창 캡처 실패를 대체 이미지로 채우지 않는다.
- 해결되지 않은 PC native 창 검증은 자동 제어가 가능한 새 환경 또는 수동 조작으로 ‘시작→답 선택→제출 취소→채점→창 닫기→부모 링크 초점’ 순서로 마무리할 수 있다. 이번 결과에서는 미확인으로 유지한다.
- 제품 변경이 없으므로 Astro Test/Build 미실행. 문서 상대 링크·JSON·변경 경로 검사만 수행한다. CI·Merge·Deploy를 성공으로 주장하지 않는다.

브라우저 override는 reset했고 이번 테스트 탭·popup만 정리했다. 조사·문서 완료와 실제 UI 개편 완료를 혼동하지 않는다. 다음 단계의 구체적인 구현 시작점은 **두 서비스 GNB와 기존 학습 목차의 공존**이다.

# 1. P1-15a — 컴퓨터를 분류하는 기준

## 학습 본문

### 한 줄 핵심

컴퓨터 이름을 바로 외우기보다 **무엇을 기준으로 분류한 것인지 먼저 구별**해야 함

### 컴퓨터는 여러 기준으로 분류함

| 분류 기준 | 기출에서 구별할 종류 |
|---|---|
| 처리하는 데이터 형태 | 디지털, 아날로그, 하이브리드 |
| 처리 능력 | 슈퍼컴퓨터, 메인프레임, 퍼스널 컴퓨터 |
| 휴대 크기·형태 | 팜톱, 랩톱, 노트북, 데스크톱 |

같은 보기라도 문제에서 묻는 **분류 축**이 다르면 정답 판단이 달라짐

예를 들어

- 하이브리드 컴퓨터 → 처리하는 데이터 형태에 따른 분류
- 슈퍼컴퓨터 → 처리 능력에 따른 분류

따라서 `처리 능력에 따른 분류가 아닌 것`을 묻는 문제에서는 하이브리드 컴퓨터를 찾고, `처리하는 데이터 형태에 따른 분류가 아닌 것`을 묻는 문제에서는 슈퍼컴퓨터를 찾음

### 디지털과 아날로그 구별

| 구분 | 디지털 컴퓨터 | 아날로그 컴퓨터 |
|---|---|---|
| 데이터 | 불연속적인 값으로 표현 | 연속적으로 변하는 양으로 표현 |
| 대표 회로 | 논리회로 | 증폭회로 |
| 주된 연산 | 산술·논리 연산 | 미분·적분 연산 |
| 기출의 전형적 용도 비교 | 범용 | 특수 목적 |

전압·전류·온도처럼 연속적으로 변하는 양은 아날로그 데이터의 대표적인 예임

기출에서는 다음처럼 오답을 제거함

- 디지털 컴퓨터가 미분·적분 연산을 주로 함 → 틀림
- 아날로그 컴퓨터가 산술·논리 연산을 주로 함 → 틀림
- 디지털 컴퓨터가 증폭회로를 사용함 → 틀림
- 아날로그 컴퓨터가 논리회로를 사용함 → 틀림
- 아날로그가 범용이고 디지털이 특수 목적이라는 설명 → 기출의 비교 방향과 반대임

디지털 컴퓨터는 프로그램에 따라 데이터를 처리하고 기억 기능을 사용하는 것으로 출제되므로 `프로그래밍이 필요 없다`, `기억 기능이 없다`는 선택지는 제거함

### 스마트폰과 팜톱

2015년 기출에서는 마이크로컴퓨터를 휴대 크기·형태에 따라 나누며 스마트폰을 **팜톱 컴퓨터**에 대응함

여기서 중요한 것은 현재 모든 스마트폰의 제품 분류를 팜톱이라고 부르는 것이 아니라 **해당 기출의 휴대 크기 분류 기준을 적용하는 것**임

# 2. P1-42a — 웨어러블 컴퓨터의 착용과 입력 방식

## 학습 본문

### 한 줄 핵심

웨어러블 컴퓨터는 단순히 들고 다니는 컴퓨터가 아니라 **몸에 착용하여 사용하는 컴퓨터**임

### 가장 먼저 볼 단서는 ‘착용’

웨어러블 컴퓨터 문제에서는 다음 표현이 함께 나타남

- 소형화·경량화
- 몸에 착용하여 사용
- 장소에 구애받지 않고 활용
- 음성·동작 인식 활용

이 가운데 다른 휴대형 컴퓨터와 가장 직접적으로 구별하는 단서는 **몸에 착용**임

`작고 들고 다닐 수 있음`과 `몸에 착용함`은 같은 조건이 아님

### 휴대형과 웨어러블 구별

| 문제의 단서 | 판단 |
|---|---|
| 작고 들고 다닐 수 있음 | 휴대 가능한 컴퓨터 |
| 책상 등에 두고 사용 | 고정형 사용 형태 |
| 몸에 착용하여 사용 | 웨어러블 컴퓨터의 핵심 단서 |

앞 챕터의 팜톱·랩톱·노트북처럼 **크기와 휴대성으로 나누는 분류**와 웨어러블의 **착용 형태**를 혼동하지 않음

### 음성·동작 인식

기출에서는 음성과 동작 인식이 웨어러블의 특징을 보강하는 단서로 제시됨

따라서 다음 흐름으로 읽으면 됨

**소형·경량 → 몸에 착용 → 음성·동작 인식 → 장소에 구애받지 않고 사용**

정답을 가르는 가장 직접적인 조건은 **착용 여부**임

# 3. P1-15b — 컴퓨터 발전의 주요 전환

## 학습 본문

### 한 줄 핵심

컴퓨터 발전사는 모든 연도를 외우기보다 **계산기 → 천공카드 자료 처리 → 프로그램 내장 → 상업용 컴퓨터**의 핵심 전환을 구별함

### 파스칼의 계산기

파스칼의 기계식 계산기는 **덧셈과 뺄셈을 기계적으로 처리**하는 데 초점을 둔 장치임

따라서 기출의

`파스칼의 계산기는 사칙연산이 가능한 최초의 기계식 계산기`

라는 설명은 틀린 선택지임

이 챕터에서는 기계식 계산기 전체 역사를 늘리지 않고 **파스칼 계산기 = 덧셈·뺄셈 중심**이라는 정답 판단에 필요한 차이만 기억함

### 홀러리스의 천공카드

홀러리스의 천공카드 시스템은 카드의 구멍으로 자료를 나타내고 집계하는 방식이며 인구통계 처리에 사용됨

기출에서는 다음 단서로 연결함

**홀러리스 → 천공카드 → 인구통계·조사 자료 처리**

### EDSAC

EDSAC은 명령과 데이터를 기억장치에 저장하여 실행하는 **저장 프로그램 방식의 초기 실용 컴퓨터**로 연결함

시험 단서는

**프로그램 내장 방식 → EDSAC**

임

### UNIVAC I

UNIVAC I은 초기 상업용 전자계산기로 연결함

기출에서는

**상업용 전자계산기 → UNIVAC I**

로 판단함

| 파스칼 계산기 | 덧셈·뺄셈 중심의 기계식 계산 |

# 4. P1-16a-01 — 비트·바이트와 자료 구성 단위

## 학습 본문

### 한 줄 핵심

자료 단위 문제는 **비트 → 니블 → 바이트의 크기 관계**와 **필드 → 레코드 → 파일 → 데이터베이스의 구성 관계**를 나누어 판단함

### 비트·니블·바이트·워드

| 단위 | 판단 기준 |
|---|---|
| 비트(Bit) | 0 또는 1을 나타내는 정보의 최소 단위 |
| 니블(Nibble) | 4비트 |
| 바이트(Byte) | 8비트 |
| 워드(Word) | CPU가 한 번에 처리하는 데이터 단위로 설명되는 단위이며 크기는 시스템 구조에 따라 달라짐 |

**1바이트 = 8비트**이므로 표현 가능한 조합은 `2⁸ = 256가지`임

따라서 `4비트`라는 단서가 나오면 **Nibble**, `8비트`라는 단서가 나오면 **Byte**로 연결함

`Octet`도 8비트를 뜻하므로 4비트인 니블과 구별함

### 자료가 모이는 순서

자료의 논리적 구성은 다음 흐름으로 판단함

**필드 → 레코드 → 파일 → 데이터베이스**

- 필드(Field): 하나의 항목을 나타내는 자료 단위
- 레코드(Record): 관련된 여러 필드의 모음
- 파일(File): 관련된 여러 레코드의 모음
- 데이터베이스(Database): 관련된 데이터 파일들의 집합

예를 들어 사원 자료에서 `이름`, `부서`, `사번`은 각각 필드이며 이 필드들이 한 사람의 레코드를 구성함

### 기출에서 주의할 표현

과거 기출에는 영문자·숫자는 1Byte, 한글·한자는 2Byte로 표현한다는 설명이 등장함

이 표현은 **당시 기출의 문자 코드 문맥**으로만 사용하고 모든 현대 문자 인코딩에 적용되는 절대 규칙으로 확대하지 않음

문자 코드의 세부 차이는 `P1-31-01`에서 다룸

# 5. P1-16a-02 — 저장 용량 환산하기

## 학습 본문

### 한 줄 핵심

기출의 저장 용량 환산은 **Byte → KB → MB → GB의 단계를 세어 1024를 곱하거나 나누는 방식**으로 풀이함

### 기출에서 사용하는 환산 흐름

과거 컴활 기출에서는 다음 관례로 계산함

**1KB = 1024B**  
**1MB = 1024KB**  
**1GB = 1024MB**

따라서

**1GB = 1024 × 1024 × 1024 Byte**

임

Byte에서 GB까지 올라가려면 `B → KB → MB → GB`로 **3단계**이므로 1024를 세 번 나눔

반대로 GB를 Byte로 바꾸면 1024를 세 번 곱함

### 문제 풀이 순서

1. 시작 단위 확인
2. 목표 단위 확인
3. 몇 단계를 이동하는지 확인
4. 작은 단위로 내려가면 곱함
5. 큰 단위로 올라가면 나눔

예를 들어 `2MB → Byte`라면

`2 × 1024 × 1024 Byte`

로 계산함

### 현재 단위 표기와 기출 관례 구별

현재 SI/IEC 표기에서는 다음처럼 구별함

- **1GB = 1,000,000,000B**
- **1GiB = 1,073,741,824B = 1024³B**

그러나 연결된 2015·2018년 기출은 **GB를 1024³Byte로 계산하는 당시 시험 관례**를 사용함

따라서 원문을 임의로 `GiB`로 고치지 않고, 해당 기출을 풀 때는 문제의 1024 관례를 적용함

## 주 기출 적용 검토

| question_id | 문제 단서 | 적용 | 판단 |
|---|---|---|---|
| `20150307_016` | 1GB를 Byte로 환산 | 기출 관례상 1024³B | **③** |
| `20180901_013` | 1GB를 Byte로 환산 | 기출 관례상 1024³B | **③** |

## 시각 자료

별도 이미지 불필요

모바일에서는 아래 단위 사슬만 제시하면 충분함

`Byte ↔ KB ↔ MB ↔ GB`

각 화살표에 `×1024` 또는 `÷1024`를 표시하는 학습용 재구성을 사용할 수 있음

# 6. P1-31-01 — ASCII·EBCDIC·Unicode의 문자 표현

## 학습 본문

### 한 줄 핵심

문자 코드 문제는 **문자를 몇 비트로 어떻게 표현하는가**를 보고 ASCII·EBCDIC·Unicode를 구별함

### ASCII

표준 ASCII는 **7비트**를 사용하므로 `2⁷ = 128가지` 코드를 표현함

기출에서는 표준 ASCII를 **3개의 Zone 비트 + 4개의 Digit 비트**로 설명함

영문 대·소문자, 숫자, 문장 부호, 제어 문자 등을 표현하는 코드임

기출에서 말하는 확장 ASCII는 **8비트 → 256가지**로 판단함

단, `멀티미디어 데이터를 표현하기 위해 확장한 코드`라는 설명은 ASCII의 목적과 맞지 않음

### EBCDIC

EBCDIC은 IBM 계열 대형 컴퓨터에서 사용된 문자 코드로 출제됨

시험에서는 ASCII와 비교할 때 **대형 컴퓨터용 코드**라는 단서를 주로 사용함

### Unicode

Unicode는 여러 언어의 문자를 공통 체계에서 다루기 위한 문자 체계임

여기서 **문자에 부여된 코드 포인트**와 이를 실제 바이트열로 저장하는 **UTF-8·UTF-16·UTF-32 같은 인코딩 방식**을 구별해야 함

따라서 현재 개념에서는

**Unicode = 모든 문자마다 항상 16비트**

라고 외우면 안 됨

UTF-16은 16비트 코드 단위를 사용하지만 일부 문자는 두 개의 코드 단위를 사용함

### 과거 기출의 16비트 표현

`20190831_010`의 저장된 정답은 ④이며 원문에는 `1개 문자를 16비트로 표현`한다고 적혀 있음

이 선택지는 **과거 기출의 채점값으로 보존**하되 현행 Unicode의 일반 정의로 재사용하지 않음

# 7. P1-31-02 — 패리티 비트로 오류 검출하기

## 학습 본문

### 한 줄 핵심

패리티 비트는 **문자를 표현하는 코드가 아니라 전송 중 오류가 생겼는지 확인하기 위해 추가하는 비트**임

### 문자 코드와 패리티 비트 구별

ASCII·EBCDIC·Unicode는 문자나 기호에 값을 대응시키는 **문자 표현 체계**임

패리티 비트는 문자 자체를 표현하는 코드가 아니라 **오류 검출을 위한 추가 비트**임

따라서 문자 표현 방법을 묻는 보기에서 `Parity bit`가 나오면 다른 목적의 개념으로 제거함

### 짝수 패리티와 홀수 패리티

- 짝수 패리티: 패리티 비트까지 포함한 `1`의 개수를 짝수로 맞춤
- 홀수 패리티: 패리티 비트까지 포함한 `1`의 개수를 홀수로 맞춤

수신한 데이터의 `1` 개수가 약속한 패리티 조건과 맞지 않으면 전송 과정에서 오류가 발생했음을 알 수 있음

### 검출과 교정은 다름

일반적인 단일 패리티 방식은 **오류 발생 여부를 검출**하는 데 사용함

어느 비트가 잘못됐는지 찾아 원래 값으로 고치는 **오류 교정 기능**으로 보지 않음

또한 짝수 개의 비트가 동시에 뒤집히는 오류처럼 단순 패리티만으로 검출하지 못하는 경우가 있음

시험에서는 우선

**패리티 = 오류 검출 / 문자 코드 아님**

으로 구별하면 됨

## 주 기출 적용 검토

| question_id | 문제 단서 | 적용 | 판단 |
|---|---|---|---|
| `20190302_007` | 문자 데이터 표현 방법이 아닌 것 | EBCDIC·Unicode·ASCII는 문자 코드, Parity bit는 오류 검출 | **④** |

## 보조 기출 활용

`20150627_011`, `20170902_012`에서 `패리티 비트를 이용해 오류 검출과 오류 교정이 가능하다`는 선택지는 틀린 설명으로 판단함

패리티는 오류 검출과 문자 코드의 차이를 보여주는 보조 사례로만 사용함

## 시각 자료

별도 이미지 불필요

필요하면 `데이터 비트 + 패리티 비트 → 1의 개수 검사` 정도의 한 줄 학습용 재구성만 사용 가능

## 편집 메모

- 주 1문항·보조 4문항 유지
- 오류 정정 코드나 해밍 코드 등은 현재 기출 판단에 필요하지 않아 확장하지 않음
- `P1-31-01`의 Unicode 세부 설명을 중복하지 않음

# 8. P1-17-01 — CPU의 연산·제어 기능

## 학습 본문

### 한 줄 핵심

CPU 문제는 **ALU는 계산, CU는 명령 해독과 제어, 레지스터는 CPU 내부 임시 저장**으로 구별함

### CPU의 세 구성 요소

| 구성 요소 | 역할 |
|---|---|
| ALU | 산술 연산과 논리 연산 수행 |
| CU | 명령을 해독하고 각 장치에 제어 신호를 보냄 |
| 레지스터 | CPU 내부에서 명령·주소·연산 결과 등을 임시 저장 |

CPU는 이 구성 요소들이 함께 명령을 처리하는 중앙처리장치임

SSD는 데이터를 장기간 저장하는 보조기억장치이므로 CPU 구성 요소가 아님

### ALU와 CU 구별

**ALU**의 핵심 단서는 `산술`, `논리`, `연산`임

**CU**의 핵심 단서는 `명령 해독`, `지시`, `감독`, `제어 신호`임

따라서

`주기억장치에서 읽은 명령어를 해독하고 장치에 제어 신호를 보낸다`

라는 설명은 ALU가 아니라 **CU**의 역할임

가 표시됨

따라서 단순화된 기출 구조에서

- `(ㄱ)` → 연산장치

# 10. P1-18a — RAM·ROM·플래시 메모리 비교

## 학습 본문

### 한 줄 핵심

메모리 문제는 **전원이 꺼져도 남는가**, **어떻게 지우고 다시 쓰는가**, **어디에 사용하는가**를 기준으로 구별함

### RAM과 ROM

| 구분 | RAM | ROM 계열 |
|---|---|---|
| 전원 차단 | 내용이 사라지는 휘발성 | 내용이 유지되는 비휘발성 |
| 일반적인 역할 | 현재 실행 중인 프로그램과 데이터 저장 | 펌웨어 등 고정·반고정 정보 저장 |
| 읽기·쓰기 | 읽기와 쓰기 가능 | 종류에 따라 기록·소거 방식이 다름 |

기출에서 `현재 사용 중인 응용 프로그램이나 데이터`라는 단서가 나오면 **RAM**으로 판단함

### ROM 계열의 기록·소거 방식

| 종류 | 판단 단서 |
|---|---|
| PROM | 한 번 기록 후 일반적으로 다시 지우지 않음 |
| EPROM | **자외선**으로 내용을 지운 뒤 다시 기록 |
| EEPROM | **전기적 방법**으로 내용을 지우고 다시 기록 |
| Flash Memory | EEPROM 계열의 비휘발성 메모리로 전기적으로 기록·삭제 |

시험에서는 `EPROM = 자외선`, `EEPROM·Flash = 전기적 방법`의 차이를 우선 기억함

### 플래시 메모리

플래시 메모리는 비휘발성이며 전원이 꺼져도 데이터가 유지됨

USB 메모리, 디지털카메라, 휴대전화 등의 저장장치에 사용되는 사례로 출제됨

자기 디스크처럼 **트랙 단위로 저장하는 장치가 아님**

따라서 다음은 플래시 메모리의 오답 단서임

- 휘발성 메모리
- 트랙 단위 저장
- CPU와 RAM 사이에서 속도를 높이는 캐시 역할
- 디스크 일부를 RAM처럼 사용하는 가상 메모리 역할

# 11. P1-19 — HDD·SSD·광학 저장장치 비교

## 학습 본문

### 한 줄 핵심

저장장치 문제는 **HDD는 회전하는 자기 디스크, SSD는 반도체, 광학매체는 빛으로 읽고 쓰는 디스크**라는 차이부터 잡음

### HDD와 SSD

| 구분 | HDD | SSD |
|---|---|---|
| 저장 원리 | 자기 디스크와 기계적 회전 | 반도체 메모리 |
| 기계적 구동부 | 있음 | 없음 |
| 속도 | SSD보다 일반적으로 느림 | HDD보다 일반적으로 빠름 |
| 소음 | 회전·구동에 따른 소음 가능 | 작동 소음이 적음 |
| 충격 | 기계적 구조 때문에 충격에 상대적으로 취약 | 기계적 구동부가 없어 상대적으로 유리 |
| 전력 | 상대적으로 큼 | 상대적으로 적은 편 |

시험에서는 `빠름`, `기계적 지연이 적음`, `소음이 적음`, `반도체 사용`이 함께 나오면 SSD를 판단함

SSD도 고장이 발생할 수 있으므로 `절대 고장이나 불량이 없다`고 일반화하지 않음

다만 HDD처럼 회전 자기 디스크의 기계적 충격 취약성을 대표 특성으로 보지는 않음

### 광학 저장장치

CD·DVD·Blu-ray Disc는 레이저를 이용하는 광학 저장매체임

기출에서는 Blu-ray Disc를 **고화질 영상 저장이 가능한 대용량 광학 디스크**로 구별하며 25GB급 단서가 사용됨

ZIP 디스크는 Blu-ray와 같은 광학 디스크가 아님

# 13. P1-18b-02 — 캐시와 버퍼의 임시 저장 목적

## 학습 본문

### 한 줄 핵심

캐시와 버퍼는 모두 임시 저장을 사용하지만 **캐시는 CPU와 주기억장치의 속도 차이**, **버퍼는 장치 사이의 처리·전송 속도 차이**를 줄이는 데 초점을 둠

### 캐시 메모리

캐시 메모리는 CPU가 자주 사용할 가능성이 높은 데이터나 명령을 빠르게 사용할 수 있도록 임시로 저장하는 고속 메모리임

기출에서는 특히

**CPU와 주기억장치 사이에 위치하여 처리 속도를 향상**

이라는 설명으로 출제됨

따라서 `CPU ↔ RAM의 속도 차이`라는 단서가 나오면 캐시를 우선 판단함

### 버퍼

버퍼는 데이터를 보내는 쪽과 받는 쪽의 처리 속도나 전송 단위가 다를 때 데이터를 잠시 모아 두는 저장 공간임

예를 들어 빠르게 데이터를 보내는 장치와 상대적으로 느리게 처리하는 장치 사이에서 데이터를 임시 저장하여 흐름을 맞추는 용도임

시험에서는

- 캐시 → CPU와 주기억장치의 속도 차이
- 버퍼 → 장치 간 전송·처리 속도 차이

로 우선 구별함

### 다른 메모리와 구별

| 개념 | 핵심 목적 |
|---|---|
| 캐시 메모리 | CPU와 주기억장치 사이의 속도 차이 완화 |
| 버퍼 | 장치·처리 단계 사이의 속도 차이 완화 |
| 가상 메모리 | 디스크 일부를 이용해 주기억 용량 부족 보완 |
| 연관 메모리 | 주소 대신 저장된 내용의 일부를 이용해 검색 |
| 플래시 메모리 | 비휘발성 반도체 저장 |

따라서 캐시 문제에서 `디스크 일부를 RAM처럼 사용`, `내용으로 직접 접근`, `EEPROM 계열` 같은 설명은 각각 다른 개념의 특징임

## 학습 본문

### 한 줄 핵심

# 18. P1-20b-01 — 자동 인식과 전원을 켠 채 연결: PnP·핫 스와핑

## 학습 본문

### 한 줄 핵심

장치를 설치할 때 사용자가 하드웨어 자원이나 드라이버 설정을 모두 수동으로 지정하지 않아도 운영체제가 장치를 인식하고 설정을 돕는 기능으로 출제됨

# 19. P1-20b-02 — USB의 연결 방식과 규격

## 학습 본문

### 한 줄 핵심

USB 문제는 **직렬 방식, 여러 장치 확장, 핫 플러그·PnP 지원**을 중심으로 판단하고 커넥터 색상은 절대 규칙으로 외우지 않음

### USB의 핵심 특징

과거 기출에서 USB는 다음 특징으로 출제됨

- 직렬 방식의 범용 인터페이스
- 기존 직렬 포트보다 빠른 전송 방식으로 출제
- 여러 장치를 계층적으로 확장 가능
- 핫 플러그와 PnP 지원

기출에서는 컨트롤러당 최대 127개까지 확장 가능하다는 표현을 사용함

이때 원문의 `포트` 표현을 현재 USB 구조의 엄밀한 물리 포트 수와 같은 의미로 확대하지 않고 **과거 기출의 장치 확장 한계 표현**으로 다룸

### 커넥터 색상 주의

USB 커넥터의 색은 제품·제조사·세대에 따라 달라질 수 있으므로

`USB 3.0은 항상 빨간색, USB 2.0은 항상 파란색`

처럼 색만으로 규격을 절대 판별하는 설명은 올바른 규칙으로 사용하지 않음

과거 연결 문항에서는 이 색상 설명이 오답 선택지로 출제됨

| 선택지 | 판단 |

# 20. P1-20b-03 — SATA의 저장장치 연결 방식

## 학습 본문

### 한 줄 핵심

SATA는 이름 그대로 **Serial ATA**, 즉 직렬 방식의 저장장치 연결 규격으로 이해함

### SATA와 PATA의 핵심 차이

| 구분 | SATA | PATA의 전형적 구성 |
|---|---|---|
| 전송 방식 | 직렬 | 병렬 |
| 연결 구조 | 점대점 연결이 기본 | 하나의 케이블에 여러 장치 구성 가능 |
| Master/Slave | 물리 장치 연결의 기본 개념이 아님 | 전통적인 장치 구분에 사용 |

따라서 `SATA는 병렬 인터페이스 방식`이라는 설명은 핵심적으로 틀린 설명임

### 핫 플러그

SATA 규격은 핫 플러그 기능을 지원할 수 있으나 실제 동작은 컨트롤러·BIOS/UEFI 설정·운영체제·장치 조건에 영향을 받을 수 있음

따라서 `SATA 장치는 어떤 환경에서도 무조건 전원 중 분리 가능`처럼 확대하지 않음

### Master/Slave 선택지 주의

연결 기출 `20190831_012`에는

`CMOS에서 지정하면 자동으로 Master와 Slave가 지정 된다`

는 선택지가 함께 존재함

기존 검수 기록에서는 이 표현도 SATA의 보편적 특성으로 보기 어렵다는 쟁점을 남겼으며, 초기 SATA 규격에는 호환을 위한 Master/Slave 에뮬레이션 가능성도 존재함

따라서 이 문항은 **① 병렬 방식이라는 명백한 오류를 canonical 정답으로 보존**하되 ③을 현대 SATA의 일반적인 참 명제로 가르치지 않음

## 주 기출 적용 검토

| question_id | 판단 |
|---|---|
| `20190831_012` | 저장 정답 **①** 유지 — SATA는 직렬 방식이므로 `병렬 인터페이스`가 핵심 오류 |
|  | ③ Master/Slave 문구는 기존 복수 쟁점이 있어 보편적 사실로 승인하지 않음 |

# 22. P1-46 — 펌웨어와 BIOS의 부팅 역할

## 학습 본문

### 한 줄 핵심

펌웨어는 **하드웨어 제어를 위해 비휘발성 메모리에 저장되는 제어 프로그램**, BIOS는 PC 부팅 초기에 하드웨어를 점검·초기화하는 펌웨어로 이해함

### 펌웨어

펌웨어는 하드웨어 동작을 제어하는 프로그램 성격의 코드임

과거 기출에서는 ROM에 기록된 마이크로프로그램의 집합으로 설명하며 필요에 따라 업그레이드할 수 있는 것으로 출제됨

- 기본 하드웨어 상태 확인
- POST 수행
- 사용 가능한 장치 초기화
- 다음 부팅 단계로 넘길 준비

등을 수행하는 것으로 출제됨

### 저장 위치 주의

BIOS는 **RAM에 저장되어 전원을 끄면 사라지는 프로그램이 아님**

기출에서는 ROM/비휘발성 메모리 계열에 저장되는 펌웨어로 판단함

# 23. P1-16b-01 — 연산 시간 단위와 빠르기 비교

## 학습 본문

### 한 줄 핵심

연산 시간 단위는 **값이 작을수록 짧은 시간**, 즉 더 빠른 처리로 판단함

### 시간 단위

| 단위 | 초로 표현 |
|---|---:|
| ms | `10⁻³ s` |
| μs | `10⁻⁶ s` |
| ns | `10⁻⁹ s` |
| ps | `10⁻¹² s` |

같은 `1`이라는 숫자라도 지수가 더 작은 시간 단위가 실제 시간은 더 짧음

따라서

**1ps < 1ns < 1μs < 1ms**

이고 처리 시간 기준으로는 **1ps가 가장 빠름**

### 풀이 방법

1. 모두 초의 거듭제곱으로 바꿈
2. 가장 짧은 시간을 찾음
3. `빠르다`를 숫자가 크다는 의미로 착각하지 않음

## 주 기출 적용 검토

| question_id | 선택지 | 판단 |
|---|---|---|
| `20160305_019` | 1ms / 1μs / 1ns / 1ps | 1ps가 가장 짧음 → **④** |
| `20180303_012` | 동일 비교 | 1ps가 가장 짧음 → **④** |

## 시각 자료

별도 이미지 불필요

`ms → μs → ns → ps`를 세로로 두고 아래로 갈수록 시간이 짧다고 표시하면 충분함

# 24. P1-16b-02 — 성능 수치의 크기와 비교 방향

## 학습 본문

### 한 줄 핵심

성능 수치는 무조건 `크면 좋다`가 아니라 **무엇을 측정한 수치인지 먼저 확인**해야 함

### 대표 비교 방향

| 측정값 | 일반적인 비교 방향 |
|---|---|
| 저장 용량 | 같은 조건이면 큰 값이 더 많은 데이터를 저장 |
| CPU 클럭 속도 | 같은 비교 조건에서는 큰 값이 높은 동작 빈도 |
| 전송 속도 | 같은 조건에서는 큰 값이 더 많은 데이터 전송 |
| 배속 | 같은 기준에서는 큰 값이 빠름 |
| 접근 시간 | 작은 값이 더 빠른 접근 |

특히 `속도`와 `시간`을 혼동하지 않음

**접근 시간 10ns와 5ns라면 5ns가 더 빠름**

### 과거 기출의 ‘RAM 접근 속도’ 표현

연결 기출은 `RAM의 접근 속도`라고 표현하면서 **수치가 작을수록 좋은 항목**으로 채점함

이 문맥은 실제로 `접근에 걸리는 시간값`을 비교하는 시험 표현으로 읽어야 함

따라서

`RAM 접근 속도는 숫자가 작을수록 좋다`

라는 일반 문장을 만들지 말고

**RAM의 접근 시간(ns)은 작을수록 빠름**

으로 정리함

| question_id | 단서 | 판단 |
|---|---|---|
| `20180303_014` | 수치가 클수록 좋은 것이 아닌 것 | RAM 접근 시간 성격은 작을수록 빠름 → **②** |
| `20190831_013` | 수치가 작을수록 좋은 항목 | RAM 접근 시간 → **③** |

# 26. ADD-17 — 부품 업그레이드의 목적과 호환 조건

## 학습 본문

### 한 줄 핵심

PC 업그레이드는 **무엇이 부족한지 확인 → 바꿀 부품의 역할 확인 → 실제 호환 조건 확인** 순서로 판단함

### 1단계: 개선하려는 항목 확인

먼저 무엇을 개선하려는지 정함

예

- 작업 중 메모리 부족 → RAM 검토
- 저장 공간 부족 → 저장장치 검토
- 특정 CPU 교체 목적 → CPU와 메인보드 호환 확인

이 예시는 학습용이며 직접 배정된 기출 사례가 아님

### 2단계: 부품 역할 확인

부품을 바꾸기 전에 해당 부품이 해결하려는 문제와 관련 있는지 확인함

저장 공간이 부족한데 CPU만 교체하거나, CPU 호환 문제가 있는데 저장장치 용량만 늘리는 식으로 **목적과 부품 역할이 어긋나지 않아야 함**

### 3단계: 호환 조건 확인

부품의 성능 수치만 높다고 바로 교체할 수 있는 것은 아님

확인할 조건의 예

- CPU와 메인보드 소켓·지원 범위
- 메모리 종류와 메인보드 지원 규격
- 저장장치 연결 인터페이스 지원 여부

핵심은

**좋은 부품인가?**보다 먼저  
**이 시스템에서 사용할 수 있는 부품인가?**

를 확인하는 것임

### 학습 적용

사양표에서 부품 이름을 읽는 능력은 `P1-16b-03`, 성능 수치의 방향은 `P1-16b-02`에서 배움

이 챕터에서는 그 정보를 실제 교체 판단으로 연결하여

**목적 → 부품 → 호환성**

순서로 정리함

## 직접 연결 기출

주 기출·보조 기출 **없음**

공식 출제기준의 PC 업그레이드 범위를 보완하기 위한 기초 챕터이며 실제 기출이나 출제 빈도를 새로 만들어 붙이지 않음

## 시각 자료

별도 이미지 불필요

`목적 확인 → 부품 선택 → 호환성 확인` 3단계 세로 흐름이 적합함

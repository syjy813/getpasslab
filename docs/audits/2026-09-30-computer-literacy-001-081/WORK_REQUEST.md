# [LOCAL 전달용 작업 요청서]

## 1. 작업명

컴활 2급 통합 순서 1~81 웹 집필본 실제 저장소 반영 및 검증

## 2. 작업 목적

웹 GetPassLab에서 작성한 컴퓨터활용능력 2급 학습 콘텐츠를 현재 로컬 저장소의 실제 구조와 정본 데이터에 맞게 반영하고 검증해 줘

대상 범위는 통합 순서 1~81임

- 웹 신규 집필 대상: 77개
- 기존 공개 보호 대상: 38, 39, 40, 43번 4개
- 1~81 전체를 하나의 연속 학습 구간으로 정합성 검수

첨부 ZIP 안의 `01_MASTER_DRAFTS_001_081.md`와 `drafts/`의 배치 원본을 콘텐츠 입력으로 사용해 줘

## 3. 현재 문제 및 근거

웹 Chat에서 순서 1~81까지 콘텐츠 범위를 확보했지만 실제 저장소 반영 상태는 별도 확인이 필요함

현재 웹 산출물 기준

- 1~37: 신규 웹 초안 완료
- 38~40: 기존 공개 챕터
- 41~42: 신규 웹 초안 완료
- 43: 기존 공개 챕터
- 44~81: 신규 웹 초안 완료

즉 웹 신규 초안은 총 77개이며 38, 39, 40, 43은 기존 공개 본문을 유지해야 함

이 패키지는 2026-09-24 기준 추출 자료를 바탕으로 작성했으므로, 실제 작업 시작 시 현재 저장소 상태가 달라졌다면 **현재 저장소와 최신 AI_HANDOVER를 우선 증거로 사용**해 줘

## 4. 변경 범위

### A. 현재 저장소 상태 확인

먼저 다음을 확인해 줘

- 현재 branch / HEAD
- `git status`
- 미커밋·미추적 파일
- 컴활 공개 본문 실제 경로
- 현재 1~81 챕터 구현·공개 상태
- 최신 통합 목차·canonical question JSON·관계 데이터
- 이미지 등록부와 실제 이미지 파일
- 현재 사용 중인 챕터 frontmatter·Markdown·컴포넌트 패턴

2026-09-24 패키지와 현재 저장소가 다르면 차이를 먼저 정리하고 현재 저장소를 기준으로 작업해 줘

### B. 신규 웹 초안 반영

다음 배치의 웹 집필본을 실제 챕터 구조로 반영해 줘

- 1~27
- 28~37
- 41~42
- 44~51
- 52~61
- 62~71
- 72~81

총 77개

단, 현재 저장소에 같은 챕터가 이미 구현되어 있다면 무조건 덮어쓰지 말고 기존 본문과 웹 초안을 비교해 더 최신의 승인된 내용과 기존 정상 기능을 보호해 줘

### C. 기존 공개 챕터 보호

다음 4개는 신규 초안 반영 대상이 아님

- 38 `ADD-01` — Windows 화면의 앱·파일·창 구별하기
- 39 `ADD-44` — 창 최소화·최대화·닫기의 결과
- 40 `P1-24-01` — 작업 표시줄의 설정과 창 배열
- 43 `P1-39` — Windows 단축키로 실행되는 동작

기존 공개 URL·slug·본문을 정본으로 유지해 줘

다만 1~81 연속 흐름에서 인접 챕터와 내용 중복·범위 충돌·내부 링크 문제가 있는지는 검수해 줘

### D. 식별자·기출 배정 검증

각 신규 챕터마다 실제 canonical 자료와 다음을 재대조해 줘

- chapter ID
- 제목
- 통합 순서
- subject_id
- 주 기출 question_id
- 보조 기출 question_id
- 문제 원문
- 선택지
- 정답
- 원본 이미지
- 기존 공개 URL·slug 충돌 여부

웹 초안을 이유로 question_id 배정이나 구조를 임의 변경하지 말아 줘

불일치가 발견되면 웹 초안을 억지로 맞추지 말고 실제 정본 근거와 함께 별도 보고해 줘

### E. 콘텐츠의 중요 조건 유지

다음은 반영 과정에서 일반화하거나 삭제하지 말아 줘

- GB/GiB의 과거 기출 관례와 현재 표기 구별
- 과거 Unicode `1문자=16비트` 채점 문맥과 현재 Unicode 정의 구별
- `20190831_012` SATA 정답 ① 유지 및 Master/Slave 쟁점 일반화 금지
- Windows 7/10 기출 UI와 Windows 11 현재 UI 구별
- HDD 조각 모음과 SSD TRIM 최적화 구별
- Storage Sense 온라인 전용 전환과 클라우드 원본 삭제 구별
- `20150627_013` Device Manager의 드라이버 미설치 상태와 과거 노란 물음표 아이콘 표현 구별
- 과거 계정·자녀 보호 문구와 현재 Microsoft 계정 체계 구별
- 직접 기출이 없는 `ADD-*` 챕터에서 존재하지 않는 기출·출제 빈도 생성 금지

### F. 이미지

웹에서 직접 확인한 대표 이미지

- `20151017_012`
- `20200704_018`
- `20151017_010`
- `20151017_009`
- `20180901_012`
- `20180901_003`

실제 저장소의 이미지 등록부·파일과 다시 대조하고 필요한 챕터에 올바르게 연결해 줘

등록 이미지가 없는 문항의 UI를 임의로 실제 화면처럼 만들어 추가하지 말아 줘

새 이미지가 정말 필요한 경우에는 먼저 기존 가이드의 이미지 기준과 모바일 가독성을 검토해 줘

## 5. 유지해야 할 사항

- 현재 정상 작동하는 Astro 정적 사이트 구조
- 컴활 과목 slug와 공개 URL
- 기존 chapter ID
- subject_id
- question_id
- 기존 공개 8개 챕터의 URL 안정성
- 현재 정상 동작하는 기출 연결·내부 링크
- 사용자 로컬의 기존 미커밋·미추적 작업
- 현재 승인되지 않은 대규모 구조 변경 금지

특히 이번 작업은 **콘텐츠 반영 작업**이며 전체 정보구조·식별자 체계를 재설계하는 작업이 아님

## 6. 완료 기준

다음 조건을 모두 충족해야 반영 완료로 판단함

1. 현재 저장소 기준 1~81 상태를 실제로 확인
2. 신규 대상 77개의 반영 여부를 챕터별로 식별 가능
3. 기존 공개 38~40, 43번을 불필요하게 덮어쓰지 않음
4. 모든 반영 챕터의 주·보조 question_id가 canonical 정본과 일치
5. 원문·선택지·정답을 임의 수정하지 않음
6. 필요한 기존 이미지가 실제 파일과 연결됨
7. 모바일 약 390px에서 표·긴 제목·본문·기출 연결이 가로 스크롤 없이 학습 가능
8. 기존 공개 URL·관련 페이지에 회귀 문제 없음
9. 프로젝트에서 요구하는 Test PASS
10. Build PASS
11. 작업 종료 시 `git diff`와 `git status`를 확인
12. 미확인·조건부 사항을 완료로 숨기지 않고 별도 보고

## 7. 필요한 검증

### 콘텐츠 검증

- 챕터별 핵심 개념이 주 기출을 실제로 풀 수 있는지
- 정답 근거와 주요 오답 제거 근거가 본문에 존재하는지
- 인접 챕터 간 중복·범위 침범 여부
- 직접 기출 없는 보완 챕터의 학습 예시가 실제 기출처럼 표현되지 않았는지

### 데이터 검증

- question_id 존재 여부
- subject_id 일치
- 주 기출 중복 배정 여부
- 이미지 파일 존재 여부
- 이미지 등록 정보와 실제 파일 일치
- slug·공개 URL 충돌 여부

### UI/QA

- 데스크톱
- 모바일 약 390px
- 표 가독성
- 긴 코드·확장자·단축키 줄바꿈
- 원본 기출 이미지 크기·alt
- 내부 링크·관련 기출 이동

### 실행 검증

- 저장소 정의 Test
- Build
- 가능하면 변경 영향이 있는 정적 페이지 생성 결과 확인

## 8. 사용자 승인 필요 사항

다음은 이번 요청에 포함하지 말고 별도 승인 요청이 필요함

- 기존 공개 URL 또는 slug 변경
- chapter ID / question_id / subject_id 체계 변경
- 통합 목차 순서·배정 변경
- 대규모 콘텐츠 삭제
- 신규 라이브러리·유료 서비스 도입
- Production 배포
- main push 또는 merge로 자동 배포가 발생하는 작업
- Force Push / History Rewrite

이번 요청에서는 **실제 파일 반영 + 로컬 검증 + Test + Build + diff 보고까지** 진행해 줘

**Commit / Push / Deploy는 하지 말고 결과를 먼저 보고해 줘**

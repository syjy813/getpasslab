# 52. P1-25a-02 — 탐색기의 폴더 계층과 이동

## 학습 본문

### 한 줄 핵심

파일 탐색기 문제는 **드라이브 → 폴더 → 하위 폴더 → 파일의 계층**과 **현재 위치에서 어디로 이동하는지**를 구별하면 됨

### 파일 탐색기의 역할

파일 탐색기는 컴퓨터에 있는 드라이브·폴더·파일을 찾고 열고 관리하는 기능임

기출에서는 다음 기능을 같은 범위로 묶어 판단함

- 드라이브 확인
- 폴더·파일 계층 표시
- 폴더 이동
- 파일·폴더 검색

### 폴더 계층

폴더 안에 새 폴더를 만들면 새 폴더는 현재 폴더의 **하위 폴더**가 됨

예

`연습`
└ `자료`

위 구조에서 `연습`은 부모 폴더, `자료`는 하위 폴더임

탐색기 화면에서 가까이 보인다는 이유로 같은 계층이라고 판단하지 않음

### 상위 폴더로 이동

연결 기출의 핵심 함정은

`현재 폴더에서 상위 폴더로 이동하려면 Home 키를 누른다`

라는 설명임

이 설명은 틀림

현재 Microsoft 문서 기준으로도

- `Home` → 활성 창의 위쪽으로 이동
- `Alt + ↑` → 폴더 경로에서 한 단계 위로 이동

으로 구별됨

따라서

**상위 폴더 이동 ≠ Home**

임

파일 탐색기의 검색 상자는 선택한 위치를 기준으로 파일·폴더를 찾는 데 사용함

현재 Windows에서도 특정 폴더나 드라이브를 선택한 뒤 그 위치를 기준으로 검색할 수 있음

검색 기능 자체와 프로그램 실행은 다음 `ADD-03`에서 구별함

# 53. ADD-03 — 파일 찾기와 프로그램 실행 구별하기

## 학습 본문

### 한 줄 핵심

파일 검색은 **어디에 저장된 무엇을 찾는가**, 프로그램 실행은 **어떤 프로그램·명령을 실행할 것인가**를 판단함

### 파일 검색

파일을 찾을 때는

1. 검색할 위치 확인
2. 파일 이름이나 검색어 입력
3. 검색 결과에서 원하는 파일 확인

순서로 판단함

현재 Windows에서는 파일 탐색기에서 특정 폴더·드라이브·이 PC 등을 기준으로 파일을 검색할 수 있음

따라서

`문서 폴더 안에서 견적서 파일을 찾음`

은 파일 탐색의 문제임

### 프로그램 실행

프로그램 실행은 파일 저장 위치를 찾아보는 것과 목적이 다름

예

- 시작 메뉴·검색에서 앱 이름을 입력한 뒤 실행
- 실행 대화상자에서 프로그램 명령을 입력해 실행

핵심은

**찾을 대상이 파일인가, 실행할 프로그램·명령인가**

를 먼저 구별하는 것임

### 검색과 실행은 완전히 분리된 기능이 아님

Windows 검색 결과에서 프로그램을 찾아 바로 실행할 수도 있음

따라서

`검색 = 파일만 찾는 기능`
`실행 = 검색과 무관한 기능`

처럼 서로 완전히 배타적인 기능으로 외우지 않음

### 판단 예시

`문서 폴더에서 견적서.xlsx를 찾음`

→ 파일 검색

`계산기 앱을 검색한 뒤 실행함`

→ 검색 결과를 이용한 프로그램 실행

`실행 창에서 프로그램 명령을 입력함`

→ 실행 명령

위 예시는 학습용이며 실제 기출이 아님

## 직접 연결 기출

주 기출·보조 기출 **없음**

2026·2027 출제기준의 검색·실행 범위를 보완하는 기초 챕터임

기출 미배정을 출제 0회로 표현하지 않음

## 시각 자료

별도 이미지 불필요

`파일 찾기 / 프로그램 찾기·실행 / 실행 명령` 3행 비교표가 적합함

## 편집 메모

- 직접 배정 기출 없음
- 기존 ADD-03 보완 설계를 그대로 반영함
- 현재 Microsoft 문서에서도 작업 표시줄 검색과 파일 탐색기 검색을 모두 지원함
- 전체 명령어 목록·검색 인덱싱 세부 설정은 제외함

# 54. P1-25a-01 — 파일·폴더의 이름과 속성

## 학습 본문

### 한 줄 핵심

파일·폴더 문제는 **같은 위치에서 이름이 충돌하는가**, **이름에 사용할 수 없는 문자가 있는가**, **속성 창에서 무엇을 확인하는가**를 기준으로 판단함

### 같은 폴더 안의 이름

같은 폴더 안에서는 같은 이름의 파일이나 폴더를 그대로 중복해 만들 수 없음

따라서

`하나의 폴더 안에 같은 이름의 파일이나 폴더가 존재할 수 있다`

는 설명은 틀림

### 이름에 사용할 수 없는 문자

Windows 파일·폴더 이름에는 다음 예약 문자를 사용할 수 없음

`\ / : * ? " < > |`

이 규칙은 현재 Windows 파일 이름 규칙에서도 유지됨

### 폴더 속성에서 확인하는 내용

연결 기출에서는 [속성] 창과 다음 항목을 연결함

- 폴더 크기
- 포함된 파일·하위 폴더 수
- 만든 날짜
- 읽기 전용 관련 속성
- 공유 관련 설정

반대로 속성 창 자체에서 **특정 하위 폴더를 골라 삭제하는 기능**을 수행하는 것으로 보지 않음

### 바로가기 만들기와 구별

`폴더 속성 창에서 바로가기 아이콘을 만든다`

는 설명도 연결 기출에서 틀린 선택지임

바로가기 생성은 폴더 속성 확인과 다른 작업임

# 55. P1-25a-04 — 확장자로 파일의 용도 구별하기

## 학습 본문

### 한 줄 핵심

확장자는 **파일 이름 뒤에서 파일의 형식·용도를 구별하는 정보**이며 기출에서는 `.exe`, `.ini`, `.sys`, `.tmp`의 성격을 비교함

### 기출에서의 확장자 구별

| 확장자 | 기출에서의 판단 |
|---|---|
| `.exe` | 실행 파일 계열 |
| `.ini` | 설정 정보 파일 계열 |
| `.sys` | 시스템 관련 파일 계열 |
| `.tmp` | 임시 파일 계열 |

연결 기출은

`삭제할 때 시스템에 영향을 줄 수 있는 파일 확장자에 해당하지 않는 것`

을 묻고 있으며 `.tmp`를 정답으로 채점함

따라서 이 문항에서는

**`.exe`·`.ini`·`.sys`는 주의 대상 / `.tmp`는 임시 파일 계열**

로 구별함

### 과도한 일반화 금지

모든 `.exe`, `.ini`, `.sys` 파일을 삭제하면 반드시 Windows가 고장 난다는 의미는 아님

반대로 모든 `.tmp` 파일을 어떤 상황에서도 무조건 지워도 된다는 뜻도 아님

이 챕터에서는 **기출의 확장자 성격 구별**까지만 담당함

### 확장자를 바꿔도 파일 형식이 변환되는 것은 아님

현재 Microsoft 문서에서도 파일 이름 확장자를 바꾸는 것만으로 파일 내용이나 실제 형식이 다른 형식으로 변환되는 것은 아니라고 설명함

확장자의 **표시 여부**와 **파일 형식 변환**도 구별해야 함

# 56. ADD-02 — 숨김 파일과 확장자의 표시 설정

## 학습 본문

### 한 줄 핵심

숨김 파일·확장자 표시는 **파일을 바꾸는 기능이 아니라 탐색기에서 보이는 방식을 바꾸는 기능**임

### 확장자 표시

파일 이름이

`보고서`

로 보이다가 확장자 표시 설정을 켠 뒤

`보고서.txt`

로 보이더라도 파일 내용이 변환된 것이 아님

단지 원래 파일 이름의 확장자 부분을 **보이게 한 것**임

따라서

**확장자가 안 보임 ≠ 확장자가 없음**

임

### 숨김 항목 표시

숨김 항목 표시를 켜면 숨김 속성이 있는 파일·폴더를 탐색기에서 볼 수 있게 됨

이 역시 파일 내용 자체를 바꾸는 작업이 아님

### Windows 10과 Windows 11 경로 구별

2026 기준 Windows 10과 2027 기준 Windows 11의 화면을 같은 메뉴라고 외우지 않음

Windows 10 계열에서는 파일 탐색기의 보기·폴더 옵션에서

- 알려진 파일 형식의 확장명 숨기기
- 숨김 파일·폴더 표시

설정을 조정하는 방식이 사용됨

현재 Windows 11에서는 파일 탐색기에서

**보기 → 표시 → 파일 이름 확장명**
**보기 → 표시 → 숨긴 항목**

으로 접근 가능함

핵심은 경로 자체보다

**표시 설정을 바꾼 것인지 파일 자체를 바꾼 것인지**

를 구별하는 것임

### 보호된 운영체제 파일과 구별

일반 `숨긴 항목` 표시와 보호된 운영체제 파일의 별도 표시 옵션을 같은 기능으로 단정하지 않음

## 직접 연결 기출

주 기출·보조 기출 **없음**

출제기준의 폴더 옵션 범위를 보완하는 기초 챕터임

## 학습 예시

`보고서`가 설정 변경 후 `보고서.txt`로 보임

→ 파일 형식이 변환된 것이 아니라 **확장자 표시가 켜진 것**

실제 기출이 아닌 학습 예시임

## 시각 자료

별도 이미지 불필요

`표시 전 / 표시 후 / 파일 내용 변화 없음` 3단계 예시로 충분함

- 직접 배정 기출 없음

# 57. P1-25b-01 — 파일·폴더 선택하기

# 59. P1-25b-03 — 바로가기와 원본의 관계

## 학습 본문

### 한 줄 핵심

바로가기는 **원본 자체가 아니라 원본의 위치를 가리키는 연결 정보**이므로 바로가기와 원본을 따로 판단해야 함

### 하나의 원본에 여러 바로가기 가능

하나의 원본 파일에 대해 바로가기는 여러 위치에 여러 개 만들 수 있음

따라서

`하나의 원본 파일에는 바로가기 하나만 만들 수 있다`

는 설명은 틀림

### 바로가기를 실행하면 원본 실행

바로가기는 원본 경로를 기억하고 있으므로 정상적인 연결 상태라면 바로가기를 실행할 때 연결된 원본을 열거나 실행함

### 바로가기 삭제와 원본 삭제는 다름

바로가기 아이콘을 삭제해도 **원본 파일·프로그램 자체가 삭제되는 것은 아님**

반대로 원본 파일을 삭제하면 바로가기가 남아 있어도 정상적으로 원본을 실행할 수 없음

따라서

**바로가기 삭제 ≠ 원본 삭제**
**원본 삭제 → 바로가기만 남아도 원본 실행 불가**

로 구별함

### 확장자

연결 기출에서는 바로가기 아이콘의 확장자를

**`.LNK`**

로 구별함

`.exe`는 실행 파일 확장자이므로 바로가기 자체의 확장자가 아님

### 바로가기 생성 드래그

과거 기출에서는

**Ctrl + Shift + 드래그 → 바로가기 생성**

으로 출제됨

현재 Microsoft 문서에서는 **Alt + 드래그 → 바로가기 생성** 동작도 명시되어 있음

시험에서는 문항에 제시된 보조키 조합을 그대로 판단함

# 61. P1-40 — 파일 삭제와 휴지통 복원 조건

## 학습 본문

### 한 줄 핵심

휴지통 문제는 **어디에서 삭제했는가, 어떤 방식으로 삭제했는가, 휴지통 설정이 어떻게 되어 있는가**를 먼저 확인함

### 로컬 드라이브와 휴지통

과거 기출에서는 로컬 하드 디스크 드라이브에서 삭제한 파일을 휴지통에 임시 보관하고 복원할 수 있는 구조로 출제됨

휴지통 아이콘은 하나처럼 보이지만 삭제된 항목은 원래 드라이브와 연결된 휴지통 저장 영역에서 관리됨

`하드 디스크 드라이브마다 휴지통을 둘 수 있다`

- USB 메모리에서 Delete로 삭제
- 네트워크 드라이브에서 삭제

**삭제 위치가 로컬 드라이브인지 외부·네트워크 위치인지**

로 안내됨

### 휴지통 최대 크기

휴지통에 설정된 용량 조건에 따라 삭제된 항목이 휴지통에 들어가지 않을 수 있음

`바탕 화면의 파일을 휴지통으로 드래그해 삭제`

## 현행 Windows 검증 반영

현재 Microsoft 문서로 확인한 내용

- File Explorer에서 폴더·파일 검색 가능
- `Home`은 활성 창 위쪽, `Alt+↑`는 상위 폴더 이동
- `Ctrl + 드래그` → 복사
- `Shift + 드래그` → 이동
- `Alt + 드래그` → 바로가기 생성
- `Shift + Delete` → 휴지통 없이 영구 삭제
- Windows 11의 확장자·숨김 항목 → `보기 → 표시`
- 라이브러리 기능은 Windows 11에서도 존재하며 여러 위치의 콘텐츠를 통합 표시하는 가상 컨테이너

## 시대·버전 경계

- Windows 7/10 기출 화면과 Windows 11 UI를 같은 화면으로 표현하지 않음

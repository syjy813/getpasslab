# 72. P1-27a-02 — 작업 관리자에서 사용량 확인·작업 종료하기

## 학습 본문

### 한 줄 핵심

작업 관리자는 **실행 중인 앱·프로세스·서비스와 자원 사용량을 확인하고 필요한 작업을 종료하는 도구**이며 실행 순서를 임의로 정하는 도구가 아님

### 실행 중인 앱과 프로세스 확인

작업 관리자에서는 현재 실행 중인 앱과 백그라운드 프로세스를 확인할 수 있음

현재 Windows에서도 프로세스 화면에서 다음 자원 사용량을 확인할 수 있음

- CPU
- 메모리
- 디스크
- 네트워크

따라서 문제에서 `CPU 사용 정도 확인`이 나오면 작업 관리자의 대표 기능으로 판단함

### 작업 종료

응답하지 않는 앱이나 종료가 필요한 프로세스를 선택하여 **작업 끝내기**를 실행할 수 있음

과거 기출에서도 프로그램이 응답하지 않을 때 작업 관리자를 사용해 프로그램을 직접 종료할 수 있다고 출제됨

### 서비스 확인

작업 관리자에서는 실행 중인 서비스 목록을 확인할 수 있음

현행 작업 관리자에도 서비스 관련 정보가 제공됨

### 실행 순서 변경과 구별

연결 기출의 핵심 오답은

`실행 중인 응용 프로그램의 실행 순서를 변경할 수 있다`

라는 설명임

작업 관리자는 프로세스의 상태·자원 사용을 확인하고 종료하는 기능을 제공하지만 **응용 프로그램이 실행되는 순서를 사용자가 줄 세워 바꾸는 기능으로 보지 않음**

현재 Windows에서 프로세스 우선 순위와 같은 고급 설정이 존재하더라도

**우선 순위 설정 ≠ 응용 프로그램 실행 순서 변경**

임

# 73. P1-27b — Windows 레지스트리에 저장하는 정보

## 학습 본문

### 한 줄 핵심

Windows 레지스트리는 **Windows와 응용 프로그램이 사용하는 구성 정보를 저장하는 시스템 데이터베이스**임

### 레지스트리의 역할

현재 Microsoft 문서에서도 레지스트리를

**응용 프로그램과 시스템 구성 요소가 구성 데이터를 저장하고 읽는 시스템 정의 데이터베이스**

로 설명함

기출에서 다음 표현이 나오면 Registry와 연결함

- Windows 데이터베이스
- 시스템 하드웨어·소프트웨어 구성 정보
- 프로그램 실행과 시스템 설정에 필요한 정보

### CMOS와 구별

CMOS는 전통적으로 BIOS 설정과 같은 하드웨어 초기 설정 정보를 연결해 설명하는 개념임

Windows 운영체제의 구성 데이터베이스를 뜻하지 않음

따라서 문제의 단서가

**Windows 데이터베이스 + 시스템·소프트웨어 구성 정보**

라면 CMOS가 아니라 Registry임

### 하드 디스크와 구별

하드 디스크는 저장장치임

레지스트리 데이터가 저장장치에 실제 파일 형태로 존재할 수 있다는 사실과

`하드 디스크 자체가 Windows 구성 데이터베이스다`

라는 설명은 다른 의미임

### 캐시 메모리와 구별

캐시는 CPU와 주기억장치 사이의 속도 차이를 줄이기 위한 고속 기억장치임

시스템 설정 데이터베이스가 아님

### CPU 레지스터와 구별

CPU 레지스터는 CPU 내부에서 명령·주소·연산 결과 등을 임시로 저장하는 초고속 기억장치임

`운영체제의 시스템 정보를 기억하고 관리한다`

는 설명은 CPU 레지스터가 아니라 Windows **Registry**와 혼동한 것임

## 주 기출 적용 검토

|---|---|---|
| `20151017_020` | Windows 데이터베이스·시스템 하드웨어·소프트웨어 정보 | Registry → **②** |

## 보조 기출 활용

CPU 레지스터 설명에서 `운영체제 시스템 정보를 기억·관리한다`는 선택지는 틀림

Windows Registry와 CPU register의 이름만 비슷한 점을 구별하는 보조 근거로 사용함

## 시각 자료

별도 이미지 불필요

`Registry / CPU register / CMOS / cache`의 목적 비교표가 가장 적합함

## 편집 메모

- 주 1문항·보조 1문항 유지
- 현재 Microsoft Learn의 Registry 정의와 기출 핵심이 일치함
- 레지스트리 편집 실습·키 구조·하이브 목록은 범위 밖
- 잘못 편집하면 시스템 문제가 발생할 수 있으므로 편집 방법을 학습 목표로 확장하지 않음

# 74. P1-32a — 프로그램 제거·복구와 Windows 기능 설정

## 학습 본문

### 한 줄 핵심

프로그램 관리 문제는 **설치 앱 제거·변경/복구, 설치된 업데이트 제거, Windows 기능 켜기/끄기, Windows Update 설정**을 서로 다른 작업으로 구별함

### 프로그램 제거·변경·복구

Windows 7 기출의 [프로그램 및 기능]에서는 설치된 응용 프로그램에 대해

- 제거
- 변경
- 지원되는 경우 복구

작업을 수행할 수 있는 것으로 출제됨

현재 Windows 10/11에서도 프로그램 제거 기능은 유지되지만 설정 앱의 `설치된 앱` 등 다른 경로도 함께 사용됨

따라서 **과거 제어판 경로와 현재 설정 앱 화면을 동일한 UI로 외우지 않음**

### 설치된 업데이트 제거

Windows 7 기출에서는 [프로그램 및 기능]에서 설치된 업데이트 목록을 확인하고 제거할 수 있는 것으로 출제됨

현재 Windows에서는 Windows Update의 업데이트 기록에서 제거 가능한 업데이트를 선택하는 방식도 사용됨

일부 업데이트는 제거할 수 없을 수 있음

### Windows 기능 켜기/끄기

Windows에 포함된 일부 기능은 별도의 일반 응용 프로그램처럼 제거하는 것이 아니라 **Windows 기능 사용/사용 안 함**에서 켜거나 끄는 방식으로 출제됨

2016년 기출의 기본 게임 프로그램이 대표 사례임

### 기능 끄기와 디스크 공간 주의

2017년 Windows 7 기출의

`Windows 기능을 해제하면 하드 디스크 공간의 크기도 줄어든다`

는 설명은 틀린 선택지임

해당 기출에서는 **기능을 끄는 것과 구성 파일을 제거하여 저장 공간을 줄이는 것을 같은 동작으로 보지 않음**

현재 Windows의 선택적 기능은 실제 제거 가능한 항목도 있으므로 이 과거 선택지를

`현재 Windows에서 기능을 끄거나 제거해도 절대 공간이 줄지 않는다`

라고 일반화하지 않음

### Windows Update 자동 수행 설정과 구별

Windows 7 기출에서 Windows Update 자동 수행 설정은 [프로그램 및 기능]의 기능이 아님

즉

**프로그램·Windows 기능 관리 ≠ Windows Update 설정**

임

# 75. ADD-09 — 기본 앱과 파일 형식 연결

## 학습 본문

### 한 줄 핵심

기본 앱 변경은 **특정 파일 형식이나 링크를 어떤 앱으로 열지 연결하는 설정**이며 파일 내용·확장자·설치 상태를 바꾸는 작업이 아님

### 파일 형식과 기본 앱

현재 Windows에서는 파일 확장자나 링크 형식에 대해 기본으로 열 앱을 지정할 수 있음

예

`.txt → 메모장`

에서

`.txt → 다른 텍스트 편집기`

로 기본 앱을 바꾸면

**같은 `.txt` 파일을 기본적으로 여는 앱만 바뀜**

### 파일 내용은 변하지 않음

기본 앱을 변경했다고 기존 문서 내용이 자동으로 수정되는 것은 아님

`어떤 앱으로 열 것인가`와 `파일 내용 편집`은 다른 작업임

### 확장자도 자동으로 바뀌지 않음

`.txt`의 기본 앱을 바꿔도 파일 이름이 자동으로 `.docx`나 다른 확장자로 변하지 않음

**앱 연결 변경 ≠ 파일 형식 변환**

임

### 이전 앱도 제거되지 않음

기본 앱을 다른 앱으로 선택했다고 이전 프로그램이 삭제되는 것도 아님

프로그램 설치·제거는 `P1-32a`의 별도 작업임

### 프로토콜 연결

현재 Windows는 파일 확장자뿐 아니라 링크·프로토콜 형식에도 기본 앱을 지정할 수 있음

시험에서는

**무엇으로 열 것인가를 정하는 설정**

이라는 핵심만 판단함

## 직접 연결 기출

주 기출·보조 기출 **없음**

공식 출제기준의 앱 설정 범위를 보완하는 기초 챕터임

### 학습 예시

`.txt` 기본 앱을 메모장에서 다른 편집기로 변경함

→ `.txt` 파일 내용과 확장자는 그대로임  
→ 기본으로 여는 앱만 변경됨

실제 기출이 아닌 학습 예시임

## 시각 자료

별도 이미지 불필요

`파일 형식 → 기본 앱` 연결 화살표와 `내용/확장자 변화 없음` 메모로 충분함

## 편집 메모

- 직접 배정 기출 없음
- 현재 Microsoft 공식 문서에서 파일 형식·프로토콜·앱별 기본값 설정을 재확인함
- 파일을 실제 다른 형식으로 저장하는 작업은 이 챕터에서 다루지 않음

# 76. ADD-15 — 업데이트 설치와 재시작 상태

## 학습 본문

### 한 줄 핵심

Windows Update는 **확인 → 다운로드 → 설치 → 필요한 경우 재시작**을 서로 다른 상태로 구별해야 함

### 업데이트 확인

새 업데이트가 있는지 Windows Update에서 확인하는 단계임

업데이트가 검색됐다는 사실만으로 설치가 완료된 것은 아님

### 다운로드

업데이트 파일을 PC로 받는 단계임

**다운로드 완료 ≠ 적용 완료**

임

### 설치

다운로드된 업데이트를 시스템에 적용하는 단계임

업데이트에 따라 설치 과정에서 재시작이 필요할 수 있음

### 재시작 필요

현재 Microsoft 문서에서도 일부 업데이트는 설치를 완료하려면 PC를 다시 시작해야 함

따라서

`다운로드가 100% 완료됐고 재시작 필요라고 표시됨`

이라면 아직 **재시작까지 필요한 업데이트 상태**로 판단함

### 사용 시간

사용 시간은 사용자가 보통 PC를 사용하는 시간대를 Windows에 알려 **업데이트 재시작으로 인한 작업 방해를 줄이는 설정**임

사용 시간의 목적은

# 78. ADD-11 — 시각·시간대·자동 설정의 차이

## 학습 본문

### 한 줄 핵심

Windows의 **현재 시각**과 **시간대**는 서로 다른 설정이며 자동 설정과 수동 설정도 각각 구별함

### 현재 시각

PC가 표시하는 날짜와 시간 자체를 의미함

자동 시간 설정을 사용하면 Windows가 시간 정보를 자동으로 맞추도록 설정할 수 있음

수동으로 날짜·시간을 지정하려면 자동 시간 설정 조건을 먼저 확인해야 함

### 시간대

시간대는 **같은 순간을 어느 지역의 시각으로 표시할지 정하는 기준**임

예

같은 순간이 `UTC 00:00`이라면

`UTC+9` 지역에서는 `09:00`으로 표시됨

실제로 9시간이 새로 경과한 것이 아니라 **같은 순간의 지역별 표시가 달라진 것**임

### 자동 시간과 자동 시간대

현재 Windows에서는

- 시간 자동 설정
- 시간대 자동 설정

을 별도로 관리할 수 있음

따라서 둘을 같은 토글로 이해하지 않음

### 수동 변경

자동 설정을 끄고 사용자가 날짜·시간 또는 시간대를 직접 지정하는 방식이 존재함

핵심은

**현재 시각 변경과 시간대 변경은 목적이 다름**

이라는 점임

### 서머타임 주의

일부 지역의 서머타임 적용 여부는 지역·설정에 따라 달라질 수 있음

이 챕터에서는 특정 국가의 서머타임 규칙을 암기 대상으로 확장하지 않음

## 직접 연결 기출

주 기출·보조 기출 **없음**

시간 및 언어 설정 범위를 보완하는 기초 챕터임

### 학습 예시

UTC 00:00인 같은 순간을 UTC+9 시간대로 표시

→ 09:00

시간대에 따른 표시 차이이며 실제 경과 시간이 9시간 늘어난 것이 아님

실제 기출이 아닌 학습 예시임

## 시각 자료

별도 이미지 불필요

`현재 시각 / 시간대 / 자동 설정` 3행 비교표가 적합함

## 편집 메모

- 직접 배정 기출 없음
- 현재 Microsoft 공식 문서에서 시간 자동 설정과 시간대 자동 설정이 별도 항목임을 재확인함
- 서머타임 세부 규칙은 범위 밖

# 79. ADD-12 — 표시 언어·입력 언어·지역 형식

## 학습 본문

### 한 줄 핵심

**Windows 메뉴 언어, 키보드 입력 방식, 날짜·숫자·통화 표시 형식은 서로 다른 설정 대상**임

### 표시 언어

Windows 표시 언어는 설정·파일 탐색기 등 Windows 인터페이스에 표시되는 언어와 관련됨

표시 언어를 한국어로 사용

키보드 레이아웃은 키를 눌렀을 때 어떤 문자 입력 방식이 사용되는지와 관련됨

현재 Microsoft 문서에서도 **키보드 레이아웃을 바꾸는 것만으로 Windows 표시 언어가 바뀌지 않음**을 명시함

→ 메뉴가 반드시 영어로 바뀌는 것이 아님

### 지역 형식

지역 형식은 날짜·시간·숫자·통화 등을 어떤 관례로 표시할지에 영향을 줌

예

- 날짜 순서
- 소수점·천 단위 구분 방식
- 통화 기호

등의 표시 형식과 연결됨

### 세 설정 구별

|---|---|
| Windows 메뉴·인터페이스 언어 | 표시 언어 |
| 키보드로 입력하는 문자 배열·방식 | 키보드/입력 레이아웃 |
| 날짜·숫자·통화 표시 관례 | 지역 형식 |

한 설정을 바꿨다고 나머지 둘이 반드시 모두 함께 바뀌는 것은 아님

### Excel 데이터와 구별

지역 형식은 프로그램의 날짜·숫자 표시 방식에 영향을 줄 수 있음

하지만 기존 Excel 셀의 실제 저장값이 어떻게 변하는지까지 이 챕터에서 일괄 단정하지 않음

→ Windows 메뉴가 자동으로 영어로 바뀌는 것은 아님

실제 기출이 아닌 학습 예시임

## 편집 메모

- 직접 배정 기출 없음
- 현재 Microsoft 공식 문서에서 표시 언어와 키보드 레이아웃이 별도 설정임을 재확인함
- 지역 형식이 날짜·숫자·통화 표시에 영향을 주는 점도 공식 문서로 확인함

# 80. ADD-13 — 게임 바와 게임 모드의 목적

## 학습 본문

### 한 줄 핵심

### 게임 바

현재 Windows의 Game Bar는 게임 중 필요한 도구를 호출하고 게임 화면 캡처·기록 기능과 연결됨

- 캡처

이라면 Game Bar·Captures 쪽으로 판단함

### 게임 모드

Game Mode는 게임 실행 중 시스템 성능을 게임에 맞게 최적화하는 목적의 설정임

핵심

**게임 모드 = 화면 녹화 기능**

이 아님

### 둘을 비교

| 목적 | 기능 |
|---|---|
| 게임 화면 캡처·기록·게임 도구 호출 | Game Bar / Captures |

- 모든 컴퓨터에서 FPS가 반드시 상승

- 게임 화면이 자동 녹화됨

이라고 단정하지 않음

게임 모드의 목적은 **게임 환경 최적화**이며 실제 성능 효과는 시스템·게임 환경에 따라 달라질 수 있음

### 현재 Windows의 다른 게임 기능과 구별

2026년 현재 Windows에는 Xbox mode 등 별도의 게임 관련 기능도 존재함

하지만 이 챕터는 통합 목차의 범위대로 **Game Bar와 Game Mode의 목적 차이**만 다룸

## 직접 연결 기출

Windows 게임 설정 범위를 보완하는 기초 챕터임

## 시각 자료

- 현재 Microsoft 공식 문서에서 Game Bar=캡처 관련 설정, Game Mode=게임 중 시스템 성능 최적화로 구분됨

# 81. P1-28 — 사용자 계정의 권한과 UAC 승인

## 학습 본문

### 한 줄 핵심

사용자 계정 문제는 **표준 사용자가 할 수 있는 개인 작업과 관리자 권한이 필요한 시스템 변경을 구별하고, 관리자 수준 변경에는 UAC 승인 알림이 나타날 수 있음**을 이해하면 됨

### 관리자와 표준 사용자

현재 Windows에서도 관리자 계정과 표준 사용자 계정은 권한 수준이 다름

- 관리자 → 시스템 설정 변경·소프트웨어 설치 등 높은 권한의 작업 가능
- 표준 사용자 → 일상적인 프로그램 사용·개인 설정 중심

시스템 전체 보안에 영향을 주는 작업을 표준 사용자가 자유롭게 변경할 수 있다고 판단하지 않음

### 표준 사용자의 개인 작업

과거 Windows 7 기출에서는 표준 사용자가 다음과 같은 개인 작업을 수행할 수 있는 것으로 출제됨

- 자신의 암호 변경
- 마우스 포인터 모양 변경
- 자신의 바탕 화면 설정
- 설치된 대부분의 프로그램 사용

반면 관리자가 설정한 프린터를 임의로 제거하거나 컴퓨터 보안에 영향을 주는 시스템 설정을 자유롭게 변경하는 것은 표준 사용자 권한으로 보지 않음

### 과거 자녀 보호 문항 주의

2017·2020년 기출에서는 관리자 계정이 다른 계정의

- 컴퓨터 사용 시간
- 게임 등급·콘텐츠
- 계정 유형·이름·암호

등을 관리하는 설명이 정답 판단에 사용됨

이 내용은 **해당 Windows 7/10 기출의 계정 관리 문맥으로 보존**함

현재 Windows의 Family Safety·Microsoft 계정 관리 체계가 과거 제어판 기능과 동일한 메뉴·권한 구조라고 일반화하지 않음

### UAC

사용자 계정 컨트롤(UAC)은 프로그램이나 사용자가 Windows에 **관리자 수준의 변경**을 시도할 때 승인 또는 거부를 요구하는 보안 기능임

현재 Microsoft 공식 문서에서도 UAC의 목적을

**무단 Windows 설정 변경 방지**

로 설명함

따라서 다음 단서가 나오면 UAC로 판단함

### Defender·BitLocker·시스템 복원과 구별

| 기능 | 핵심 목적 |
|---|---|
| UAC | 관리자 수준 변경 승인·알림 |
| Windows Defender / Windows Security | 악성코드·보안 위협 방어 |
| BitLocker | 드라이브 암호화 |
| 시스템 복원 | 시스템 변경을 이전 상태로 되돌림 |

문제에서 `설정 변경을 알려 사용자가 제어`가 핵심이면 UAC임

### 로그인 수단과 권한은 다름

PIN·비밀번호·얼굴·지문은 로그인 방법임

관리자·표준 사용자는 권한 수준임

PIN을 설정했다고 관리자 권한을 얻는 것이 아님

- 지역 형식 → 날짜·시간·숫자·통화 표시에 영향

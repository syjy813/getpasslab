## E. 개선 제안 — 도입 결정은 QA 이후 확정

아래 '현재 문제'는 **제품 코드로 확인된 구조적 제약 또는 UX 가설**이다. 실제 사용자 오류나 시각 버그 발생을 단정하지 않는다.

| 단계 | 현재 GetPassLab의 구조/검토할 문제 | 토스피드 공개 페이지에서 확인한 참고 | 구체적 변경안 | 기대 효과·보호 대상 | 우선순위 / 난이도 / 완료 기준 |

## G. Work 브라우저에서 이어서 실행할 검사 및 기록 요건

1. PC Chrome 연결 또는 Work Cloud Browser를 실제 제어. 사용한 환경을 명시.
2. 토스피드 3개 URL과 GetPassLab Production 홈/자격증 목록/네 자격증 대표 챕터를 1440×900, 390×844, 320×700에서 각자 열기. 태블릿 768×1024은 보조.
3. 각 화면마다 URL, 시간, 뷰포트, 브라우저/에뮬레이션 여부, 전체/화면 캡처 경로 기록.
4. 각 클릭 흐름은 시작 URL → 클릭 대상 → 결과 URL/표시 → 뒤로가기/닫기/초점 복귀 순서로 기록. `PASS`·`FAIL`·`미확인` 엄격 구분.
5. 픽셀 수치는 DOM computed style와 bounding rectangle으로 실제 측정한 요소만 기재. 메뉴 열린 상태, 스크롤 위치, 미디어쿼리 조건을 함께 기록.
6. 토스피드 실제 UX에서 배운 내용과 GetPassLab 변경안의 차이를 재검토. FAIL이 발견되면 재현 조건과 스크린샷 포함.
7. 사용자 데이터가 바뀌는 좋아요·댓글 전송, 실서버 코드 변경, `main` merge, Production 배포는 실행하지 않음.

**완료 경계:** 실측·스크린샷·조작 결과가 없어 최종 요청의 수용 기준은 **충족하지 않음**. 본 문서가 있는 것만으로 QA 완료·제품 변경 완료라고 기록해서는 안 됨.
